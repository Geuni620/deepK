# 최종 UI/UX: Final Settings와 창 크기

갱신일: 2026-10-13
상태: 2026-09-23 최종 시안을 채택하고 PR #30–#33(빌드 버전, 창 크기·로그인 항목 상태, Final Settings·명시적 재번역·창 크기 전환, 실사용 검증 보완)으로 구현을 main에 반영했다. 그려지지 않은 세부 상태는 아래 구현 기본안과 검증 항목으로 보완했다. 이후 변경(PR #44·#48·#49)은 해당 항목에 적었다. 2026-10-13 사용자 피드백으로 메인 창 아래쪽을 막대 하나로 줄였다(아래 [하단 막대](#하단-막대--2026-10-13사용자-피드백)). 아래 체크박스는 계획 당시 목록이며 갱신하지 않았다. 구현·실사용 검증 상태는 [검증 기록](final-settings-validation.md)을 따른다.

## 최신 기준과 우선순위

MCP에서 현재 선택된 노드는 **`J6JTV` · Final · Settings**다. 이전 이름 Essential v2에서 최종본으로 변경된 것을 확인했다. 활성 문서 `pencil-new.pen`의 섹션 구조·문구를 다시 대조했다. 아래 설정 구조를 구현 기준으로 사용하며, 메인 창 크기는 기존 Size Toggle 시안을 함께 따른다.

| 범위 | 기준 노드 | 확인 내용 |
| --- | --- | --- |
| 기본 설정 | `GagM5` | 일반·번역 2탭, 실제 버전·빌드 번호, 계정 하나/둘 연결 |
| 권한 상세 | `uaQy5` | 요약 한 줄 → 항목별 상태 팝오버, 4가지 요약 상태 |

## 1. 설정 기본 구조

- [ ] `일반 | 번역` 2탭의 작은 설정 창을 구현한다. 별도 화면 탭은 만들지 않는다. ⌘, 및 기존 설정 진입점에서 같은 창을 연다. (이후 변경: PR #49(2026-10-08)가 다음 단계로 밝힌 확정 디자인 S6′은 코드 스타일을 고르는 ‘표시’ 탭을 추가한다. 구현되면 이 결정을 대체한다. 현재 main은 일반·번역 2탭이고, ‘표시’ 탭은 PR #59에서 진행 중이다. [결과 구조 유지](result-structure.md) 참고.)
- [ ] 일반: ⌘C 두 번 번역 사용, 권한 요약, 열릴 때 창 크기, 로그인 시 자동 실행.
- [ ] 번역: Codex·Claude Code 계정 행과 제공자 선택, 선택된 제공자의 모델. (이후 변경: Codex 빠른 응답(Fast, PR #44)과 복사 형식(PR #49)이 더해져 설정 창은 340×376이다.)
- [ ] 하단은 실제 앱 버전·빌드 번호를 표시한다. `deepK 0.1.0 (12)`는 형식 예시이지 고정값이 아니다. 구독 등급은 표시하지 않는다.
- [ ] 로그인 시 자동 실행은 설정값만 저장하는 가짜 스위치로 만들지 않는다. macOS 등록·해제·사용자 승인 상태를 구현하고 재로그인 검증 후 유지한다. 미구현 상태를 사용 가능한 기능처럼 노출하지 않는다.

## 2. 권한: 요약과 실제 기능 구분

- [ ] 권한 한 줄을 누르면 설정 창 안 팝오버에서 입력 모니터링·손쉬운 사용을 각각 확인한다.
- [ ] 입력 모니터링은 ⌘C 두 번 감지, 손쉬운 사용은 원래 위치 삽입에 필요한 것으로 설명한다. 삽입 권한만 없다고 번역 자체를 불가능한 것으로 안내하지 않는다.
- [ ] 요약 상태는 준비됨 / 1개 필요 / 2개 필요 / 확인 필요. 세부 문구는 실제 부족한 기능을 따른다. 손쉬운 사용만 없는 예시 문구를 입력 감시만 없는 상태에 재사용하지 않는다.
- [ ] 현재 실행 앱의 권한 연결을 확인하지 못하는 경우 ‘확인 필요’로 구분한다. preflight 결과만으로 시스템 스위치 OFF나 실제 감시 성공을 단정하지 않는다. 단축키를 사용자가 끈 상태도 권한 오류와 구분한다.
- [ ] 필요한 항목에만 ‘설정 열기…’를 표시하고 정확한 시스템 설정 페이지를 연다. 이미 제공 중인 OS 권한 요청 동작은 필요한 경우 내부 흐름으로 유지한다.
- [ ] 시스템 설정을 열기 전에 팝오버를 닫고 deepK의 상시 표시 창이 가리지 않게 처리한다. 돌아오면 자동으로 다시 확인하며 반복 요청 팝업을 만들지 않는다.

## 3. 계정·제공자·모델

- [ ] 계정 상태: 연결됨 / 연결 중 / 로그인 필요 / CLI 미설치 / 연결 실패. 오류를 모두 네트워크 문제로 표시하지 말고 실제 원인에 맞는 문구와 다음 동작 하나를 표시한다.
- [ ] 상태에 따라 로그인…, 설치 방법, 다시 시도를 노출한다. 정상 계정의 관리 동작은 ⋯로 옮긴다.
- [ ] 라디오는 기본 번역 제공자 선택, 옆 버튼은 계정 연결 관리로 구분한다. 한 계정만 연결/둘 다 연결된 경우와 선택한 계정이 끊기는 경우를 검증한다. 사용 불가 제공자로 조용히 전환하거나 다른 제공자를 자동 호출하지 않는다.
- [ ] 선택한 제공자에 맞춰 모델 목록과 실제 사용 모델을 표시한다. 시안의 Sonnet은 표현 예시로 기록한다. Codex 기본은 Luna이고 저장한 선택을 유지한다. Claude는 PR #48(2026-10-08)에서 실제 CLI로 모델별 사용 기록을 확인한 뒤 Haiku 5.5(기본)·Sonnet 5.5·Opus 5.5·Fable 5.1 고정 선택지(`TranslationProvider.fixedModels`)로 정했다. Haiku 4.5는 선택지에서 빠졌고, 선택지에 없는 저장값은 기본값으로 돌아간다(`TranslationSelection.model(for:in:)`).
- [ ] ⋯ 메뉴의 ‘deepK에서 연결 해제’와 ‘Codex 로그아웃…’을 구분한다. 로그아웃은 공유 Codex 로그인에 영향을 줄 수 있다는 안내와 확인창을 거치고 기본 동작은 취소로 한다. Claude는 실제 지원하는 동작만 노출한다.
- [ ] 계정 연결 여부를 선택 여부와 별도로 관찰한다. 설정을 열 때 확인하되 재렌더링마다 CLI를 호출하지 않는다. 연결 실패·재시도 중 버튼 중복 실행을 막는다.

## 4. 창 크기: 다음 열기와 현재 창 분리

- [ ] 일반의 ‘열릴 때 창 크기’에는 마지막 크기 / 항상 작게 / 항상 크게를 표시한다. macOS 기본 팝업 메뉴에 현재 값 체크와 ‘다음에 열 때부터 적용’ 안내를 제공한다.
- [ ] 이 설정을 바꿔도 현재 번역 창 크기는 바뀌지 않는다. 다음 사용자 호출로 열릴 때 적용한다. 최초 기본값은 마지막 크기, 저장 이력이 없으면 작게를 구현 기본안으로 둔다.
- [ ] ‘지금 창: 작게/크게/사용자 크기 · 창 보기’는 실제 창 상태를 반영한다. ‘창 보기’는 기존 번역 창을 앞으로 가져오고 원문·결과·스크롤·요청을 유지한다.
- [ ] 시안대로 아직 생성된 번역 창이 없으면 ‘창 보기’는 작은 확인용 창을 연다. 저장된 다음 열기 설정을 변경하지 않는다. 일반적인 다음 호출과 이 확인용 동작을 구분해 테스트한다.
- [ ] 현재 번역 창은 초록 버튼·앱 내 ⌘⇧E·메뉴 막대의 창 크기로 전환한다. 기존 Size Toggle의 타이틀바 토글을 유지할지는 메인 창 검토에서 정리하며, 설정에 중복된 즉시 변경 행을 되살리지 않는다.
- [ ] 420×296 ↔ 880×600 전환은 외곽 크기를 기준으로 한다. 왼쪽 위 기준·현재 화면 경계 보정을 적용하고, 모니터보다 큰 프리셋은 가려지지 않게 보정한다. 현재 단축키 호출의 포인터 근처 배치 규칙은 유지한다. 단, 이미 열린 창이 포인터와 같은 화면에 있으면 읽던 글이 움직이지 않도록 옮기지 않는다(2026-10-07).
- [ ] 초록 버튼의 크기 전환과 macOS 전체 화면/Option 동작을 구분한다. ⌘⇧E를 전역으로 가로채지 않는다. 0.25초 전환은 Reduce Motion에서 최소화한다.

## 5. 설정 변경과 번역 요청

최신 시안은 제공자·모델 변경에도 자동 재번역하지 않고 ‘다시 번역’ 동작을 제공한다. 현재 구현과 다른 계약이므로 명시적으로 수정·검증한다.

- [ ] 창 크기·권한·자동 실행 등 설정 변경으로 번역을 새로 요청하지 않는다.
- [ ] 제공자·모델을 바꾸면 선택은 저장하되 기존 결과를 즉시 새 제공자의 결과로 표시하지 않는다. 현재 결과를 만든 제공자·모델을 유지하고 ‘다시 번역’으로 새 선택을 적용한다.
- [ ] 전환 시 이전 진행 요청을 취소하거나 결과 적용을 차단해 늦은 응답이 새 상태를 덮지 않게 한다. 원문은 유지한다.
- [ ] ‘다시 번역’을 누르거나 사용자가 새 원문을 입력/두 번 복사할 때 선택된 제공자·모델을 사용한다. 기존 500ms 디바운스·IME 보호·캐시 제공자/모델 분리를 유지한다.
- [ ] 창 크기 변경 중 NSTextView를 불필요하게 재생성하지 않으며 원문·번역·선택·한글 조합·각 스크롤 위치·진행 요청·원래 앱 삽입 세션을 보존한다.

치수는 pen.dev 창 프레임 기준이다. 구현 시 macOS 창 외곽 크기와 콘텐츠 크기를 구분한다.

가로는 약 2.10배, 세로는 약 2.03배가 되지만 폰트·버튼을 같은 비율로 확대하지 않는다. 큰 화면에서도 각 칸의 글 너비는 작은 화면의 약 99%로 유지된다. 큰 화면의 가용 본문 높이 468은 전체 높이의 78%이며, 더 많은 문단을 나란히 읽는 데 공간을 사용한다. 긴 번역에 맞춰 왼쪽도 같은 높이를 갖는 빈 공간은 정상이며 텍스트 자체를 강제로 늘리지 않는다.

작은 시안의 텍스트 잘림은 MCP에서도 확인됐다. 고정된 스크롤 영역의 예시로 해석하며 실제 앱에서는 두 영역의 독립 스크롤로 전체 내용에 접근할 수 있어야 한다. 현재 큰 시안의 예시 텍스트는 영역 안에 들어가지만 이는 임의 길이 문장의 적합성을 보장하지 않는다.

## 하단 막대 — 2026-10-13(사용자 피드백)

사용자 피드백: "하단에 잡다한 게 너무 많다. 이게 다 뭔가. 디테일과 스타일을 신경 써 달라. 불필요한 것은 없애고, 필요한 것은 사람들이 잘 읽도록 다듬어 달라."

이전에는 두 칸 아래에 위에서부터 (1) 결과 칸의 상태 행 18pt(진행 표시+문구, 오른쪽에 ‘다시 번역’·‘다시 시도’·‘번역 제공자 연결 설정’·‘↓ 새 번역 보기’·‘전체 다시 번역’), (2) 창 폭 전체의 9pt 모델 줄(왼쪽 `Claude Code · claude-haiku-5-5`, 오른쪽 `5,811 ms`), (3) 구분선, (4) 푸터 48/44pt(11pt 안내 문구와 팝오버, ‘삽입’, ‘복사’)가 있었다. 여백도 푸터 16pt와 본문 28pt로 어긋났고, 원문 칸 쪽은 결과 상태 행 옆이 빈 띠로 남았다.

바꾼 것(`TranslationView.swift`, 판단은 순수 함수 `TranslationFooterState.swift`):

- 모델 줄과 결과 칸 상태 행을 없앴다. 두 글 칸이 구분선 하나까지 내려오고, 그 아래 높이 고정 막대 하나(크게 44 / 작게 40)만 둔다. 글 주변에 행이 생기거나 사라지지 않는다는 원칙은 그대로다. 결과 칸 아래 여백은 원문 칸과 같게(크게 12) 맞춰 두 칸이 한 줄에서 끝난다.
- 좌우 여백은 창 크기마다 값 하나(`TranslationLayout.textInset`, 크게 28 / 작게 18)다. 원문 칸·결과 칸의 글, 작게 창의 칸 구분선, 머리 줄, 막대가 모두 이 값을 쓴다. 그래서 막대 왼쪽 끝은 원문 글, 오른쪽 끝은 결과 글의 여백과 맞고, 원문 가로줄·결과 단위 선·칸 구분선의 양 끝이 어긋나지 않는다(작게 창의 원문 16을 18로 맞췄다).
- 왼쪽은 상태 한 줄이다. 12pt 보조색, 넘치면 말줄임, 누르면 기존 팝오버에 전체 문구. 번역 중·복사 확인 중에는 문구 뒤에 작은 진행 표시가 붙는다. 앞에 붙이면 ‘입력 중…’ → ‘번역 중…’마다 글자가 약 22pt 옆으로 움직이므로 뒤에 둔다. 우선순위: 복사한 텍스트 확인 중 > 조치가 필요한 안내(오류, 복사 실패, ‘결과가 변경되어 삽입을 중단했습니다’ 등) > 끝나지 않은 번역 상태(입력 중…, 번역 중…, 추가 내용 번역 중…, 추가 내용이 번역되지 않았습니다, 연결 확인 중…, 번역 제공자 연결 전, 오류) > 단축키 감시 실패 안내 > ‘선택한 제공자·모델로 다시 번역할 수 있습니다’ > 원문 반복 경고(앞에 주황 경고 표시, ‘원문이 그대로 남아 있을 수 있습니다’) > 평소와 다른 단축키 상태(‘단축키 감시 연결 안 됨’ 등) > 없음. 다시 요청하는 동안은 끝나지 않은 번역 상태 자리에 ‘원문이 그대로 나와 다시 번역하는 중…’이 보인다. 원문 반복 경고는 PR #55(실행 중 결과 검사)가 예전 상태 행에 더한 것을 main과 합치며 이 막대로 옮겼다([실행 중 결과 검사](runtime-output-check.md) 6절).
- 단축키 감시 실패 안내(‘현재 앱의 키 입력 감시가 연결되지 않았습니다…’, ‘단축키를 시작하지 못했습니다…’)는 앱이 활성화될 때마다 감시를 다시 시작하며 다시 선다. 진행 중이거나 실패한 번역보다 앞에 두면 입력 감시 권한이 없는 사용자에게는 ‘번역 중…’과 다음 오류가 늘 가려진다. 그래서 끝나지 않은 번역 상태 뒤에 두고, 번역이 끝나면 다시 보인다(`TranslationFooterState.Input.feedbackIsStanding`).
- 새 요청을 시작하는 동작(‘다시 시도’, ‘다시 번역’, 방향 바꾸기)은 입력·‘전체 다시 번역’처럼 앞 요청 때의 안내(삽입 실패 등)를 지운다. 그 안내가 새 요청의 진행·오류를 가리지 않는다. ‘다시 시도’는 이제 `AppModel.retry()`를 거치고, 걸린 시간도 그때부터 잰다.
- 더 보이지 않는 것: ‘완료’, ‘기존 번역 유지 · 추가 번역 완료’, ‘저장된 번역’, 평소의 ‘⌘C 두 번 · 감지 중’(시작 직후 ‘단축키 확인 중’ 포함), 설정에서 끈 ‘두 번 복사 꺼짐’, 삽입할 수 없는 이유(‘읽기 전용 위치입니다…’, ‘…손쉬운 사용 연결을 확인하지 못했습니다…’, ‘원래 입력 위치를 확인하지 못했습니다…’). ‘두 번 복사 꺼짐’은 사용자가 고른 설정이지 고장이 아니고, 메뉴 막대 항목과 설정에 이미 보인다. 삽입할 수 없는 이유는 `AppModel.insertionNote`로 옮겨 ‘복사’ 버튼의 툴팁이 되고, 호출이 바뀌면 지운다.
- 복사 확인은 누른 자리에서 한다. 복사가 되면 ‘복사’ 알약이 약 2초 ‘복사됨’으로 바뀌고 스스로 돌아온다(`AppModel.reportCopy`; 다시 복사하면 앞 확인의 시계로 일찍 돌아오지 않는다). 알약은 긴 글자(‘복사됨’) 폭을 늘 차지해 바뀔 때 옆 버튼이 움직이지 않는다. 하단 왼쪽 상태 칸은 버튼에서 크게 창 약 730pt, 작게 창 약 300pt 떨어져 있어 2초짜리 확인을 놓치기 쉬우므로 쓰지 않는다. ‘복사하지 못했습니다’는 상태 칸에 남아 저절로 지우지 않고, 이어서 복사가 되면 지운다. ‘삽입됨’은 창이 숨은 뒤 다시 열었을 때 남지 않게 약 2초 뒤 지운다(`AppModel.showBriefly`; 그 사이 다른 안내가 오면 그 안내는 남는다).
- 상태 칸이 비어 있으면 마우스를 올렸을 때만 11pt 3차 색으로 `<제공자> · <모델> · 5.8초`가 보인다. ⌘C 두 번은 deepK를 활성화하지 않고 창을 띄우므로, 마우스 추적은 SwiftUI `.onHover` 대신 `.activeAlways` 추적 영역(`HoverTrackingView`)으로 해 창을 누르기 전에도 보이게 한다. 이 뷰는 클릭을 받지 않는다. 시간은 소수 한 자리 초(반올림, 0.05초 미만은 ‘0.1초 미만’)이고, 모르거나 캐시 결과이면 뺀다. 문구가 있으면 같은 내용이 그 툴팁이다. 모델은 이전처럼 보이는 결과를 만든 모델(`store.resultModelLabel ?? requestModelLabel ?? 선택`)이라 제공자를 바꾼 뒤에도 원래 모델을 가리킨다.
- 오른쪽은 그때 필요한 글자 버튼(테두리 없음, 12pt medium, 강조색) 하나: ‘번역 제공자 연결 설정’ / ‘다시 번역’ / ‘다시 시도’ / ‘↓ 새 번역 보기’(조건은 이전과 같다). 스크롤 프록시를 창 수준으로 올려 막대가 결과 칸을 스크롤한다. ‘전체 다시 번역’은 늘 보이는 화면에서 빼고(예외: 다시 요청한 답도 원문 반복이면 ‘↓ 새 번역 보기’ 다음 순위로 막대에 둔다. 사용자에게 다시 하라고 알리는 유일한 결과라서다) 결과 글의 오른쪽 클릭 메뉴 맨 위(그 아래 구분선, 찾아보기·복사·서비스 등 기본 항목)에만 둔다. 예전 SwiftUI `.contextMenu`는 결과 글 위에서 열리지 않는다. AppKit이 오른쪽 클릭을 그 아래 `NSTextView`에 보내고, `NSTextView`가 자기 메뉴로 답하기 때문이다(창을 띄우지 않은 시험으로 확인). 그래서 `ResultTextView.menu(for:)`가 항목을 더한다(`ResultMenuAction`). 켜짐 여부는 메뉴를 열 때 묻는다(엔진 준비, 조합·번역 중 아님, 복사 확인 중 아님).
- 그 오른쪽에 ‘삽입’(밝은 회색 바탕·진한 글자, 삽입할 수 있을 때만)과 ‘복사’(진한 먹색 바탕·흰 글자). 둘 다 높이 24, 모서리 6, 12pt medium, 좌우 12. 쓸 수 없는 ‘복사’는 옅은 바탕과 옅은 글자로 분명히 꺼져 보인다.
- 결과 칸에 아직 글이 없으면 상태(문구와 그 뒤 진행 표시, 쉬는 상태는 ‘번역 결과’)는 지금처럼 글이 나올 왼쪽 위, 글이 시작할 자리에 보이고, 막대는 같은 문구를 되풀이하지 않는다. 빈 칸은 자리가 넉넉하므로 긴 오류는 말줄임 없이 네 줄까지 감기고(스크롤바 여백 앞에서), 선택해 복사할 수 있다.
- 결과 칸에 글이 있는지는 칸과 막대가 모두 스트리밍 조각마다 묻는다. 결과 글마다 한 번만 파싱하도록 `ResultTextPresence`가 기억한다.
- 테스트: `TranslationFooterStateTests`(우선순위, 숨기는 문구, 단축키 감시 실패 안내와 진행 중 번역, 끈 두 번 복사, 빈 결과 칸과 중복 없음, 진행 표시, 시간 형식, 글자 버튼 조건), `PermissionPresentationTests`(앱 상태에서 막대 입력 읽기, ‘삽입됨’ 자동 지우기, 복사 확인과 실패, ‘다시 시도’가 지우는 안내, 진행 표시가 글자를 밀지 않음(창 없이 그린 픽셀 비교), 빈 칸 오류 줄바꿈, `.activeAlways` 추적, 파싱 기억), `TranslationResultTextViewTests`(오른쪽 클릭 메뉴의 ‘전체 다시 번역’). 저장소 밖 사본에 결함을 하나씩 넣어 확인했다. 처음에는 순수 함수 13건과 확인 문구 지우기 조건 2건이 모두 잡혔다. 독립 리뷰를 반영한 뒤 넣은 16건 가운데 15건이 잡혔다(진행 표시를 앞에, 빈 칸 한 줄, `.activeInActiveApp`, 파싱 기억 빼기, ‘다시 시도’가 안내 유지, 복사 실패 자동 지우기, 복사 성공을 상태 칸에, 복사 확인 세대 비교 빼기, 끈 두 번 복사 표시, 감시 실패 안내 순서 2건, 메뉴 항목 빼기·맨 아래·늘 켜짐, 결과 창 legacy 여백). 메뉴를 복사하지 않고 고치는 1건은 살아남았다. AppKit이 오른쪽 클릭마다 새 메뉴를 만들어 결과가 같기 때문이며, 복사는 방어로 남긴다.
- 남은 실제 앱 확인은 [Mac 통합 확인](mac-integration-checks.md) ‘하단 막대’ 절에 있다.
- 독립 리뷰(2026-10-13) 뒤 바꾼 것은 위에 반영했다. ‘전체 다시 번역’ 메뉴를 `NSTextView` 메뉴로 옮김, 감시 실패 안내와 새 요청, 복사 확인 위치, 진행 표시 위치, 빈 칸 오류 줄바꿈, 작게 창 여백 18 통일, 끈 두 번 복사 숨김, `.activeAlways` 마우스 추적, 파싱 한 번이다. 스크롤바 여백은 overlay 스크롤바일 때만 둔다. legacy 스크롤바는 자기 자리를 따로 차지한다([명시 경계 번역](explicit-boundary-translation.md) 10절).

## 남은 구현 판단과 검증 주의점

- 이전 큰 화면 측정에서는 오른쪽 언어 제목과 본문이 13.5px 어긋났다. 언어 행과 본문을 같은 칸에 정렬하고 중앙 교환 버튼은 별도로 배치한다.
- 이전 메인 시안은 작게/크게에서 설정 아이콘 위치가 달랐다. 설정 진입점과 크기 전환 컨트롤을 실제 양쪽 화면에서 확인하고 찾기 쉬운 위치로 일치시킨다.
- 모서리 수동 크기 조절을 유지할 경우 최소 크기·분할 임계폭이 여전히 필요하다. 구현은 720px을 분할 기준으로 쓴다. `TranslationView`는 폭 720 이상에서 좌우 배치로 바꾸고, 크기 판정 `WindowPresentation.expandedWidthThreshold`는 719/720/721 단위 테스트로 고정했다. 좁고 긴 창·넓고 낮은 창의 실제 화면 확인 기록은 아직 없다.
- `P7LPB`의 팝업 장면에서 stage 경계 일부 넘침이 감지됐다. 시연용 팝업 오버레이와 실제 창의 잘림은 구분하고 구현에서는 가용 화면 안에 배치한다.
- (해결됨) 구현 전 NSPanel은 콘텐츠 420×264에 `.resizable`이 없었고 TranslationView의 루트와 원문 높이도 고정이었다. 지금 패널은 `.resizable`이고 최소 크기는 작게(420×296)와 같다. 크기 상태는 `WindowPresentation`(작게 420×296 / 크게 880×600, 마지막 크기 저장)이 관리하고, TranslationView는 같은 뷰의 배치만 바꾸는 가변 레이아웃이다(분할 기준은 위 항목).
- 현재 `AppModel.changeProvider`는 연결 흐름으로 이동하고 `changeModel`은 재번역을 호출한다. UI만 바꾸지 말고 요청 상태 계약과 회귀 테스트까지 수정한다.
- 언어는 메인 창 메뉴에 유지한다. 업데이트 확인·Homebrew·글자 크기·항상 위 옵션·읽기 중심 배치는 이번 설정에서 제외한다. 내부 상주 창 정책이나 기존 기능을 삭제한다는 의미는 아니다.
- 스크립트 빌드의 실제 버전·빌드 번호를 정리해 설정에 사용한다. 시안 숫자를 그대로 넣지 않는다.

## 최종 누락 점검과 구현 기본안

큰 설정 항목의 추가는 필요하지 않다. 아래는 시안에 완전한 화면이 없는 상태를 구현할 때 사용할 기본안이며, 이미 그려져 있거나 구현됐다는 뜻은 아니다.

- [ ] **다시 번역**: 제공자·모델 변경으로 현재 결과/진행 요청과 선택이 달라진 경우 결과 영역 아래의 고정 높이 상태 행에 간결한 안내와 ‘다시 번역’을 표시한다(2026-10-07: 결과 위에 행을 끼워 읽던 글을 밀지 않도록 변경). 원문이 비어 있으면 노출하지 않고, 실행 중에는 중복 클릭을 막는다. 크기 전환만으로 이 상태를 만들지 않는다. 실제 좁은/넓은 화면에서 푸터의 복사·삽입을 가리지 않는지 확인한다. (이후 변경, 2026-10-13: 결과 영역 아래 상태 행을 없앴다. 안내는 하단 막대 왼쪽 한 줄, ‘다시 번역’은 막대 오른쪽 글자 버튼이다.)
- [ ] **두 계정 모두 미연결**: 초기 선호 제공자는 기존 기본값 Codex로 보존하되 연결된 것처럼 표시하지 않는다. 각 계정은 로그인/설치 진입점을 제공하고 모델 선택·번역 실행은 준비 전 비활성화한다. 연결 시 기존 선호 선택을 존중하며 사용자 의사 없이 다른 제공자에 번역을 보내지 않는다.
- [ ] **입력 감시만 준비되지 않은 상태**: 손쉬운 사용 부족 예시와 별도로 ‘⌘C 두 번 감지를 사용할 수 없어요’를 표시한다. 직접 입력 번역·결과 복사 가능 여부를 그대로 유지한다. 부족한 권한 개수만으로 어느 기능이 막혔는지 추정하지 않는다.
- [ ] **자동 실행 상태**: 꺼짐/등록됨/사용자 승인 대기/등록 실패를 구분한다. 승인 대기는 시스템 설정 진입, 실패는 원인과 재시도를 조건부 표시한다. OS 등록 결과와 스위치 상태가 일치해야 한다.
- [ ] **모델 예시 정리**: 시안의 Sonnet은 예시였으나 PR #48부터 Sonnet 5.5는 실제 선택지다(현재 선택지는 3절). 구현 화면은 실제 사용 가능한 모델과 저장된 선택을 표시한다.
- [ ] **창이 없는 경우의 ‘창 보기’**: 최신 시안의 ‘없으면 작게 새로 열기’를 현재 기준으로 유지한다. ‘항상 크게’ 등 다음 열기 기본값은 바꾸지 않으며, 확인용 작은 창 생성과 이후 일반 호출의 정책을 각각 검사한다. 앞선 ‘열기 설정을 따르자’는 검토 제안은 채택된 결정으로 취급하지 않는다.

설정 화면 외에도 메뉴 막대 → 설정, ⌘, 진입과 메인 창의 제공자/모델·재번역·권한 안내가 같은 상태를 사용해야 한다. 현재 초안의 버튼 위치와 수동 리사이즈 임계값 같은 세부 구현 판단은 실제 앱에서 비교·검증하고 변경 이유를 기록한다. 이를 위해 기능이 빠진 상태를 완성으로 축소하지 않는다.

## 작은 PR 실행 순서

0. 현재 브랜치의 기존 plans 변경을 보존하고 계획을 정리한다. 코드 변경 전 최신 main/기존 PR 상태와 pen.dev 기준을 확인한다.
1. 최신 설정 구조와 상태 모델: 2탭, 실제 버전, 계정별 상태·선택·⋯, 권한 상세.
2. 제공자·모델 변경의 명시적 재번역과 취소·늦은 응답·캐시 회귀 검증.
3. 창 크기 저장·다음 열기 정책·창 보기·크기 전환·상하/좌우 레이아웃 및 편집 상태 보존.
4. 로그인 시 자동 실행 구현·실제 등록 상태 확인, 기능별 스크린샷과 시안 대조.
5. [개인 베타 계획](macos-distribution.md)에 따라 다른 Mac에서 버전 기준 소스 빌드·설치·업데이트·실사용 검증.

완료 조건은 구현만이 아니라 실제 설정 전환, 계정 하나/둘 연결, 각 권한 조합, 모든 계정 오류, 로그아웃 취소, 다음 열기 설정, 닫기/재실행, ⌘W 상주·ESC 복귀·⌘C 두 번·명시적 삽입의 검증이다. 실제 계정 로그아웃은 공유 도구 영향과 사용자 승인 범위를 확인해 테스트하며 모의 결과와 구분한다. UI 구현 전 시안 확인을 실사용 검증으로 표시하지 않는다.

공개 배포·공증·Homebrew는 후속으로 유지한다. 사용자의 후속 goal 실행 요청으로 구현을 진행한다. Release 게시는 현재 범위에 포함하지 않는다.
