## 남은 실제 검증

후속 정리 빌드는 성공했으나 전면 앱이 `com.apple.loginwindow`여서 추가 접근성 조작을 진행하지 않았다. 잠금을 우회하지 않는다. 이후 [잠금 해제 후 재개 검증](#잠금-해제-후-재개-검증)에서 확인한 범위를 아래 항목에 함께 적는다. 두 번째 Mac 항목은 사용자 결정으로 후속 작업이다([개인 베타 계획](macos-distribution.md)).

- [ ] 최종 일반·번역 탭과 권한 팝오버·계정 메뉴의 실제 화면 비교 및 스크린샷. 2026-09-23 재개 검증에서 두 탭·실제 버전·두 제공자 연결·권한 상세와 Codex 로그아웃 확인창을 확인했다(`translation.png`). 이후 번역 탭에 Codex 실행 파일 경로·버전 줄과 ‘Codex 빠른 응답(Fast)’(PR #44), ‘복사 형식’(PR #49)이 더해지고 설정 창 높이가 320 → 376pt로 바뀌었다. 바뀐 화면의 확인(Codex 선택 시 다섯 행, Fast·복사 형식 유지)은 [Mac 연동 기록](mac-integration-checks.md#실제-앱-확인-대기--2026-10-12)에서 추적한다.
- [ ] 작게/크게 전환의 실제 외곽 크기·독립 스크롤·IME·선택 보존, 초기/다음 열기 정책과 창 보기. 재개 검증에서 도구 조작으로 880×600 ↔ 420×296, 편집기·원문 유지, ‘항상 작게’ 다음 열기 정책을 확인했고, 비표시 하네스로 selectedRange·markedRange 보존을 확인했다. 큰 창의 독립 스크롤, 창 보기, 실제 한글 입력기 키보드 조작은 남았다.
- [ ] 설정 진입·계정 상태 재확인 중 진행 번역 유지. 연결 해제와 로그인 동작이 기본 제공자를 바꾸지 않음.
- [x] 제공자 전환 직후 요청 미전송과 명시적 다시 번역, 원래 결과 모델 표시. 재개 검증에서 Codex → Claude 전환으로 확인했다(`provider-change-awaits-action.png`, `manual-retranslation.png`).
- [ ] 같은 제공자 안에서 모델만 바꾸는 전환. 제공자 전환과 같은 `setTranslationContext` 경로이지만 실제 앱으로 따로 확인하지 않았다.
- [ ] ⌘W·ESC·실제 키보드 ⌘C 두 번·원래 위치 삽입. 합성 이벤트와 구분한다. 사용자가 실제 앱에서 Chrome 원문을 두 번 복사해 번역한 기록은 생겼다(PR #51, [웹 수식 복사 계획](web-math-copy.md)). ⌘W는 도구 조작으로만 확인했고, ESC와 원래 위치 삽입의 실제 키보드 확인은 남았다.
- [ ] 다음 macOS 로그인에서 자동 실행되는지 확인한다. 테스트를 위해 사용자 로그인 상태를 종료하지 않는다. 앱 토글의 실제 ServiceManagement 등록·해제는 재개 검증에서 확인했다.
- [ ] 두 번째 Mac의 설치·권한·로그인·업데이트·핵심 사용 흐름.

코드·단위 테스트 완료와 위 실사용 검증을 구분한다. 전체 goal은 이 문서만으로 완료 처리하지 않는다. 공개 배포·공증·Homebrew는 현재 범위가 아니다.

## 통합 리뷰 보강

저장된 모델이 목록에서 사라져도 계정 연결을 실패로 고정하지 않고 모델 Picker에서 복구하도록 계정 상태와 모델 가용성을 분리했다. 로그인·연결 해제·로그아웃의 중복 실행을 막고, 설정 재진입은 명시적으로 상태를 갱신한다. 권한 갱신은 캐시된 shortcutReady 대신 실제 이벤트 탭의 활성화·키 이벤트 마스크를 재확인한다. 해당 stale 상태와 모델 가용성은 실제 AppModel을 사용하는 테스트에 추가했다. 번역 실패가 자기 요청의 오류 처리까지 취소하지 않도록 계정 연결 실패와 요청 실패를 구분했다.


## 잠금 해제 후 재개 검증

- 최신 main 빌드의 일반·번역 탭, 실제 버전 0.1.0 (79), 두 제공자 연결 및 권한 상세의 준비됨 상태를 확인했다.
- 실제 창을 확대/축소해 외곽 880×600 → 420×296을 확인했다. 같은 AX 편집기 객체와 원문이 유지됐다. ‘항상 작게’ 변경 직후 현재 큰 창은 유지됐고, ⌘W로 닫은 후 재호출 시 420×296으로 열렸다. 같은 PID의 상주도 확인했다. 이는 도구가 전달한 조작이며 실제 키보드 확인과 구분한다.
- 안전한 예시 원문으로 실제 Codex Luna 번역을 확인했다. Claude 선택만 바꾼 구간에서는 요청 수가 증가하지 않고 기존 결과·Codex 모델 표시와 ‘다시 번역’ 안내를 유지했다. 버튼 클릭 뒤에만 새 요청 1건과 Claude Haiku 결과·모델 표시를 확인했다. 진단은 요청 단계·식별자만 사용했고 임시 계측 코드는 제거했다.
- 번역이 안 보인다고 판단했던 초기 검증은 AX가 본문 대신 고정 접근성 이름 ‘번역 결과’를 반환한 데서 비롯됐다. 화면의 실제 번역은 정상이었다. 본문이 접근성에서도 읽히도록 고정 label을 식별자로 교체했다.
- Codex 로그아웃 확인창의 경고 문구와 취소 동작을 확인했고 실제 로그아웃은 하지 않았다. 기본 제공자는 Codex로, 열기 정책은 마지막 크기로 복원했다.
- ServiceManagement의 실제 자동 실행 등록·해제를 앱 토글로 수행해 켜짐/꺼짐을 확인하고 원래 꺼짐으로 복원했다. 다음 macOS 로그인에서 실행되는지는 별도 확인이 필요하다.
- 별도 비표시 NSHostingView 하네스가 실제 SourceEditor와 AnyLayout을 사용해 폰트/프레임 변경 전후 selectedRange, markedRange와 편집기 식별자 보존을 확인했다. 화면에 창을 띄우지 않았으며 실제 한글 입력기의 키보드 조작을 대체하지 않는다.

사용자 결정: 현재 두 번째 Mac은 없으므로 다른 Mac 개인 베타 검증은 후속 작업으로 분리한다. 이 Mac의 실제 키보드·삽입 확인과 다음 로그인 검증 범위는 사용자 응답을 기다린다. 미검증 내용을 완료로 표시하지 않는다.

## 재개 중 보완과 증거 파일

- `TranslationView`의 고정 접근성 label을 identifier로 변경해 결과 본문을 접근성에서 가리지 않게 했다.
- 자동 실행의 실제 등록 상태와 실행 승인 상태를 분리했다. 승인 대기 중 중복 등록하지 않고 취소할 수 있으며, 해제 실패 시 실제 켜짐을 꺼짐으로 표시하지 않는다. 실패를 먼저 재현한 fake-adapter 테스트가 수정 후 통과했다.
- 전체 9개 테스트 프로그램과 앱 빌드를 다시 통과했다. 임시 요청 진단 코드는 저장소 변경에서 제거했다.
- 실제 화면: `translation.png`(번역 설정), `expanded.png`(880×600), `provider-change-awaits-action.png`(선택 변경 후 기존 결과 유지), `manual-retranslation.png`(버튼 후 Haiku 결과). `opening-size-menu-before.png`는 선택 메뉴 체크 표시를 정리하기 전의 실제 검증 화면이며 최종 픽셀 비교 근거로 사용하지 않는다.
