# 이미지 입력 실패 분리 POC

기준: PR #12 `596fea1507ee11c26332e91dc086a39c4eeb83c8`. 원본 dirty checkout·설치 앱·사용 중인 POC는 보존하고, 별도 POC 브랜치에서 구현한다. 머지·배포하지 않는다.

## 사용자가 확인할 결과

1. 아이콘 주소가 실패해도 선택 글은 같은 창에서 번역된다.
2. 명시된 작은 표시 크기와 인라인 문맥을 함께 확인한 아이콘은 원래 작은 크기로 표시하고 OCR하지 않는다. alt/aria-hidden만으로 삭제하지 않는다.
3. 이미지를 개별 로드·OCR하고 성공 항목은 계속 처리한다. 한 항목이 전체를 중단하지 않는다.
4. 복사 출처가 검증된 상대 주소와 관찰한 Bluesky/GitHub/문서 CDN을 처리한다. HTTPS·호스트·리다이렉트·크기·쿠키/인증 제한은 유지한다.
5. 글·이미지 결과를 구분해 완료/부분 실패를 알리고, 글 번역 결과는 부분 실패에서도 복사할 수 있다.

## 작업 순서

- [x] 기준 버전을 별도 고정하고 동일한 합성 HTML·이미지 5개로 before 영상을 만든다.
- [x] 파서가 이미지 역할·크기·텍스트 위치·출처를 보존하고 부분 로드 결과를 반환하게 한다.
- [x] 선택 글 번역을 이미지 로드/OCR 성공과 분리한다. 이미지는 각자 처리하되 제공자는 기존 선택 CLI와 클라이언트를 재사용한다.
- [x] 같은 창에서 인라인 아이콘과 본문 이미지, 원본 유지/부분 실패 상태를 표시한다.
- [x] 합성 회귀·정상 빌드·다운로드 경계·최대 2회 실제 합성 번역 요청으로 검증한다.
- [x] 같은 입력의 after 영상과 1~5 동작 결과, 테스트 POC 실행 경로를 제공한다.

## 영상·증거 기준

전후 영상은 각 버전의 실제 TranslationView를 합성 입력으로 실행해 녹화한다. 화면 기록 권한이나 다른 앱의 화면을 수집하지 않고 해당 앱 뷰만 합성 영상으로 기록한다. 준비된 번역 응답을 쓰는 5개 장면과 실제 제공자 요청 검증을 구분한다. 물리적 드래그·전역 ⌘C 두 번의 증거로 제시하지 않는다.

표본: (1) 실패하는 작은 아이콘+글 (2) 18px 인라인 이미지 (3) 성공·실패 본문 이미지 혼합 (4) 상대 주소/다른 CDN (5) 이미지가 모두 실패한 글의 부분 성공·복사.

사용자·웹사이트 원문/이미지/OCR/번역문을 로그·파일·스크린샷·진단 서버에 저장하지 않는다. 명시적으로 만든 합성 표본과 영상·수치만 산출물로 남긴다. 제공자의 처리·보관은 별도 범위다.
