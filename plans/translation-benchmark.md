# 번역 속도 검증

상태: 초기 설계에 이어 Codex 파일럿, Claude 경로 교차 측정, Claude Haiku 4.5 ↔ 5.5 비교를 진행했다. 결과는 아래 절에 있다. Codex 대기 스레드·Fast 측정은 [Codex 번역 후속 개선](codex-translation-followup.md)에 있다.

## 요구사항과 측정 경계

초기 목표는 **대체로 1초 이내에 번역 전체 완료**다. 2026-09-19 사용자 확인으로 구독을 유지하고 현재 1초 미달은 개선 목표로 남긴 채 앱을 완성한다. 첫 글자 표시나 로딩 UI 표시는 완료가 아니다.

- 전역 호출: 두 번째 ⌘C 이벤트 감지부터 클립보드의 이번 복사 텍스트 확인, 번역 요청, 전체 번역문 화면 반영까지. 클립보드 갱신 대기도 포함하며 첫 번째와 두 번째 입력 사이 시간은 별도 기록한다.
- 수동 입력: 마지막 입력 또는 IME 조합 종료부터 전체 번역문 화면 반영까지. 자동 요청 대기 시간도 포함한다.
- 엔진 단독: 원문이 준비된 상태에서 요청을 시작해 전체 결과를 받을 때까지. 앱 전체 성능과 별도로 기록한다.
- 첫 결과 표시 시간은 체감 속도의 보조 지표로만 사용한다.

초기 제안은 일반 문장·문단의 **p95 ≤ 1,000ms**다. 사용자에게서 확정된 백분위나 글자 수는 없으므로 지원 분량은 실제 입력 표본으로 정한다. 엔진이 1초를 모두 소비하면 OS 연동과 화면 표시 여유가 없다는 점을 반영한다.

## 표본과 조건

1. 한국어 → 영어와 영어 → 한국어 각각 짧은 문장, 일반 문단, 긴 문단을 준비하고 실제 글자 수를 기록한다.
2. 기술 용어, 코드, 숫자·단위, 부정 표현, 여러 줄 입력을 포함한다.
3. 후보마다 동일한 표본·번역 지시를 사용한다. 설명 없이 번역문만 반환하도록 한다.
4. 초기 비교는 후보별·방향별·일반 분량 구간별로 최소 30회를 제안한다. 최종 후보는 각 구간 100회 이상으로 재검증하고 표본 수를 공개한다.
5. 동일 문장 재사용으로 인한 캐시 효과를 기록한다. 캐시 적중 결과만으로 일반 성능을 판정하지 않는다.
6. 기기·OS·네트워크·엔진 버전·모델·출력 길이·실행 도구의 기동 상태를 함께 기록한다.
7. 앱 실행 후 첫 요청, 로그인·모델 다운로드 등의 최초 준비, 준비된 상태의 반복 요청을 분리한다. 첫 요청 지연을 숨기지 않는다.

## 최소 품질과 속도 비교

선정 원칙은 **품질 최소 기준을 통과한 측정 후보 중 전체 번역이 가장 빠른 모델**이다. 가벼운 모델이나 기존 구독 사용 자체를 우선하지 않는다.

- 의미, 부정, 숫자·단위, 기술 용어가 유지되고 한국어·영어 문장이 이해 가능하고 자연스러워야 한다.
- 의미 반전·내용 누락·숫자 변경은 중대한 오류로 기록한다. 문체 선호와 의미 오류를 구분한다.
- 동일 표본의 원문과 번역을 대조하고, 기술 문서와 일상 문장의 대표 결과를 사용자가 검토할 수 있게 제공한다.
- 정량 합격선은 아직 미정이다. 본 측정 전에 표본과 품질 판정 기준을 정하고, 결과를 본 뒤 특정 후보에 유리하게 바꾸지 않는다.
- 통과 후보의 전체 p50·p95와 오류율을 함께 비교한다. 일반 분량의 p95 우선, p50 보조를 초기 비교안으로 두며 분량별 순위가 다르면 그 차이를 기록한다. 세상에서 가장 빠른 모델이라고 일반화하지 않는다.

## 후보 선택

사용자 결정에 따라 ChatGPT 구독으로 로그인한 Codex app-server 경로에서 모델을 비교한다. model/list로 실제 사용 가능한 모델과 지원 reasoning effort를 조회한다. 번역은 최소 지원 effort부터 비교하고, 개발 서브에이전트의 Luna Max 설정과 구분한다. 후보와 연결 근거는 [구독 연결 조사](engine-candidates.md)에 기록한다. 구독 경로라는 이유로 품질·속도 기준을 완화하지 않는다.

실제 요청 전 계정 유형이 chatgpt임을 확인한다. API 키 과금으로 자동 전환하지 않으며 구독 사용량 제한을 기록한다. 예시·모의 응답은 속도 검증 결과에서 제외한다.

| ----------- | -------------- | ----------- | ---- | -------- | -------- | --------------- | ------------- | ------ |
| 미선정      | 미측정         | 미측정      | —    | —        | —        | —               | —             | 미검토 |

- 시간을 잴 때는 단조 증가 시계를 사용한다. 화면 완료는 전체 결과가 UI에 반영된 시점으로 계측한다.
- 성공한 요청의 지연 백분위와 별도로, **전체 시도 중 1초 이내에 성공한 비율**을 기록한다. 오류·타임아웃을 분모에서 빼지 않는다.
- 첫 결과 시간, 클립보드 갱신·읽기, 실행 도구 기동, 엔진 호출, UI 표시 시간을 별도 기록해 병목을 구분한다.
- 품질은 의미·부정·숫자·단위 보존, 기술 용어, 문단·코드 유지, 불필요한 설명 유무를 확인한다.

## 판정

최소 품질을 통과한 후보 중 전체 완료 속도로 우선순위를 정한다. 제안한 p95 기준 및 전체 시도의 95% 이상이 1초 이내 성공이라는 기준의 달성 여부도 별도로 기록한다. 선택한 후보를 Mac 최소 구현에 연결하며, 품질 통과나 최속 선정만으로 1초 목표 달성을 주장하지 않는다. 전체 앱에서 재측정하기 전까지 엔진 단독 합격으로만 표시한다.

아무 후보도 만족하지 못하면 측정값과 병목을 보고한다. 첫 토큰 시간으로 지표를 바꾸거나 긴 입력·오류를 조용히 제외해서 통과시키지 않는다. 지원 분량이나 엔진을 조정해야 한다면 변경 이유를 명시한다.

## 파일럿 실행 결과

2026-09-19: [30회 파일럿](../benchmarks/pilot-summary.md)에서 모든 요청은 성공했지만 1초 이내는 0회였다. 현재는 클라이언트 전체 시간이며 앱 전체 측정과 최종 모델 선정은 미완료다. 다음 작업은 준비 비용과 모델 응답 시간의 분리 측정이다.

## Claude 경로 교차 측정 — 2026-10-03

`DEEPK_RUN_LIVE_BENCHMARK=1 ./scripts/benchmark-claude.sh [결과.json] -- [옵션]`은 앱과 같은 `ClaudeTranslationClient`로 경로별 arm을 표본·반복마다 번갈아 실행한다. `--dry-run`은 요청 없이 일정만 출력한다. 결과는 새 파일에만 쓰며 번역문은 `--store-output`을 줄 때만 저장한다.

| arm | 의미 |
| --- | --- |
| `baseline-json` | 기존 방식: 매 번역 `auth status` + 단발 `--output-format json` |
| `baseline-json-proof` | 단발 json + 30초 증명 재사용(전송 방식 효과만 분리) |
| `stream-warm` | 준비된 대기 프로세스 사용 |
| `stream-idle` | `--idle-gaps` 초만큼 쉰 뒤 사용 |
| `stream-immediate` | 직전 결과 직후 요청(교체 프로세스 기동 중) |
| `stream-ondemand` | 대기 프로세스 없이 요청마다 stream 프로세스 기동 |

| 후보 / 버전 | 경로·분량 | 횟수 | 전체 p50 | 첫 글자 p50 | 오류 | 품질 |

p50은 방향별 셀 값의 범위다. 셀당 n<20이라 p95는 참고값이다. 엔진 단독 시간이며 앱 전체 1초 달성으로 표시하지 않는다. 근거와 사용 패턴별 결과는 [Claude 대기 프로세스 기록](engine-candidates.md#claude-대기-프로세스스트리밍--2026-10-03)을 따른다.

## Claude Haiku 4.5 ↔ 5.5 비교 — 2026-10-08

같은 `stream-warm` 경로와 CLI 2.1.293으로 [`translation-samples-v2.json`](../benchmarks/translation-samples-v2.json) 20개 × 3회를 블라인드 비교했다. 사전 기준 중 '중대 오류가 4.5 이하'는 미달이었지만, 사용자 결정으로 Haiku 5.5를 Claude 기본값으로 바꾸고 원문 섞임을 줄이도록 프롬프트를 보강했다. 채점 방법과 남은 위험은 [비교 결과](../benchmarks/haiku-45-vs-55-summary.md)를 따른다.

| 후보 / 버전 | 경로 | 횟수 | 전체 p50 | 전체 p90 | 오류 | 품질 |
| --- | --- | --- | --- | --- | --- | --- |
| Haiku 4.5 / CLI 2.1.293, 보강 전 프롬프트 | 대기 프로세스 | 60 | 1,109ms | 2,361ms | 0 | 중대 오류 0 |
| Haiku 5.5 / CLI 2.1.293, 보강 전 프롬프트 | 대기 프로세스 | 60 | 898ms | 1,404ms | 0 | 중대 오류 3(영→한 원문 섞임) |
| Haiku 5.5 / CLI 2.1.293, 프롬프트 보강 후 | 대기 프로세스 | 60 | 859ms | 1,320ms | 0 | 중대 오류 1(지시문 머리말) |

엔진 단독 시간이며 앱 전체 1초 달성으로 표시하지 않는다. 합성 표본 20개, 3회의 소규모 검증이고 채점은 사람이 아닌 에이전트가 했다(보강 전 2명, 보강 후 1명). Haiku 4.5는 프롬프트 보강 뒤 다시 재지 않았다.
