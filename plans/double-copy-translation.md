# 두 번 복사 자동 번역

상태: 감지·클립보드·화면 연결을 구현했다. 2026-09-19에 보고된 무반응은 두 문제로 확인해 고쳤다. 현재 앱에 입력 모니터링이 연결되지 않아 감시가 시작되지 않았는데 그 안내가 숨은 창에만 있었고, 개발 빌드의 cdhash 서명 때문에 빌드마다 권한 식별이 바뀌었다([무반응 해결 계획](shortcut-response-recovery.md)). 사용자가 실제 키보드로 단축키 창이 뜨는 것을 확인했고([Mac 연동 기록](mac-integration-checks.md)), 2026-10-09에는 실제 Chrome 두 번 복사 번역도 확인했다([웹 수식 복사](web-math-copy.md)). 실제 키보드의 ESC 복귀·원래 위치 삽입·반복 호출과 지원 앱 범위는 아직 미검증이다([실행 계획](remaining-work.md)).

## 확정한 흐름

텍스트 선택 → ⌘C 두 번 → 이번에 복사한 원문을 deepK 창에 표시 → 즉시 AI 번역 요청 → 결과 읽기 → 닫고 원래 앱으로 복귀.

번역 버튼이나 Enter는 필요하지 않다. 번역 결과의 원래 위치 삽입은 별도의 명시적 사용자 동작이며 자동으로 실행하지 않는다. 모델 선정은 [번역 속도 검증](translation-benchmark.md)을 따른다.

## 구현 순서

1. 키 입력 감지 방식을 작은 실험으로 검증한다. 일반 복사 이벤트를 가로채거나 막지 않고 관찰할 수 있는지, 필요한 macOS 권한과 제한을 확인한다.
2. 두 번 입력 판정을 구현한다. 키를 누른 채 발생하는 반복 입력을 두 번으로 세지 않는다. 시간 초과, 다른 키 입력, 호출 앱 변경 시 이전 판정을 초기화한다. 연속 입력 허용 시간과 세 번 이상 입력의 재호출 정책은 실험 후 결정한다.
3. 두 번째 복사 이벤트 처리 직전의 클립보드 changeCount와 이후 변화를 비교해 이번 복사의 텍스트를 확보한다. 첫 번째 복사만으로는 클립보드를 읽거나 번역을 요청하지 않는다. 두 번째 키 이벤트 직후에는 아직 갱신 전일 수 있으므로 제한된 대기로 갱신을 확인한다. 같은 문자열을 다시 복사하는 경우도 검증하며 문자열 동일 여부만으로 실패를 판단하지 않는다.
4. 이번 복사 성공을 확인할 수 없으면 이전 클립보드 텍스트를 자동 전송하지 않는다. 첫 복사가 성공했더라도 두 번째 복사의 갱신을 확인하지 못하면 번역을 시작하지 않는다. 같은 문자열 재복사는 문자열 비교 대신 두 번째 복사의 changeCount 갱신으로 확인한다. 빈 값·이미지·파일만 복사된 경우에는 번역을 요청하지 않는다.
5. 원래 앱과 포커스를 기록한 뒤 창을 재사용해 원문과 번역 중 상태를 표시한다. 텍스트 준비 후에는 타이핑용 디바운스 없이 요청한다. 초기 인증·권한 설정은 별도이며, 정상 준비 상태에서는 추가 사용자 조작이 없다.
6. 각 호출에 요청 ID와 원문 버전을 부여한다. 새 호출 시 가능한 이전 요청을 취소하고, 취소가 늦어도 이전 응답은 표시하지 않는다. 오래된 결과의 복사·삽입을 막는다.
7. ESC/닫기 후 원래 앱으로 복귀한다. 설정 창과 한글 조합 중 ESC는 별도로 처리한다.

복사 호출은 클립보드를 읽는 경로다. 결과를 클립보드에 자동으로 덮어쓰지 않는다. 지속적인 클립보드 변경만으로 번역을 시작하지 않는다.

## 검증 사례

| 사례 | 확인할 결과 |
| --- | --- |
| ⌘C 한 번 / C 길게 누르기 | 일반 복사 유지, 번역 미호출 |
| 허용 시간 안의 ⌘C 두 번 | 최신 원문 표시와 번역 요청 한 번 |
| 시간 초과 / 중간 다른 키 / 앱 전환 | 이전 입력과 묶어서 오호출하지 않음 |
| 같은 원문 재복사 | 새 복사 여부를 확인하고 정상 호출 |
| 갱신 지연 / 복사 불가 | 제한된 대기 후 처리, 과거 텍스트 자동 전송 없음 |
| 빈 값 / 이미지 / 파일 | 번역 요청 없음, 상태 안내 |
| 비밀번호 관리자 복사(숨김·임시 표시, 문자열을 쓴 뒤 10ms 안에 표시를 붙이는 경우 포함) | 번역 요청 없음, 원문 창에 표시하지 않음, 민감 항목 안내. 실제 비밀번호 관리자 앱은 미확인 |
| Chromium 브라우저 복사(KaTeX 수식·링크·인라인 코드) | 수식은 한 줄 수식으로 정리, 링크·인라인 코드는 결과에 유지(수식 정리로 글자가 바뀐 복사는 링크·인라인 코드 없이 번역). `org.chromium.source-url` 타입이 없는 복사(Safari·Firefox 등)는 지금처럼 일반 텍스트 |
| 번역 중 다른 문장 재호출 | 새 원문에 맞는 결과만 표시 |
| 권한 없음 / 네트워크 실패 | 실패 상태와 복구 방법 표시 |
| 창 닫기 / 호출 앱 종료 | 유효한 대상만 포커스 복원 |

실제 사용하는 브라우저와 편집기를 정하고 앱·OS 버전과 함께 결과를 기록한다. 다른 두 번 복사 도구와의 충돌도 확인한다. 외부 앱 복사와 포커스 동작은 단위 테스트나 빌드 성공으로 대체하지 않는다.

## 완료 기준과 남은 결정

- 두 번째 ⌘C 감지부터 클립보드 확인·엔진 요청·결과 전체 표시까지 시간을 측정한다. 첫 토큰 표시는 보조 지표다.
- 일반 복사 보존, 최신 원문, 중복 요청 방지, 결과 일관성, 복귀를 실제 앱에서 확인한다.
- 현재 구현은 입력 간격 500ms, 두 번째 복사 후 클립보드 대기 250ms, 확인 주기 10ms이다. 수신 전용 CGEvent 탭과 입력 모니터링 권한을 사용하며, 한 쌍을 처리한 뒤 세 번째 입력은 새 쌍을 시작한다. 이 설정의 실제 앱 적합성은 후속 계획에서 검증한다.
- 클립보드 확인 규칙(2026-10-12 기준): 두 번째 ⌘C 뒤 changeCount가 바뀌면 읽기 전후 changeCount가 같은 읽기만 쓴다. 파일 URL이 있는 복사는 문자열이 있어도 번역하지 않는다. 비밀번호 관리자가 붙이는 `org.nspasteboard.ConcealedType`·`TransientType` 표시가 있으면 문자열을 읽기 전에 거절하고 ‘비밀번호 등 민감한 항목으로 표시된 복사는 번역하지 않습니다’를 표시한다(PR #52). 문자열을 먼저 쓰고 표시를 나중에 붙이는 앱(arboard를 쓰는 1Password·Bitwarden)이 있어, 성공 후보는 다음 확인 주기(10ms)에 같은 항목에 표시가 없을 때만 확정한다. 그보다 늦게 붙는 표시는 걸러지지 않을 수 있다. 대기 한도(250ms)에 닿은 마지막 후보는 기다리지 않고 바로 확인한다. Chromium 복사(`org.chromium.source-url` 타입)는 같은 읽기 안에서 512KB 이하의 `public.html`도 읽어 수식 정리(PR #51)와 링크·인라인 코드 가져오기(PR #53)에 함께 쓴다. 그 밖의 앱에서는 HTML을 읽지 않는다.
- 권장 PR 분리: 입력 감지와 클립보드 검증 → 창과 자동 번역 연결 → 포커스 복귀와 실패 경로 보완. 각 PR은 독립적으로 검증 가능한 범위를 설명하고 실제 화면 변경이 있을 때 실행 증거를 첨부한다.
