# 결과 창 코드 표시 (S6′)

상태: 2026-10-12 C1(스타일 값과 렌더러) 구현. 2026-10-13 펜스 제목을 머리줄에 보이는 규칙 추가(3절 '블록 제목'). 2026-10-13 PR #57 독립 리뷰 반영(3절 '성능', 복사됨 자리, 완료 때 다시 그리기, 커서, 접기 줄 수 보정, 4절 테스트, 8절 그대로 둔 것). 2026-10-13 C2(문법 색, 긴 코드 접기) 구현(6절). 2026-10-14 PR #58 독립 리뷰 반영(6절: 숨긴 줄 그리지 않기, 접기 누름은 그 블록만, 같은 결과 편집 뒤 펼침 유지, 끝 빈 줄, 토크나이저 규칙, 한계). 2026-10-13 C3(설정 '표시' 탭과 코드 스타일 고르기 화면) 구현(7절). 2026-10-14 PR #59 독립 리뷰 반영(7절: 미리보기 출처 칩, 커서, 넓히는 중 닫기·돌아오기, 저장 기다림, 테스트). 이제 스타일·접기·출처 칩·문법 색을 설정 화면에서 바꾼다. 실제 앱 확인은 하지 않았다(테스트와 화면 밖 렌더만).

## 1. 범위

결과 창 서식은 설정에서 고르는 '코드 스타일'과, 스타일과 따로 켜고 끄는 동작(긴 코드 접기, 링크 출처 표시, 문법 색)으로 나눈다. 설정 화면은 확정 시안 S6′(pen.dev `HZjyh`)를 따른다. 렌더러는 하나이고 스타일은 값이다.

연속 PR 세 개로 나눈다.

| PR | 내용 | 사용자가 보는 변화 |
| --- | --- | --- |
| C1 | 스타일 값, 표시 설정 저장, 렌더러의 머리줄·블록 복사·링크 밑줄·출처 칩, AppModel 연결 | 기본 Native 카드와 머리줄, 블록 복사. GitHub는 `defaults write`로만 |
| C2 | 직접 만든 줄 단위 토크나이저(문법 색), 긴 코드 접기 | 문법 색, 접기 |
| C3 (이 PR) | '표시' 탭과 620폭 고르기 화면, 미리보기 | S6′ 설정 화면 |

C1은 문법 색, 접기, 설정 UI를 넣지 않는다. 그래도 스타일 값에는 문법 팔레트와 접기 하단 값을 미리 넣는다. C2는 렌더러만 고치면 된다.

## 2. 값의 출처

- Native: `eK0C3`(E · macOS Native), GitHub: `Ubex8`(B · GitHub). 메인 세션이 pen.dev에서 직접 읽은 값(`~/.claude/plans/smooth-prancing-mitten/pen-values.md`)을 그대로 쓴다.
- pen.dev 여백은 줄 높이 1.6인 CSS 상자다. 앱의 SF Mono 13 줄은 16pt이고 줄 간격 5를 더해 21pt 간격을 만든다. 그래서 블록 위·아래 여백(`bodyTop`, `bodyBottom`)에 반행간을 더한다(위 +2, 아래 +3). 1.5배 내보내기 PNG에서 GitHub 첫 줄 기준선(머리줄 아래 27.7pt)과 마지막 기준선(카드 아래 19.7pt)으로 확인했다.
- pen.dev에 없어서 정한 값:
  - Native의 펼친 블록 아래 여백 10. 시안의 Native 블록은 접힌 상태(하단 줄이 바로 붙음)뿐이라 펼친 블록의 아래 여백이 없다. 값 그대로(0+3)는 마지막 줄이 카드 끝에 닿는다.
  - 출처 칩 앞 6, 뒤 2. E 시안 PNG에서 쟀다.
  - 칩 kern은 칩 안쪽 여백 + 1(Native 5→6, GitHub 6→7). 이웃 글자와 1pt 떨어진다.
- 문법 팔레트: Native는 Xcode Default (Light)/(Dark), GitHub는 Primer. 토큰 종류 10개(keyword, type, function, string, number, comment, property, tag, command, flag)를 모든 팔레트가 정의한다. 출처에 없는 종류는 command→function, flag→property, tag→keyword로 채운다.

**카드와 머리줄**

- Native: 카드 채움은 흰 배경에서 #F2F2F7이 되는 반투명 색(#00005F 5%)이다. 창 배경이 회색이어도 카드가 배경보다 어둡게 남는다. 테두리 검정 6%, 모서리 8. 머리줄 32pt에 `</>` 기호와 "TypeScript · 12줄"(11pt #8E8E93), 오른쪽에 파란 '복사'(11pt 500 #007AFF).
- GitHub: #F6F8FA 카드, 1pt #D0D7DE 테두리, 모서리 6. 머리줄 35pt와 아래 구분선, 원래 태그를 소문자 고정폭 12pt #59636E로, 오른쪽에 23×23 흰 아이콘 버튼.
- 코드 줄은 모두 같은 줄 간격이다. 마지막 줄이 줄바꿈돼도 21pt 간격을 지킨다. TextKit은 글 전체의 마지막 줄 아래에만 줄 간격을 넣지 않는다. 그래서 마지막 줄의 문단 간격에서 줄 간격만큼 빼고, 카드 아래 끝도 줄 간격을 뺀 자리에서 잰다. 카드 크기와 다음 글 위치는 그대로다.
- 언어 이름은 태그를 소문자로 바꿔 찾는다. `text`·`txt`·`plain`·`plaintext`와 태그 없는 블록은 이름을 쓰지 않는다(Native는 "</> 3줄"). 모르는 태그는 쓴 그대로 보인다.
- 펜스에 제목이 있으면 언어 앞에 쓴다. 아래 '블록 제목'.

**블록 제목** (2026-10-13 사용자 결정)

복사한 위젯에서 선택된 탭 이름은 그 코드의 제목이다. impeccable.style의 'Most Agents | Codex' 탭에서 'Most Agents'는 명령이 어느 환경용인지 말해 준다. B는 이 이름을 펜스 정보 문자열에 넣고(```` ```text title="Most Agents" ````), C는 머리줄에 보인다. 번역하지 않는다.

- 머리줄 글자는 [제목, 스타일 방식의 언어 이름, 줄 수(스타일이 보일 때)] 중 있는 것만 " · "로 잇는다.
  - Native: "</> Most Agents · 1줄", 언어가 있으면 "</> npm · Bash · 1줄"
  - GitHub: "Most Agents", "npm · bash"
  - 제목은 쓴 그대로다. 소문자(`rawTag`)·대문자(`uppercaseTracked`) 변환은 언어 부분에만 한다. 대문자 스타일의 자간은 라벨 전체에 그대로 둔다.
  - 제목이 언어를 이미 말하면 언어 부분을 뺀다(독립 리뷰 반영, 5절에서 확인 필요). 언어 탭 위젯(Docusaurus `groupId=language`, SDK 문서)에서 B는 ```` ```python title="Python" ````을 만든다. 그대로 이으면 "Python · Python · 2줄"이 된다.
    - 대소문자를 무시하고 제목이 표시 이름(`JavaScript`)이나 태그(`js`)와 같을 때만이다(`CodeLanguageName.display(for:under:)`).
    - Native "</> Python · 2줄", GitHub "Python", VoiceOver "Python 코드 복사". 남는 것은 제목이므로 쓴 그대로 보인다.
    - "Python 3", "Node.js"처럼 언어를 언급만 하는 제목은 언어를 그대로 잇는다.
- 제목 읽기(`CodeBlockChrome.title(fromInfo:)`)
  - 앱이 만든 펜스, 모델이 쓴 펜스, 사용자가 쓴 펜스(```` ```js title="a.js" ````)를 가리지 않는다.
  - 태그나 `{…}` 묶음 뒤의 첫 `title=` 속성을 읽는다. 큰따옴표·작은따옴표 모두 된다. 문법은 `TranslationMarkup.reading(of:)`와 같다.
  - 정보 문자열이 아닌 줄(```` ```npm install ````, 머리 없는 `title="x"`)과 빈 제목은 제목이 없다.
  - `{.py title="x"}`처럼 `{…}` 묶음 안은 읽지 않는다. Pandoc 문법이고 앱이 만드는 펜스는 쓰지 않는다.
  - `TranslationMarkup.swift`(B 소유)는 고치지 않고 `CodeBlockChrome.swift`에서 직접 읽는다. 테스트가 제목을 읽은 줄은 `TranslationMarkup`도 정보 문자열로 읽는지 확인한다.
- 길면 복사 컨트롤 앞에서 끝을 "…"로 줄인다.
  - 복사 컨트롤의 위치와 클릭 영역은 라벨 길이와 상관없이 그대로다.
  - 구분점 바로 뒤에서 잘리면 "·…"가 점 줄처럼 보여서, 끝의 구분점과 공백을 빼고 "…"를 붙인다. 그래서 텍스트 시스템의 꼬리 줄임 대신 직접 자른다.
  - 잘린 라벨은 그 자리에 전체 라벨을 툴팁으로 붙인다.
  - 366pt 폭에서 'Most Agents' 같은 탭 이름은 두 스타일 모두 다 보인다. B의 최대 40자 제목은 언어가 붙으면 잘릴 수 있다. 라벨 자리는 Native가 약 288pt(시스템 11pt), GitHub가 고정폭 12pt로 42자다.
- VoiceOver 복사 동작 이름에 제목을 넣는다: "Most Agents 코드 복사", "npm, Bash 코드 복사". 머리줄은 그린 것이라 따로 접근성 요소가 없다(C1 그대로). VoiceOver가 제목을 듣는 곳은 이 동작 이름뿐이다.
- 스트리밍: 여는 줄이 끝나기 전에는 `TranslationMarkup`이 그 줄을 보류하므로 상자가 없다. `title="Most Ag` 같은 반쪽 제목은 그려지지 않는다. 제목은 표시 텍스트에 없으므로 뒤에만 붙는 성질도 그대로다.

**B–C 약속: 제목** (B의 설계 노트에도 같은 내용)

- B가 만드는 여는 줄: 백틱(`SourceCodeBlock.fence` 개수) + 태그 + ` title=` + 따옴표로 감싼 제목.
  - 태그는 블록의 언어다. 언어가 없고 제목만 있으면 `text`.
  - 큰따옴표로 감싼다. 제목에 큰따옴표가 있으면 작은따옴표로 감싼다.
  - 두 따옴표가 모두 있거나, 백틱·줄바꿈·제어 문자가 있거나, 앞뒤 공백을 자르고 안쪽 공백을 하나로 줄인 길이가 40자를 넘으면 제목이 없다. 그때 선택된 탭은 다른 탭처럼 지운다(1단계와 같음).
- 제목 없는 블록의 여는 줄은 1단계와 바이트까지 같다. GitHub·MDN·Sphinx 시료는 바뀌지 않는다.
- C는 어느 펜스에서든 제목을 읽고 그대로 보인다. 대소문자를 바꾸거나 번역하지 않는다.
- 알려진 한계: 제목은 코드도 줄도 아니다. 줄 수, 블록 복사, `fences: .none` 일반 텍스트 복사, 삽입은 코드만 쓴다. 블록 복사로 옮긴 코드에는 'Most Agents'가 없다.
  - 펜스를 남기는 일반 텍스트(`.fenced`)와 '마크다운만' 복사는 정보 문자열을 그대로 옮기므로 제목이 남는다.
  - 기본 복사 형식 '서식 포함'의 HTML(`TranslationMarkup.html(in:)`)과 RTF(`ResultClipboard.rtf(for:)`)에는 제목이 없다. Notion·Pages처럼 서식을 읽는 곳에 붙이면 'Most Agents'가 빠진다. HTML에 제목을 싣는 일은 B 소유의 `TranslationMarkup.html`을 고쳐야 하므로 이 PR 밖이다.

**블록 복사**

- 그 블록의 표시 텍스트만 복사하고 마지막 줄바꿈은 뺀다. 문자열(`.string`)만 쓴다.
- 목록 안 펜스의 들여쓰기는 되살리지 않는다. 그 들여쓰기는 markdown 구조이지 코드가 아니어서, 되살리면 목록 안 Python 블록이 `IndentationError`를 낸다. 복사 버튼(`plainText(in:fences: .none)`)은 문서를 옮기므로 계속 되살린다. 앱이 0열에 만드는 B의 펜스는 두 결과가 같다.
- 스트리밍 중인 초안 블록과 지난 결과(stale)의 블록은 비활성(35%)이고 눌리지 않는다. 전역 복사와 같은 `copyableLength` 규칙이다.
- 누른 뒤 1.5초 동안 '복사됨'(아이콘은 체크)으로 보이고, VoiceOver로 "코드를 복사했습니다"를 알린다.
- 복사 컨트롤 자리는 '복사'와 '복사됨' 중 넓은 쪽으로 잡는다(글자 복사, 아이콘+글자 복사). 그래서 '복사됨'도 라벨 자리와 8pt 간격 밖에 그려진다. 예전에는 '복사' 폭으로 잡아 자리를 가득 채운 긴 제목과 '복사됨'이 겹쳤다.
  - Native 컨트롤은 29×14, 클릭 영역은 29×24다(366pt 폭에서 라벨 자리 314→305pt). '복사'는 전처럼 오른쪽 끝에 붙는다.
  - 아이콘+글자 버튼(시험 스타일)은 '복사됨'에 맞춘 폭이고 '복사'는 가운데에 놓는다.
- 받던 글과 같은 글로 완료되면 편집도 다시 칠하기도 없다. 그래도 `copyableLength`나 지난 결과 여부가 바뀌면 복사 컨트롤을 다시 그린다. 예전에는 초안 꼬리 블록의 컨트롤이 이미 눌리는데도 마우스를 올릴 때까지 흐린 비활성 모양으로 남았다.

**클릭과 접근성**

- 그린 컨트롤은 `chromeControl(at:)`(찾기)와 `perform(_:)`(실행)로 나눈다. 마우스, VoiceOver, 테스트가 같은 경로를 쓴다. 클릭 경로(`mouseDown` → 추적 루프)도 테스트한다. 화면에 올리지 않은 테두리 없는 창에서 놓기 이벤트를 `NSApp.postEvent`로 먼저 넣고 `mouseDown(with:)`을 부른다. 루프가 끝나지 않으면 10초 뒤 테스트가 실패로 끝난다.
- 컨트롤은 첫 클릭을 받고, 비활성 창에서 눌러도 창을 앞으로 가져오지 않는다. 누른 채 밖으로 나가 놓으면 실행하지 않고, 선택은 바뀌지 않는다.
- 호버는 `.activeAlways` 추적 영역으로 받는다(결과 창은 대개 키 창이 아니다). 그린 컨트롤에는 커서 영역이 없어서 그 위에서 손가락 커서를 직접 켠다. 컨트롤을 벗어나면 글 위의 I빔(링크 위면 손가락)으로, 뷰를 벗어나면 화살표로 되돌린다. 예전에는 키 창이 아닌 패널에서 손가락이 남았다. 확인은 화면 밖 창의 합성 이벤트로만 했다. 툴팁은 `addToolTip(_:owner:userData:)`로 복사 컨트롤에 '코드 복사'를, 잘린 머리줄 라벨에 전체 라벨을 붙인다. 영역의 owner는 뷰이고, `view(_:stringForToolTip:point:userData:)`가 태그마다 글자를 돌려준다. 등록한 영역은 `chromeToolTips`에 남아 테스트가 확인한다.
- VoiceOver는 결과 텍스트의 사용자 지정 동작으로 "TypeScript 코드 복사"를 받는다. 제목이 있으면 "npm, Bash 코드 복사", 이름이 없으면 "코드 블록 2 복사".

**성능** (독립 리뷰 반영)

- 툴팁 영역은 상자, 복사 가능 여부, 라벨 글자 중 하나라도 바뀔 때만 다시 등록한다. 상자 뒤에 글만 붙는 조각은 영역을 그대로 둔다.
- 머리줄 라벨과 그 라벨이 자리에 다 들어가는지는 블록(범위, 정보 문자열)별로 기억한다. 맞춘 결과는 라벨 자리 폭과 함께 기억하므로 폭이 바뀌면 다시 잰다. 다시 칠하기는 시작 위치부터의 블록을 잊는다. 그 블록의 글자가 바뀌었을 수 있어서다. 스타일이 바뀌면 모두 잊는다.
- 마우스 이동은 상자를 한 번만 계산한다. 그리기와 마우스 이동은 그 근처 줄의 상자와 링크 칩만 배치한다(`chips(in:)`과 같은 방식). 출처 칩 폭은 호스트별로 기억한다.
- 측정(-O, 화면 밖 창, 384pt): 문단마다 10줄 swift 블록이 있는 200문단(약 8만 자)을 600조각으로 받기
  - Native 4.3–5.5초 → 3.0–3.4초, GitHub 3.6–4.3초 → 3.0–3.3초. 툴팁 갱신을 아예 뺀 경우는 2.7–2.9초다.
  - 블록 200·링크 200, GitHub+출처 칩: 마우스 이동 한 번 4.1–4.9ms → 0.03ms, 보이는 화면 다시 그리기 5.7–12.9ms → 1.5–2.4ms. 링크 없는 Native의 마우스 이동: 0.6–0.8ms → 0.04–0.07ms.

**링크와 출처 칩**

- 링크 색은 스타일 값이다(Native #007AFF, GitHub #0969DA). 밑줄은 텍스트 시스템이 아니라 뷰가 그린다. 링크 끝 글자의 kern(↗, 출처 칩 자리)까지 밑줄이 이어지지 않게 하기 위해서다. Native는 밑줄이 없고 GitHub는 마우스를 올릴 때만 긋는다.
- 출처 칩은 모든 스타일에서 Native 모양이다. http(s) 링크만 붙고 메일 링크는 붙지 않는다. 호스트는 `www.`를 빼고 28자를 넘으면 가운데를 줄인다. IDN은 실제 주소가 보이도록 punycode 그대로 둔다.
- 칩은 글자가 아니라 링크 끝 글자의 kern으로 자리를 만든다. 저장된 글자, ⌘C, 복사 버튼, 삽입은 그대로다. 칩 자리를 누르면 링크를 연다.
- 지난 결과에서도 칩 자리는 유지하고 흐리게 그린다. 누를 수는 없다. 결과가 지난 결과가 될 때 줄바꿈이 다시 일어나지 않게 하기 위해서다.
- 인라인 코드 칩의 여백 kern은 `.deepKChipKern`에 따로 적는다. 링크가 칩으로 끝나도 출처 칩 kern이 코드 칩을 늘리지 않는다.
- 링크 끝 글자의 칩 여백은 링크가 칩으로 끝날 때만 출처 칩 앞에 둔다. 링크 바로 뒤에 칩이 오면 그 여백은 뒤 칩의 왼쪽 여백이라 출처 칩 뒤에 남긴다.

**블록 상태**

- 블록 단위 상태(복사됨, 호버)는 순서 번호가 아니라 블록 키(시작 위치, 펜스, 첫 줄 해시)로 기억한다. 같은 identity로 다른 번역이 들어오거나 B의 가드가 코드를 제자리에서 바꾸면 새 블록이 된다.
- 키의 펜스는 백틱 수와 언어만 본다. 제목만 바뀐 블록은 같은 코드의 머리말만 바뀐 것이라 같은 블록이다. 예를 들어 모델이 번역한 제목을 B의 가드가 완료 때 제자리에서 되돌려도 복사됨·호버(C2의 펼침) 상태가 남는다. 머리줄은 바로 새 제목으로 다시 그린다. 언어가 바뀌면 문법 색이 달라지므로 새 블록이다.
- identity가 바뀌면 블록 상태를 모두 지운다(A의 재요청 포함).

**실시간 반영**

- 글자가 같으므로 기존 `restyleAll` 경로로 다시 칠한다. 읽던 줄과 선택이 그대로다.
- 연속 변경(C3의 ↑↓)은 100ms 안의 변경을 묶는다. 첫 변경은 바로, 이후는 구간 끝에서 마지막 값 하나만 칠한다.

## 6. C2: 문법 색과 긴 코드 접기

### 문법 색

- 직접 만든 줄 단위 토크나이저다(`SyntaxHighlighter.swift`, `SyntaxLanguages.swift`, Foundation만). 패키지·라이선스 고지가 없고 test.sh의 swiftc 목록에 두 파일만 더한다.
- UTF-16 단위를 ASCII 규칙으로 읽는다. ASCII 밖 단위는 이름 글자로 본다. 한글 주석·이름과 이모지의 범위가 정확하고 서로게이트 쌍을 가르지 않는다.
- 토큰 종류 10개(keyword, type, function, string, number, comment, property, tag, command, flag). 색은 스타일 팔레트에서 온다(2절). 값은 C1 그대로다. Native는 Xcode Default, GitHub는 Primer이고 pen.dev 값(주석 #6E7781 등)과 맞는다.
- 줄 상태가 여러 줄 구문을 다음 줄로 넘긴다: 블록 주석(Rust·Swift·Kotlin은 중첩), 여러 줄 문자열(`"""`, `'''`, JS 백틱, Go 원문 백틱, TOML, Rust `"…"`, 셸 `'…'`·`"…"`), 원문 문자열(Rust `r#"…"#`, C++ `R"x(…)x"`, 이스케이프 없음), HTML 주석과 줄을 넘는 태그, CSS 중괄호 깊이, 셸 줄 끝 `\`.
  - 셸 따옴표는 낱말 앞(줄 처음, 공백·`=`·`(`·`$`·`|`·`;`·`&` 뒤)에서 열릴 때만 다음 줄로 넘어간다(`curl -d '{`). 낱말 안의 따옴표(`It's`)는 그 줄에서 끝나 잘못 열린 따옴표가 한 줄만 칠한다. `\'`는 따옴표가 아니다.
  - HTML·Vue·Svelte의 `<script>`·`<style>` 안은 닫는 태그까지 태그로 읽지 않는다(`i<items`가 태그를 열지 않는다). 템플릿 중괄호(`{#if a<b}`, `{{ a<b }}`) 안의 `<`도 여는 태그가 아니다.
- `.` 바로 뒤 이름은 키워드·리터럴이 아니다(`app.get`, `map.set`, `entry.value`, `range.to()`). Swift `.init`·`.self`와 펼침 `...rest`는 예외다.
- SCSS `$name:`·Less `@name:`은 중괄호 밖에서도 속성 선언이다(`$primary: #333;`).

- `text` 문법은 일반 규칙 하나다. 사이트별 규칙은 없다.
  - 명령 줄만 칠한다: 프롬프트(`$ `, `% `, `> `, `› `, `❯ `, `# `)로 시작하는 줄, 또는 `/`로 시작하는 슬래시 명령(`/impeccable document`). 프롬프트는 주석 색, 나머지는 셸 규칙(첫 낱말 command, 플래그, 문자열)이다.
  - `/usr/bin/env`처럼 `/`가 더 있는 경로는 명령이 아니다. 그 밖의 줄(로그, 그림, 문장)은 그대로 둔다.
  - reconcile B–C 약속 2의 '한 줄 블록이면 명령' 규칙은 넣지 않았다(작업 지시를 따름). ```` ```text ```` 안의 `npm install deepk`는 한 색이다. 스트리밍 중 둘째 줄이 오면 첫 줄 색을 되돌려야 해서 앞 줄 색이 뒤 줄에 기대지 않는 성질과도 맞지 않는다.
- 렌더러: 문법 색이 켜져 있고, 지난 결과가 아니고, 스타일에 팔레트가 있고, 태그에 문법이 있을 때만 칠한다. 지난 결과는 C1처럼 한 색으로 흐리다.
  - 주석 기울임(`commentItalic`, 시험 스타일 Dark)은 SF Mono 이탤릭이라 글자 폭이 같고 줄바꿈이 바뀌지 않는다.
- 캐시(`SyntaxHighlightCache`): 블록 시작 위치마다 각 줄의 토큰과 줄 끝 상태를 기억한다.
  - 다시 칠하는 범위는 C1의 `restyleStart`(바뀐 블록의 옛 마지막 줄 앞 줄부터)다. 다시 읽는 범위는 첫 편집 글자의 줄부터다. 그 앞 줄은 기억한 토큰을 그대로 다시 붙인다. 스트리밍 조각 하나는 1–2줄만 읽는다.
  - 태그가 바뀌거나 블록 시작이 옮겨지면 처음부터 읽는다. B의 가드나 A의 앞말 정리처럼 제자리에서 고친 줄은 편집 위치부터 다시 읽는다(B–C 약속 3, A–C 약속 2).
  - identity가 바뀌거나 문법 색이 꺼지면 비운다. 표시 설정이 바뀌면 처음부터 읽는다.
  - 줄마다 시작 위치도 기억한다. 조각이 올 때 바뀐 줄은 기억한 줄 시작을 이분 탐색해 찾고 그 뒤만 줄바꿈을 센다. 블록 처음부터 세지 않아 긴 블록 스트림이 블록 길이의 제곱이 되지 않는다.
  - CSS에서 `name:`이 선택자인지(다음 `{`가 `;`·`}`보다 먼저인지) 볼 때 한 줄의 다음 `{`·`;`·`}` 위치는 한 번만 찾는다.

### 긴 코드 접기

- 규칙(reconcile 확정안): `resultFoldLineCount`(기본 5)보다 줄이 많은 블록은 N줄만 보인다. 숨기는 것은 N+1번째 줄부터 블록 끝까지, 각 줄의 줄바꿈과 블록의 마지막 줄바꿈까지다. N번째 줄의 줄바꿈은 남겨 그 줄이 자기 문단을 지킨다. 줄은 줄바꿈으로 센다. 아주 긴 한 줄은 접지 않는다.
  - 펜스 안 끝의 공백뿐인 줄은 한도에 세지 않는다(`contentLineCount`). 코드 5줄 + 빈 줄 3개는 접지 않는다. 접히는 블록이면 끝 빈 줄도 앞 줄과 함께 숨기고 꼬리줄의 전체 줄 수에 든다.
- 레이아웃만 바꾼다(H1). 저장소의 글자는 그대로다. 그래서 ⌘C·끌기·서비스, 복사 버튼, 삽입, 블록 복사, VoiceOver가 모두 전체 코드를 받는다.
  - 숨긴 글자에 `.deepKCodeFolded`, 블록 마지막 글자에 `.deepKFoldSpacer`를 붙인다.
  - `CodeFoldLayoutDelegate`(레이아웃 매니저 대리자)가 숨긴 글자를 제어 문자로 만들고 폭 0으로 둔다(줄바꿈은 그대로 줄바꿈). 숨긴 줄 조각은 높이 0이다. 마지막 조각만 스페이서 높이(카드 아래 + 꼬리줄 + 여백 − 줄 간격)를 가진다.
  - 먼저 스파이크로 정했다. `.null` 글리프는 앞 줄 조각에 붙어 문단 간격이 사라지고, 글 끝에서는 16pt짜리 빈 조각이 더 생겼다. 제어 문자 + 폭 0은 둘 다 없다. 가운데 블록, 글 끝 블록, 빈 마지막 줄, CRLF, 줄바꿈되는 숨긴 줄에서 확인했다.
  - 접힌 블록이 글 끝이면 숨긴 마지막 조각의 사용 높이가 0이라 아래 띠(`trailingBand`)가 스페이서를 맡는다.
  - 숨긴 글리프는 그리지 않는다(`CodeFoldLayoutManager`). 숨긴 조각은 모두 꼬리줄 높이에 모여 있어 꼬리줄이 든 영역을 그리면 TextKit이 숨긴 글리프를 전부 그린다. 레이아웃 매니저가 `.deepKCodeFolded` 구간을 속성 구간 단위로 빼고 나머지만 그린다. 레이아웃은 대리자 그대로다. 화면 밖 렌더(-O, 보이는 영역 420×300) 다시 그리기 1000줄 13.0→1.6ms, 3000줄 39.3→2.4ms, 스트리밍 조각(갱신+그리기) 3000줄 81→9ms.

### 한계

- 토크나이저는 파서가 아니다. 정규식 리터럴, 문자열 보간 안, heredoc, YAML 블록 스칼라는 보이는 대로 읽는다. HTML 안의 script·style 내용은 한 색이다(태그로 읽지 않을 뿐 JS·CSS로 칠하지 않는다).
- CSS의 `//` 줄 주석은 SCSS·Less 문법인데 CSS에도 적용된다. `url(http://…)`는 문자열로 따로 읽어서 깨지지 않는다.
- 숨긴 줄 안으로 끌어 선택하거나 Shift+화살표로 넘어가면 보이지 않는 글자까지 선택된다. 복사 내용은 맞다.
- 모두 선택하면 선택 색이 꼬리줄 자리까지 칠해진다. 머리줄과 카드 여백도 C1부터 같다.
- 지난 결과에서도 꼬리줄은 누를 수 있다. 표시만 바꾸고 글자는 내보내지 않는다.
- (PR #58 리뷰, 유지) C2는 문법 색과 접기를 기본으로 켜는데 끄는 화면(설정 '표시' 탭)은 C3에 있다. C3을 C2 바로 뒤에 머지하므로 기본값은 켠 채 둔다. 그 사이에는 `defaults write`로만 끄고, 언어 없는 펜스·```` ```text ````·```` ```markdown ````에 든 산문도 5줄을 넘으면 접힌다.
- (PR #58 리뷰, 유지) 한도 + 1줄 블록은 접으면 오히려 높아진다. 꼬리줄(30 + 위 간격)이 숨긴 코드 한 줄(21)보다 높아서다. Native 6줄 165→167, GitHub 6줄 187→196(7줄부터는 낮아진다). reconcile C8 'N = 보이는 줄 수'와 계획 5.2의 규칙이라 `lineCount >= limit + 2` 같은 예외를 두지 않았다. 바꾸려면 사용자 결정이 필요하다.
- (PR #58 리뷰, 유지) Native 접힌 블록의 마지막 보이는 줄(35% 흐림)은 대비가 1.6–2.2:1이고, GitHub 주석 #6E7781은 #F6F8FA 위 4.27:1이다. 흐림은 '더 있다'는 표시이고 pen-values '접힌 마지막 줄 #1D1D1F59(35%)', reconcile C8, Primer 주석 값이라 그대로 둔다. 토큰 대비 검사는 4절대로 3:1이다.
- (PR #58 리뷰, 측정) 긴 결과에서 설정을 켤 때 다시 칠하기: 숨긴 줄을 그리지 않게 된 뒤 3000줄 블록 하나에서 접기 켬 59ms, 접기+색 100ms, 색만 67ms(리뷰 때 130·278ms). 1000줄은 20·35·26ms. 남은 비용은 줄마다 한 번 읽어 칠하고 전체를 배치하는 것이라 그대로 둔다.
- (PR #58 리뷰, 측정) 꼬리줄 누름은 그 블록만 다시 칠하지만(5만 자, 30줄 블록 12개에서 칠하기 약 15→0.7ms), 블록 높이가 바뀌므로 TextKit 1이 그 뒤 글 전체를 다시 배치한다. 첫 블록 누름 약 80ms, 마지막 블록 1.3ms. 비연속 레이아웃은 결과 창의 독자 자리·높이 계산을 모두 바꿔야 해서 하지 않았다.

### 동작

- '코드 스타일 ›'을 누르면 탭이 왼쪽으로, 고르기 화면이 오른쪽에서 들어오고(0.2초) 창이 620×460으로 커진다. '‹ 표시'나 Esc로 돌아오면 340×376으로 돌아온다. '동작 줄이기'가 켜져 있으면 움직임 없이 바로 바뀐다.
- 창 크기: 왼쪽 위 모서리를 고정하고 화면의 `visibleFrame` 안에 둔다(`CodeStylePickerModel.settingsFrame`). 오른쪽·아래 끝에 걸리면 그만큼 밀고, 밀린 거리를 기억했다가 돌아올 때 되돌린다. 넓은 동안 사용자가 창을 옮겼으면 되돌리지 않고 옮긴 자리의 왼쪽 위를 지킨다. 화면이 더 작으면 화면만큼만 커진다.
  - 넓히는 0.2초 안에 돌아오면 지나가는 frame이 아니라 마지막 목표 frame으로 옮김 여부와 기준점을 정한다. 전에는 중간 frame을 옮긴 것으로 보아 밀린 거리를 잃었다(리뷰 F3).
  - 애니메이션 없이 바꿀 때(창을 닫을 때, 동작 줄이기)도 길이 0 애니메이션으로 한다. 그냥 `setFrame`은 진행 중인 애니메이션이 끝나며 덮어써서, 넓히는 중에 닫으면 620×460 창에 탭이 남았다(리뷰 F2).
- 호스팅 뷰는 `sizingOptions = []`다. 창 크기는 AppModel이 정하고 SwiftUI가 창 폭을 340에 묶지 않는다.
- Esc는 설정 화면 맨 바깥의 `.onExitCommand` 하나만 받는다. 고르기 화면이면 탭으로 돌아가고, 권한 팝오버가 열려 있으면 닫고, 아니면 설정 창을 닫는다(계획 검토의 '두 Esc 처리' 지적 반영). 순서는 `AppModel.escapeSettings(permissionsShown:)`가 정하고, 팝오버는 뷰가 가지므로 `.permissions`를 받으면 뷰가 닫는다.
