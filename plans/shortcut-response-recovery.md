# 단축키 무반응 해결과 즉각적인 번역 창 표시

작성일: 2026-09-19
상태: 2026-09-19 사용자 실행 승인. 무반응 원인을 확인해 고쳤다. 원인은 현재 앱에 입력 모니터링이 연결되지 않아 감시가 시작되지 않았는데 실패 안내가 숨은 창에만 있던 것, 그리고 개발 빌드의 cdhash 서명이다. 지금 동작(상태 창·메뉴 막대 감시 상태·호출 앱 변경 안내)은 아래 ‘확인한 현재 상태와 미확정 원인’ 절 첫 문단에 적었다. 아래 체크박스는 계획 당시 목록이며 갱신하지 않았다. 다중 모니터·Space 전환 확인, 실제 키보드 반복 호출·ESC 복귀·원래 위치 삽입 검증, 지원 앱 기록은 남아 있다. 실행 근거는 [Mac 연동 기록](mac-integration-checks.md)과 [실행 계획](remaining-work.md)을 따른다.

## 목표와 근거

사용자가 제공한 DeepL 영상처럼 다른 앱에서 글을 선택하고 Command를 누른 채 C를 두 번 누르면, 작업 위치 근처에 작은 번역 창이 나타나고 추가 조작 없이 번역한다. 결과를 기다리는 동안에도 호출이 접수됐는지 알 수 있어야 한다. 기존 Compact Stack 디자인을 유지하면서 호출·배치·상태 전환을 보완한다.

영상 확인: 약 1초 프레임에는 브라우저 텍스트 선택, 2초 프레임에는 선택 위치 근처의 로딩 창, 5초에는 로딩, 7초에는 번역 결과가 보인다. 이는 영상 내 시점이며 실제 키 입력 시각이나 DeepL의 정확한 응답 시간은 아니다. 키 입력 자체·닫기 후 포커스 복귀·바꾸기 성공은 영상에서 검증하지 못했다. 개인 화면이 포함된 원본 영상과 추출 프레임은 저장소나 PR에 올리지 않는다.

## 확인한 현재 상태와 미확정 원인

아래 목록은 2026-09-19 진단 시점의 기록이다. 현재 main에서는 두 번째 ⌘C 직후 `onWillCapture`가 클립보드 확인 전에 포인터 근처에 비활성 창을 띄워 ‘복사한 텍스트를 확인하는 중…’을 표시한다. 이미 같은 화면에 열린 창은 옮기지 않는다. 호출 앱이 바뀌면 ‘호출 중 앱이 바뀌었습니다. 원래 앱에서 다시 복사해 주세요’를 표시한다. 메뉴 막대 항목은 ‘⌘C 두 번 · 감지 중’, ‘단축키 감시 연결 안 됨’, ‘두 번 복사 꺼짐’ 같은 감시 상태를 보여 준다.

- 사용자는 실제 사용 시 아무 반응도 없다고 보고했다. 단축키 상수나 단위 테스트만으로 정상 동작이라고 판단하지 않는다.
- 확인 당시 deepK(PID 44733)와 DeepL(PID 51892)이 모두 실행 중이었다. 동시 실행은 확인했지만 충돌 원인으로 확정하지 않는다.
- 코드: 두 번 입력 간격 500ms, 두 번째 복사 후 클립보드 대기 최대 250ms, 확인 주기 10ms. Command를 유지하거나 놓았다 다시 누르는 방식을 지원한다.
- `DoubleCopyMonitor.start()`는 입력 모니터링 권한이 없으면 감시를 시작하지 않는다. `AppModel`은 이 실패를 feedback에 저장하지만, 시작 시 창은 숨겨져 있고 메뉴에도 준비 상태가 없어 사용자가 문제를 알아채기 어렵다.
- `AppModel.onCopiedText`는 호출 앱이 현재 맨 앞 앱과 다르면 안내 없이 반환한다. DeepL 등의 창이 먼저 활성화되는 경우도 진단 대상이다.
- 창은 클립보드 확인이 성공한 뒤 열리며, 최초 위치는 `center()`이다. 영상처럼 작업 위치 근처에 배치하지 않는다.
- 실제 실행 바이너리의 리비전, 앱 자체 권한, 이벤트 수신 여부, 실패한 단계는 아직 확인하지 못했다. 별도 진단 도구의 권한을 deepK 권한으로 대체해서 판단하지 않는다.

## 작업 순서와 완료 기준

### 1. 무반응 재현과 원인 분리

- [ ] 실제 사용하는 앱 경로·빌드 리비전·중복 실행 여부를 확인하고 검증할 빌드를 고정한다.
- [ ] deepK 자체에서 입력 모니터링 권한 → 이벤트 탭 생성/활성 → 첫 복사 → 두 번째 복사 → 클립보드 갱신 → 창 표시 → 요청 전송 단계의 성공/중단 원인을 확인한다.
- [ ] 진단은 시간·단계·실패 코드만 남긴다. 원문, 클립보드 내용, 인증 정보를 기록하지 않는다.
- [ ] DeepL 동시 실행과 단축키 비활성 상태를 구분해 비교한다. 사용자 승인 없이 DeepL을 종료하거나 설정을 바꾸지 않는다.
- [ ] 메인 액터 전달 지연, 클립보드 기준 changeCount 획득 시점, 포커스 변경에 따른 조기 종료, 이벤트 탭 비활성화를 재현 증거에 따라 수정한다. 원인을 확인하기 전에 시간 한도만 늘리지 않는다.

완료 기준: 실제 실패 단계와 재현 조건을 설명하고, 수정 후 같은 조건에서 단축키 호출이 접수됨을 확인한다.

### 2. 준비 상태와 복구 경로

- [ ] 메뉴 막대에서 단축키 준비/권한 필요/감시 실패와 ChatGPT 연결 상태를 구분해 확인할 수 있게 한다.
- [ ] 최초 설정이 필요한 경우 한 번 안내하고, 정상 준비 후에는 창 없이 조용히 상주한다. 반복 권한 팝업을 만들지 않는다.
- [ ] 권한 설정에서 돌아오거나 앱을 재실행했을 때 상태를 다시 확인하고 필요한 감시를 재설치한다. 재시작이 필요한 경우 명확히 안내한다.
- [ ] 감시 재시도·수동 열기·붙여넣기 경로를 제공한다. 권한이 없어 키를 수신하지 못하는 상태에서 단축키로 오류 창을 띄울 수 있다고 가정하지 않는다.
- [ ] 실행 경로·서명 변경으로 권한이 흔들리는지 확인하고 안정된 로컬 실행 방법을 정한다. 시스템 권한 DB를 직접 수정하거나 초기화하지 않는다.

완료 기준: 준비가 안 된 상태의 원인과 다음 행동을 메뉴/설정에서 확인할 수 있고, 권한 허용 후 정상 호출로 복구된다.

### 3. 단축키 직후 작은 창과 상태 표시

- [ ] Command를 누른 채 C를 두 번 누르면 한 번만 호출한다. 각 ⌘C를 따로 누르는 방식도 유지한다.
- [ ] 원래 앱과 작업 위치를 먼저 기록하고, 번역 완료를 기다리지 않고 창에 접수/읽는 중/연결 중/번역 중 상태를 표시한다.
- [ ] 창 표시가 두 번째 복사의 원래 앱 처리를 빼앗지 않게 한다. 클립보드 확인 중 비활성 패널로 표시하는 방식을 검토하고, 실제 복사 완료와 포커스 보존을 검증한다.
- [ ] 창은 호출 시 포인터가 있는 화면의 작업 위치 근처에 배치하고 화면 밖으로 나가지 않게 한다. 이미 열린 창이 같은 화면에 있으면 제자리에 둔다(2026-10-07). 선택 영역 좌표는 접근성 권한과 조회가 가능할 때만 활용하며, 번역 호출의 필수 조건으로 삼지 않는다. 다중 모니터·화면 가장자리·Space 전환도 확인한다.
- [ ] 확인된 새 텍스트만 번역한다. 실패 시 과거 클립보드를 보내지 않고 이유와 재시도 방법을 표시한다.
- [ ] 엔진 연결이 준비 중이면 최신 호출 하나만 기다리게 한다. 새 호출은 이전 대기/결과를 무효화한다.
- [ ] 키 호출에는 타이핑 디바운스를 적용하지 않는다. 편집에는 500ms 디바운스·IME 조합 보호·동일 요청 억제를 유지한다.
- [ ] ESC/닫기로 창을 숨기고 유효한 원래 앱으로 복귀한다. 앱은 계속 상주한다. 삽입은 명시적으로 요청했을 때만 수행한다.

완료 기준: 글 선택 → 단축키 → 작업 위치 근처 상태 창 → 자동 번역 → 복귀가 실제 앱에서 이어진다. 접수 표시 목표는 두 번째 C 수신부터 200ms 이내로 제안하며, 실측으로 달성 여부를 기록한다. 이는 번역 전체 완료 1초 목표와 별개다.

### 4. 실사용 검증과 번역 지연 개선

- [ ] Chrome 일반 페이지·textarea, TextEdit에서 실제 키보드로 검증한다. 단위 테스트와 합성 이벤트 검증은 보조 근거로만 쓴다.
- [ ] 각 앱에서 정상 호출 10회, 창 닫기 후 재호출, 앱 재실행 후 호출을 확인한다. 한 번 복사·길게 누르기·느린 두 번·같은 글 재복사·빠른 연속 호출·앱 전환·빈 값/이미지/파일 복사도 검사한다.
- [ ] 권한 없음, 연결 실패, 대상 앱 종료, 오래된 응답, 중복 삽입을 확인한다. 검증용 창은 명시적으로 실행하고 종료 시 정리한다.
- [ ] 호출부터 최초 상태 표시, 복사 확인, 모델 준비, 첫 출력, 최종 출력의 지연을 나눠 측정한다. 작은 창이 빨리 뜨는 것을 번역 속도 개선으로 보고하지 않는다.
- [ ] 현재 Terra/low/표준 계층 측정치를 비교 기준으로 보존하고, 사용자 선택에 따라 다음 기본 모델 Luna와 Claude Code의 Haiku 후보를 [제공자별 모델 계획](engine-candidates.md)에 맞춰 검증한다(2026-10-08 PR #48부터 Claude 기본은 Haiku 5.5이고 Haiku 4.5는 선택지에서 빠졌다. 비교는 [Haiku 4.5 ↔ 5.5](../benchmarks/haiku-45-vs-55-summary.md)). 최근 약 5.19초는 해결된 상태가 아니다. 단축키 수정은 Apple 번역 비교 결정 때문에 미루지 않는다.
- [ ] 안전한 예시 문장으로 실제 실행 영상을 남긴다. README와 기존 계획의 구현/검증 상태를 갱신한다.

완료 기준: 실제 키보드로 전체 경로와 실패 복구를 확인하고, 지원 앱·버전·반복 횟수·실패·지연을 기록한다. 원문 삽입은 편집 가능한 위치에서 별도로 검증한다. DeepL과 같은 속도를 입증하지 못했다면 동작 유사성과 속도 결과를 구분한다.

## PR와 goal 실행 범위

작은 PR 단위: (1) 진단·무반응 원인 수정·권한 복구, (2) 즉각적인 상태 창·위치·복귀, (3) 실사용 증거·성능 개선·문서 마무리. 진단 결과에 따라 묶음을 조정하되 무관한 리팩터링은 포함하지 않는다. 주석은 필요한 구현 이유만 한글로 작성한다.

기존 #13 통합과 #15 주석 정리의 최신 head/base를 확인하고 변경을 보존한다. 필요한 실제 검증을 마친 뒤 의존 순서대로 main에 병합하며 기존 미검증 항목을 완료로 덮지 않는다. 2026-09-19 후속 사용자 요청으로 이 계획과 제공자 선택 계획의 구현·검증 및 기존 goal의 PR 절차 실행이 승인됐다.

실행 요청 예시:

> plans/shortcut-response-recovery.md와 plans/remaining-work.md를 기준으로 기존 goal을 재개해줘. 먼저 ⌘를 누른 채 C를 두 번 눌러도 반응 없는 문제를 실제 deepK에서 재현·수정하고, DeepL 영상처럼 작업 위치 근처에 작은 상태 창이 먼저 나타난 뒤 자동 번역되게 해줘. 구독 방식은 유지하고 번역 속도 개선도 이어가줘. 작은 PR로 나누고 실제 검증 후 main에 병합해줘. 다른 앱 종료나 설정 변경이 필요하면 해당 변경만 확인받고, 미검증 동작과 미달 속도는 명시해줘.

## 실행 통합 순서

1. 현재 단축키 무반응의 실패 단계를 확인하고 권한 안내·감시 복구를 구현한다.
2. 복사를 방해하지 않는 작업 위치 근처 상태 창과 원래 앱 복귀를 연결한다.
3. Codex 기본 모델 Luna, Claude Code Haiku 어댑터, 제공자별 설정 저장과 실제 모델 표시를 연결한다. 양쪽 연결 시 저장된 사용자 선택을 사용한다.
4. 상태·통신·제공자 변경 회귀 검증과 실제 앱 검증, 구독 번역 지연/품질 비교를 수행한다. 실제 키보드 검증이 필요하면 구체적인 한 번의 동작을 요청하고 독립 구현은 계속 진행한다.
5. PR #13 → #15 및 후속 PR의 의존 관계를 확인하고 검증을 마친 순서대로 main에 반영한다. 미검증 경로를 완료로 표시하지 않는다.

현재 구현과 과거 실측은 본 계획의 사실 기록으로 유지한다. Apple 기기 내 번역 도입은 결정되지 않았으며 이번 실행의 선행 조건이 아니다. 모델 추가의 인증 경로가 공식적으로 지원되지 않거나 계정 접근이 불가능하면 해당 사유를 기록하고 Codex 및 단축키 작업은 계속한다.

## 실행 중 확인한 추가 원인

사용자가 접근성을 허용한 뒤에도 새 빌드에서 다시 권한 부족 안내가 나타났다. codesign 조회에서 기존 앱의 지정 요구사항이 cdhash 하나로 구성됨을 확인했다. 코드가 바뀌면 권한 식별도 달라지는 개발 빌드 문제다. 기존 Apple Development 인증서로 빌드 후 서명하고, 인증서 기반 식별과 재실행 권한 유지를 검증한다. 전환 시 macOS 설정의 기존 항목을 다시 연결해야 할 수 있으며, 권한 DB를 직접 수정하지 않는다.
