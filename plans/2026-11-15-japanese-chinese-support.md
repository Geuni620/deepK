# 일본어·중국어 번역 및 일본·대만 현지화 계획

작성: 2026-11-15. 상태: 검토용 계획. 구현·제공자 호출·앱 실행·배포 미실시.

## 1. 목표와 확인한 사실

한국어·영어에 일본어(`ja`), 대만 번체(`zh-Hant`, 출력 지역 `TW`), 간체(`zh-Hans`)를 원문과 대상으로 추가한다. 일본·대만 사용자가 선택 → ⌘C 두 번 → 자기 언어로 결과 확인 흐름을 사용할 수 있어야 한다.

- 사용자 관찰: 일본어 원문을 복사하면 “영어 또는 한국어 원문만 자동으로 감지할 수 있습니다.”가 표시됐다. 이번 조사에서 해당 GUI 동작을 재현하지 않았다.
- 현재 작업 트리 HEAD는 `31aa1c4`, origin은 private, public remote는 Geuni620/deepK다. 별도 공개 체크아웃 HEAD는 `2f09ff7`이며 아래 핵심 감지 함수가 같은 위치에 있다. 구현 기준은 승인 후 공개 저장소 최신 ref를 확인해 고정한다. 현재 작업 트리와 출시 바이너리가 동일하다고 가정하지 않는다.
- 이 트리에는 `docs/plans`가 없고 기존 설계는 `plans/`에 있다. String Catalog 파일은 찾지 못했다. 한국어·영어 문구가 Swift에 직접 들어 있다.
- `plans/engine-candidates.md`: Codex app-server와 Claude Code 구독 경로 유지, 자동 제공자 전환·유료 API 전환·동시 이중 요청 금지. 저장된 제공자·모델 선택 보존.
- `plans/runtime-output-check.md`: 한국어 결과의 한자를 Unihan 독음으로 치환하며 원문 반복은 최대 한 번 재요청한다. 형태소 분석기 패키지 도입은 현재 코드와 조사한 계획에서 확인되지 않았다. 형태소 분석 개선의 별도 합의가 없었다고 단정하지 않는다.
- `plans/incremental-translation.md`, `plans/public-release-security.md`의 캐시·취소·입력 보호 계약을 유지한다. 홈 디렉터리 기록은 파일명과 관련 계획만 제한적으로 조사했다. 모든 이전 대화를 전수 확인한 것은 아니다. 인증·키·환경 파일은 열지 않았다.

## 2. 현재 제한과 변경 설계

### 제한 위치

| 위치 | 확인한 제한 / 구현 작업 |
| --- | --- |
| `DeepK/Translation/TranslationStore.swift` | `TranslationLanguage`는 en/ko만, `TranslationDirection.fixedLanguages`는 auto/en-ko/ko-en만 정의. `detectedLanguage(in:)`는 인식 결과를 이 enum으로 변환하므로 ja/zh가 탈락한다. `resolveLanguages()`는 en→ko, ko→en만 반환한다. 상태 안내에도 두 언어 제한이 있다. |
| 같은 Store | `isConfidently(otherThan:_:)`는 다른 언어를 en/ko 중 하나로 계산한다. `tailMatchesLanguage`, `resolveLanguages`, 문서 복원·캐시·진행 요청 비교를 함께 확장한다. |
| `DeepK/Translation/TranslationView.swift` | 방향 Picker, 원문·대상 표시 및 방향 버튼이 한영 고정이다. |
| `DeepK/AppModel.swift` | 초기화와 `changeDirection`이 `translationDirection` raw value를 저장·복원한다. 기존 설정 마이그레이션이 필요하다. |
| 두 TranslationClient의 `translationPrompt` | source/target 문자열을 받아 지시한다. 언어 enum 확대와 함께 공통 언어 설명을 전달하고 대만식 용어를 명시한다. |
| `TranslationOutputLint`의 `foreignCharacters`, `letterCount`, `EchoProbe` | 문자·반복 판정이 한영 중심이다. ja/zh 문자 수와 공유 문자의 정상 보존을 고려한다. 기존 한영 길이 비율을 새 언어쌍에 복사하지 않는다. |
| `TranslationOutputCheck.init`, `HanjaRepair` | 현재 repair는 targetLanguage == ko일 때만 생성된다. 이 조건을 보존하고 ja/zh 출력에는 적용하지 않는다. |

### 언어·설정 계약

- 언어 식별자는 en/ko/ja/zh-Hant/zh-Hans로 유지한다. 대만 지역 표현은 `zh-Hant` 대상의 정책으로 명시한다. 사용자 표시는 “繁體中文（台灣）”. 감지된 문자 체계로 사용자의 거주 지역을 추정하지 않는다.
- 원문 선택은 자동 + 다섯 언어, 대상 선택은 다섯 언어로 분리한다. 기존 `TranslationRequest.sourceLanguage/targetLanguage` 계약은 유지한다. 감지 내부 결과만 확정 언어 / 중국어 체계 불명 / 불확실 상태를 표현하도록 확장한다.
- 설정에 “기본 대상 언어: 시스템 언어 따르기 / 다섯 언어”를 추가한다. 시스템 선호 언어 중 첫 지원 언어 사용, 지원 언어가 없으면 영어. zh-TW/zh-Hant는 대만 번체, zh-CN/zh-SG/zh-Hans는 간체, 지역·체계 없는 zh는 번체를 기본으로 하고 선택을 노출한다.
- 자동 모드에서는 원문이 기본 대상과 다르면 기본 대상으로, 같으면 영어로 번역한다. 기본 대상이 영어이고 원문도 영어면 요청하지 않고 대상 선택을 안내한다. 번체↔간체는 서로 다른 대상으로 허용한다.
- 번역 창에서 원문·대상을 바로 변경할 수 있다. 대상 수동 선택은 기본 설정을 덮어쓰지 않고 창 세션에 적용한다. 명시적으로 같은 언어를 고르면 요청 없이 안내한다.
- 기존 en-ko/ko-en 설정은 고정 원문·대상으로 마이그레이션하고 auto는 새 자동 정책으로 옮긴다. 새 설정 버전과 별도 키를 사용해 이전 앱의 값을 손상시키지 않는다.
- 대상 변경 시 진행 요청 취소와 세대 무효화, 증분 문서 무효화, 언어쌍·프롬프트 버전이 다른 캐시 재사용 금지를 적용한다. 이미 완료된 결과는 기존 제공자 변경 UX처럼 보존하고 다시 번역을 안내한다.

### 감지와 짧은·혼합 원문

- 로컬 `NLLanguageRecognizer`와 `languageHypotheses`를 사용한다. 코드 펜스·URL·식별자는 감지용 산문에서 제외하고 실제 번역 입력은 보존한다. 지원 언어만 강제해 무관한 언어를 오인시키지 않는다.
- 확정 기본 기준은 최상위 후보 0.8 이상 및 차순위와 0.2 이상 차이다. 이는 정확도 보장이 아닌 초기 정책이며 OS별 고정 샘플로 검증한다. 가나·번체/간체 특징 글자는 보조 근거로 사용하고 단일 문자만으로 확정하지 않는다.
- 가나가 있는 충분한 일본어 문장은 ja 후보를 우선 검토한다. 한자만 있는 일본어와 중국어는 억지로 구분하지 않는다. `中文`, `東京`, 숫자·이름만 있는 입력은 원문 선택을 안내한다. 인식 불확실 시 외부 모델로 판별 요청을 보내지 않는다.
- 중국어임은 확실하지만 문자 체계만 불명확하면 원문을 “중국어 · 표기 미확정”으로 표시한다. 번역 지시는 Chinese 원문으로 전달하며 대상 문자 체계를 따르게 한다. 확정되지 않은 source를 zh-Hant로 위장하지 않도록 요청용 감지 메타데이터를 추가한다.
- 일본어+영어 등은 산문의 우세 언어가 기준을 충족하면 전체를 대상 언어로 번역한다. 우세가 없으면 원문 수동 선택을 안내한다. UI 오류: “원문 언어를 확실히 감지하지 못했습니다. 원문 언어를 선택해 주세요.” 미지원 언어는 별도 안내한다.
- 독립 추가 구간의 언어가 확실히 달라지면 전체 번역으로 돌아간다. 짧은 구간의 모호한 판정 때문에 기존 결과와 다른 언어 결과를 결합하지 않는다.

## 3. 제공자·품질·보안

| 제공자 | 확인 수준과 계획 | 비용 |
| --- | --- | --- |
| Codex | 현재 어댑터는 source/target 문자열을 전달한다. ja/번체/간체의 정확한 모델별 번역 적합성과 대만 표현은 이번에 실호출하지 않아 미검증. 실제 계정에서 선택 가능한 모델로 평가한다. | 기존 구독 사용량. 언어별 고정 건당 요금으로 표현하지 않는다. |
| Claude Code | 공식 다국어 문서는 일본어·간체 평가와 대상 언어 명시를 안내한다. 이는 현재 CLI 모델의 번체·대만 번역 품질 보증이 아니다. 같은 샘플로 평가한다. | 기존 구독 사용량. 모델·문장 길이·재시도에 따라 소모가 달라진다. |

사용자가 결정한 정책은 기존 구독만 사용이다. API 키·추가 결제·자동 상위 모델 전환을 도입하지 않는다. 더 비싼 모델이 더 좋은 번역을 한다고 가정하지 않는다. 실제 모델명·CLI 버전·첫 결과/완료 지연·재시도 수를 함께 기록하고 원문은 운영 로그에 남기지 않는다.

- 프롬프트 공통 정책: Japanese / Traditional Chinese (Taiwan; Taiwanese vocabulary) / Simplified Chinese를 명시한다. 대만 출력의 예시는 軟體·資訊 등으로 검토하되 단어 치환만으로 품질을 판정하지 않는다.
- 한글 독음 치환은 한국어 대상에서만 유지한다. 일본·중국 고유명사와 인용 보존을 회귀 검증한다. 새 형태소 분석기를 이번 언어 지원의 선행 조건으로 도입하지 않는다. 향후 형태소 개선도 언어별 적용 범위를 분리한다.
- 번체↔간체와 한자 공유 문장은 원문과 같은 글자가 많아도 정상이다. 해당 쌍에는 기존 단순 원문 반복 자동 재요청을 끄고, ja/zh가 포함된 나머지 쌍은 문자 수·문장 판정을 확장해 검증한 뒤 활성화한다. 숫자·코드·고유명사의 정상 보존은 반복으로 보지 않는다.
- 민감 pasteboard 표시 차단, 환경 허용 목록, 도구·첨부·MCP 차단, 세션 비저장, 취소 처리 유지. UI 번역 과정에서도 CLI 설치·로그인·권한 상태를 혼동하지 않는다.
- 이미지 번역은 별도 POC 범위다. 이번에 OCR 언어·이미지 전송·화면 권한을 추가하지 않는다. 기존 이미지 유지 방식과 로컬 OCR/텍스트만 전송한다는 설계 경계를 보존한다.

## 4. UI·문서 현지화

- String Catalog로 사용자 노출 문자열을 모아 ko/en/ja/zh-Hant를 제공한다. 메뉴바 메뉴, 번역 창, 설정, 온보딩, 권한 안내·복구, 제공자 연결·한도·오류, 복사·삽입·재번역·접근성 레이블을 포함한다. 간체는 번역 기능부터 지원하고 간체 UI는 이번 범위에서 제외한다. 간체 OS의 UI fallback은 영어로 고정해 번체 사용자를 가장하지 않는다.
- 앱 UI 언어는 macOS 앱별 언어 설정을 따르며 번역 대상과 독립이다. 에러는 안정된 코드와 지역화된 설명으로 분리하고 CLI 원시 오류를 무조건 사용자 문구로 노출하지 않는다. 언어명을 문장에 붙여 만드는 대신 Catalog 보간을 사용한다.
- 일본어·대만 번체는 모국어 검토가 필요하다. 긴 문구, 작은 창, VoiceOver, 키보드 이동과 오류 줄바꿈을 실제 앱에서 확인한다.
- README 일본어·대만 번체 버전과 언어 이동 링크를 추가한다. 설치·구독 필요·개인정보 전송·권한·언어 오감지 교정·제한을 같은 수준으로 안내한다. 간체 README는 후속이며 기능 지원 표에는 간체를 포함한다.
- 랜딩은 소유 저장소와 배포 경로를 확인한 후 ja/zh-TW 문안을 별도 PR로 준비한다. 기존 KR↔EN 주장과 스크린샷을 갱신한다. Homebrew cask의 단일 영어 설명은 다국어 번역기로 수정하고, 언어별 설치 안내는 README/랜딩에서 제공한다. 이번 작업에서 외부 게시하지 않는다.

## 5. 검증·PR·릴리스

### 자동 검사와 실제 동작은 별도 증거

- 감지 고정 샘플: `英単語学習法と記憶成績の関係を調べる高校の探究研究「見る単」の公式アカウントです…`(사용자가 제공한 부분만), `このアプリで英語を勉強しています。`, `這個軟體可以翻譯日文，並保留段落格式。`, `这个软件可以翻译日文，并保留段落格式。`.
- 모호·혼합 샘플: `中文`, `東京`, `今日はAPIの設定を確認します。`, `這個 API 支援 JSON 回應。`, 한영 혼합, 가나 없는 일본어, 번체·간체 혼용, 코드만·숫자만·URL만·미지원 언어. 정답을 하나로 강제할 수 없는 입력은 모호 상태와 수동 교정 동작을 단언한다.
- 제공자 없는 단위 테스트: 설정 마이그레이션, 시스템 언어 매핑, 같은 언어 정책, 수동 선택, 언어쌍별 프롬프트, ja/zh 한자 무변형, 원문 반복 오탐, 캐시 분리, 대상 변경 중 늦은 응답 무시, 증분 언어 전환, 기존 한영·IME·코드·표·링크 보존.
- 승인 후 실제 제공자 평가: 두 제공자의 실제 선택 모델에서 ja/번체/간체→ko, ko/en→ja/번체/간체, 번체↔간체의 11개 방향에 각각 의미·부정/숫자·서식 표본 3개 이상. 누락·의미 반전·숫자 손상·문자 체계 오류는 출시 차단, 대만 표현은 모국어 검토 후 기록한다. 새 언어별 최소 한 건은 증분·스트리밍·취소까지 확인한다.
- 실제 macOS 앱: 배포와 같은 빌드에서 브라우저·TextEdit의 선택 → ⌘C 두 번 → 원문/대상 표시 → 결과 → 복사·삽입·원래 앱 복귀를 확인한다. 스크린샷 일본어 문장을 반드시 포함한다. 한국어·일본어·대만 언어 설정, 간체/영어 fallback, 권한 미충족, 제공자 미연결·한도·취소, 민감 표시 복사, 업그레이드 설정 보존도 확인한다.
- 자동 테스트 통과나 모의 번역 결과를 실제 키보드·제공자·GUI 성공 증거로 기록하지 않는다. 이번 계획 작성에서는 테스트나 앱 실행을 하지 않았다.

### 확정 사항과 남은 승인

- 확정: 번역 다섯 언어, 기본 대상은 사용자 언어, 같은 언어는 영어로 전환, 기존 구독만 사용.

- 구현 전 승인 대상: 위 기본값과 PR 범위·예상 작업량. 일본어·대만 문구/번역의 모국어 검토 담당은 출시 전에 확보한다. 담당자 미확보 상태에서는 검토 완료나 해당 지역 품질 보증을 주장하지 않는다.


## 2026-11-15 구현 후 기록

사용자 승인 후 공개 main `5f1b558`를 기준으로 로컬 구현했다. 코드·현지화·설정·언어 및 MCP 회귀 검사·실제 Codex/Claude 표본 결과와 검토 자료는 [검증 기록](../docs/evidence/ja-zh-support/validation.md)에 정리했다. 커밋·푸시·릴리스·배포를 수행하지 않았다.

실측으로 조정한 사항:

- 기존 en/ko의 짧은 입력 감지는 보존하고 ja/zh에 엄격한 가설 기준을 적용했다. 중국어 산문에서 API/JSON 약어가 인식기를 지배하는 표본은 감지용 문자열에서만 약어를 뺀다.
- Claude의 ja→ko가 일본어로 반환된 표본을 확인해 대상 이름을 `Korean (한국어)`로 명확히 했다. 같은 표본의 최종 앱 성공을 확인했고 캐시 컨텍스트를 languages-v3로 분리했다.
- 삭제된 MCP 이름을 연결 캐시에서 가져와 transport 없는 override를 만드는 Paper 오류를 별도로 복구·수정했다. 기존 배포 앱은 원문을 유지한 연결 재설정으로 실제 번역이 복구됐으며, 소스 패치는 그 앱에 배포하지 않았다.
- 이미지의 기존 한영 방향 메뉴를 유지해 텍스트의 다섯 언어 대상 선택과 혼동하지 않게 했다.
- UI 번역은 모국어 검토 전 초안이다. 실제 ⌘C 두 번·삽입은 개발 앱 OS 권한이 연결되지 않아 미검증이고, 영상은 직접 입력한 실제 앱 번역을 보여 준다.
