## goal 실행 범위와 진행 방식

목표는 0–5단계의 Mac 로컬 앱 구현·실제 번역·두 번 복사 호출·복귀·명시적 삽입 검증이다. iPhone은 후속 검토까지만 포함하며 구현, 공개 배포, 자동 업데이트는 제외한다.

0단계 이후 모델 검증과 단축키·클립보드 실험을 진행한다. 모델 선정 전에도 Compact Stack 화면, 상태 처리, Mac 연동의 독립 작업을 진행할 수 있다. 모의 응답은 개발용으로 명확히 구분하고 실제 번역 완료로 기록하지 않는다. 프로젝트는 0단계에서 한 번만 생성한다.

- 구현자가 정하고 기록할 항목: 최소 OS, 앱 식별자, 디렉토리, 입력 판정 간격, 클립보드 대기 한도, 지원 앱의 초기 검증 목록. 일상적인 선택으로 매번 진행을 중단하지 않는다.
- 인증 경로는 사용자가 선택한 ChatGPT 구독 로그인 + 로컬 Codex app-server로 확정했다. 공식 관리형 로그인을 사용하고 토큰을 직접 추출하지 않는다. 별도 유료 API로 자동 전환하지 않는다. 현재 Codex 로그인과 모델 목록 조회를 확인했으며 실제 번역 연결·속도는 별도 검증한다.
- 본 측정 전 표본·분량·품질 기준을 구체화한다. 현재 p95와 반복 횟수는 제안값이며 확정된 사용자 요구로 표현하지 않는다. 사용자 검토가 필요한 대표 번역은 함께 제시한다.
- PR 생성·푸시·머지는 goal 실행 요청과 기존 대화에서 승인된 범위를 따른다. 목표 준비 문서 자체를 원격 게시나 자동 머지 승인으로 해석하지 않는다.
- 각 단계의 구현·검증 후 체크박스와 실행 기록을 갱신한다. 실제 앱 간 동작, 성능, 인증을 확인하지 못하면 그 부분은 미완료로 남긴다. 사용자 후속 결정에 따라 1초는 미달한 개선 목표로 기록하며 현재 앱 완성의 필수 합격선으로 요구하지 않는다. 실측 지연을 숨기지 않는다.

실행 요청 예시(사용자가 이 요청을 보내면 게시·머지 범위도 명확해진다):

> plans/remaining-work.md를 기준으로 Mac 앱 완성을 goal로 실행해줘. 연결된 두 상세 계획을 따르고 기존 작업을 보존해줘. 목적별 브랜치·작은 PR로 커밋과 게시를 진행하고 검증 및 저장소 조건을 충족한 PR은 main으로 머지해줘. 실제 실행 스크린샷과 쉬운 설명을 포함해줘. 계정·인증·비용 결정이 필요하면 구체적인 후보를 제시하고, 기다리는 동안 독립 작업을 계속해줘. 실제 검증하지 못한 기능이나 1초 목표는 달성했다고 하지 마.

## 목표와 우선순위

개인용 Mac 번역 앱에서 텍스트를 선택하고 ⌘C를 두 번 연속 누르면, 복사한 원문을 작은 창에 표시하고 추가 클릭이나 Enter 없이 AI 번역을 시작한다. 번역을 읽은 뒤 원래 작업으로 돌아간다. 편집 가능한 위치에는 사용자 동작으로 번역을 삽입한다. 이후 iPhone 사용을 검토한다.

1. 최소 번역 품질을 통과한 후보 중 전체 완료가 가장 빠른 모델을 선택한다. 두 번째 ⌘C 감지부터 번역문 전체 표시까지 대체로 1초 이내는 개선 목표로 유지하되 사용자 확인에 따라 현재 미달 상태에서도 구독 기반 앱을 완성한다.
2. 한국어 ↔ 영어의 일상 문장과 기술 문서를 이해하고 쓰기에 충분한 품질.
3. 작은 창, 키보드 조작, 포커스 복원 등 자연스러운 네이티브 UI/UX.
4. 사용자 후속 결정에 따라 ChatGPT 구독 로그인 경로를 사용한다. 이 경로에서 사용 가능한 모델 중 품질을 통과한 최속 모델을 찾고, 1초 미달이면 그대로 보고한다.

## 현재 상태와 결정 범위

- 전환·기반·구독 통신·Mac 구성요소 PR #4–#12를 main에 머지했다. 화면 연결 PR #13도 2026-09-20에 머지했고, 이후 머지 범위는 맨 위 상태 줄을 따른다.
- Swift + SwiftUI/AppKit 기반 Mac 앱이며 최소 macOS 15, Swift 6, 앱 식별자 com.deepk.app으로 시작한다.
- 번역 연결은 ChatGPT로 로그인한 Codex app-server를 사용한다. 새 설치의 기본 모델은 사용자 요청에 따른 gpt-5.6-luna이며 설정에서 다른 가용 모델을 선택할 수 있다. Claude Code는 Haiku 5.5(기본)·Sonnet 5.5·Opus 5.5·Fable 5.1 중에서 고르며, 선택지에 없는 저장값(예: Haiku 4.5)은 기본값으로 돌아간다(PR #48). 이전 Terra 파일럿 기록은 비교 근거로 남긴다. Apple 온디바이스나 별도 유료 API는 현재 구현 경로가 아니다.
- “대체로”의 수치화로 p95 ≤ 1,000ms를 제안한다. 이는 사용자가 지정한 백분위가 아닌 초기 검증 기준이며, 대상 분량과 함께 확정한다.
- 제공자별 구독 연결 범위와 한도를 확인한다. 구독 로그인을 범용 API나 무제한 사용으로 가정하지 않는다.
- iPhone은 별도의 사용 흐름과 엔진 연결 방식을 검토한다. Mac의 로컬 실행 도구를 그대로 사용할 수 있다고 가정하지 않는다.

이전 Electron 전용 계획은 [기록](archive/2026-09-12-electron-plan.md)으로 보존했다. 그 문서의 Electron 유지, Swift 제외, 고정 400ms 디바운스는 현재 실행 기준이 아니다.

## 사용자 피드백 반영 — 요청 제어와 백그라운드 동작

- 기존 150ms 입력 대기를 500ms로 늘리고 동일한 편집 알림과 동일 원문의 진행 중/완료 요청을 중복 전송하지 않는다. IME 확정, 오류 재시도, 모델 변경은 필요한 요청을 유지한다.
- 앱은 창을 만들기 전에 메뉴 막대·단축키·Codex 연결만 준비한다. 실제 번역 창은 호출할 때 생성한다. 시작만으로 원문을 전송하지 않는다.
- 표준 서비스 계층과 지원되는 최소 추론 강도를 사용한다. 현재 번역 모델은 gpt-5.6-terra, 추론은 low이며 Claude를 사용하지 않는다(2026-09-19 당시 기록이다. 지금 기본은 Codex gpt-5.6-luna·Claude Haiku 5.5이며, Codex 계층은 기본 일반이고 설정의 ‘Codex 빠른 응답(Fast)’으로 켠다 — PR #44·#48). 개발용 Luna Max와 구분한다.
- 모델 목록의 반복 조회 비용을 줄이되 매 번역의 ChatGPT 인증 방식 확인과 도구 차단은 유지한다. 서버/모델 응답 시간이 여전히 지연의 큰 부분이므로 준비 비용 감소만으로 전체 속도 달성을 주장하지 않는다.
- 검증 창이 사용자 화면에 남았던 문제를 수정한다. GUI 검증은 명시적 환경 변수로만 실행하고 테스트 프로세스는 실행기 종료·창 닫기·제한 시간에 종료한다. 일반 테스트는 창을 띄우지 않는다.

확인 결과: 수정 후 실제 앱은 accessory 정책으로 실행 중이며 시작 시 표시된 일반 창이 0개였다. 명시적 재호출에서 420×292 창이 생성됐다. 일반 테스트·빌드는 통과했고, 테스트 입력의 중복 요청/IME/모델 변경과 캐시 무효화를 가짜 제공자 호출 수로 검증했다. 새 문장 한 건의 입력부터 화면 결과까지는 약 5.19초로, 새 문장 자체의 속도 개선은 아직 입증하지 못했다. 기기 내 번역 비교 여부는 사용자 답변을 기다린다.

검증 도구 정리: 남아 있던 native-host와 격리 Chrome 프로세스를 종료했다. Safari는 첫 정리 시도에서 시간 초과가 있었으나, 재확인에서 해당 로컬 검증 주소 탭 1개를 닫았다. 이 창·페이지는 제품의 오류 화면이 아니며 이후 자동 GUI 검증을 실행하지 않는다.
