# deepK 남은 작업 실행 계획

> 보관 문서 — 2026-09-19 Swift 전환으로 대체된 Electron 계획입니다. 아래의 상태·체크리스트·실행 요청문은 당시 기록이며 현재 작업 지시가 아닙니다. 현재 실행 기준은 [전체 계획](../remaining-work.md), [번역 속도 검증](../translation-benchmark.md), [두 번 복사 자동 번역](../double-copy-translation.md)입니다.

작성일: 2026-09-12
상태: 계획만 작성. 제품 코드 구현 및 goal 시작은 후속 요청에서 진행한다.

## 목표

macOS에서 문단을 선택하고 전역 단축키를 누르면 작은 Float 창에서 번역을 읽을 수 있다. 닫으면 원래 앱으로 돌아가며, 편집 가능한 위치에서 호출한 경우 번역을 명시적으로 삽입할 수 있다. 앱은 창을 닫아도 메뉴 막대에 남는다.

기존 React/TypeScript/Electron 및 CSS Modules UI를 유지한다. 핵심 범위는 영어 읽기 → 한국어 이해와 한국어 작성 → 영어 사용이다.

## 현재 상태와 근거

현재 작업 트리에는 아직 커밋하지 않은 UI 변경이 있다. 실행 시 이를 기준 구현으로 보존하며, 이전 커밋이나 과거 실행 기록으로 덮어쓰지 않는다.

| 영역 | 현재 확인한 구현 | 남은 작업 |
| --- | --- | --- |
| Float UI | `src/renderer/src/App.tsx`, 개별 컴포넌트 및 hooks | 실제 상태 연결, 긴 문단/키보드 검증 |
| 번역 | `useTranslation.ts`에서 고정 예시만 반환 | 실제 엔진, 자동 요청, 취소, 최신 결과 보장 |
| 설정 | `ConnectionSettings.tsx`의 안내와 예시 실행 | 연결 설정, 확인, 저장/삭제, 언어 설정 유지 |
| 데스크톱 | `desktop-ipc.ts`의 닫기/최소화/확대/복사 | 상주, 전역 호출, 선택 영역, 복귀, 삽입 |
| 창 수명 | `index.ts`에서 BrowserWindow 생성, 닫기 시 파괴 | 창 숨기기/재사용 및 명시적 종료 구분 |
| 배포 | 기본 electron-builder 템플릿 | macOS 앱 식별자, 권한/리소스, 로컬 패키지 확인 |

`use-case.md`를 제품 요구사항의 기준으로 삼는다. 문서의 760 × 620 설명과 `window-config.ts`의 실제 560 × 520 설정은 다르므로, 현재 창 크기를 기준으로 문서를 정정한다. 디자인을 임의로 확대하지 않는다.

## 실행 전 결정과 기본값

- **번역 엔진은 미정이다.** 제공자/실행 방식, 모델이 필요한 경우 모델, 인증 방식은 사용자 선택을 받는다. 임의로 유료 서비스를 선택하거나 다른 앱의 로그인 자격 증명을 가져오지 않는다.
- 엔진 선택이 없어도 요청 계약, 상태 처리, 테스트용 어댑터, 데스크톱 통합은 진행할 수 있다. 실제 연결 확인은 미완료로 남기며, 테스트용 번역을 실서비스 결과로 표시하지 않는다.
- 첫 실행의 언어 기본값은 원문 자동 감지, 결과 한국어로 한다. 이후 사용자가 선택한 언어를 유지한다. 한국어 → 영어는 명시적 언어 변경으로 지원한다. 감지 후 임의로 설정을 변경하지 않는다.
- 전역 호출 기본 단축키는 `CommandOrControl+Shift+Space`로 한다. 충돌 시 등록 실패와 설정 변경 경로를 제공한다.
- 읽기 흐름을 먼저 완성한다. 삽입은 사용자가 버튼을 눌렀을 때만 수행한다.
- 1차 완료 범위는 macOS 로컬 사용 및 로컬 패키지다. Windows/Linux 통합, 공개 배포, 서명/공증, 자동 업데이트, 번역 기록, 전체 Swift 재작성은 이번 범위에서 제외한다.

## 1. 번역 계약과 연결 설정

대상: `src/main/translation/` 신규 모듈, 공유 타입, `desktop-ipc.ts`, preload, `ConnectionSettings`.

- [ ] main에 번역 제공자 어댑터를 만들고, UI와 제공자별 호출 형식을 분리한다. 최초에는 선택된 제공자 하나만 구현한다.
- [ ] 요청에 요청 ID, 원문, 원문/대상 언어를 포함한다. 응답에는 같은 ID, 결과, 가능한 경우 감지 언어를 담는다.
- [ ] 인증 실패, 네트워크 실패, 제한 초과, 타임아웃, 취소를 구분하고 재시도 가능한 오류만 재시도 경로를 제공한다.
- [ ] 엔진 호출과 인증 정보 처리는 main에서 수행한다. renderer에는 제한된 설정/번역 API를 노출하고 IPC 발신자와 입력 값을 검증한다.
- [ ] 선택한 인증 방식에 맞게 자격 증명 저장/삭제를 구현한다. 키를 쓰는 방식이면 OS 보호 저장소를 검토하고 평문 저장이나 로그 출력을 피한다.
- [ ] 설정 화면에서 필요한 값 입력, 연결 확인, 저장, 수정, 삭제 및 실패 상태를 제공한다. 연결 확인은 명시적 동작으로 한다.
- [ ] 제공자 구현 시 공식 문서에서 지원 언어, 요청 제한, 인증 방식과 응답 형식을 확인한다. 지원하지 않는 UI 언어는 선택할 수 없게 한다.

완료 기준: 설정이 없을 때 외부 요청이 없고, 선택한 엔진으로 한국어/영어 문장 번역이 동작한다. 잘못된 인증과 연결 실패가 구분되며 재시작 후 설정이 유지된다.

## 2. 자동 번역과 결과 일관성

대상: `useTranslation.ts`, `useFloatWorkspace.ts`, `SourceInput`, `TranslationResult`, `StatusBar`, `QuickActions`.

- [ ] `empty / disconnected / waiting / translating / success / error` 상태와 예시 모드를 분리한다.
- [ ] 입력 후 약 400ms를 초기 디바운스 값으로 사용한다. 한글 IME 조합 중에는 요청하지 않고 조합 종료 후 예약한다. Enter는 계속 줄바꿈이다.
- [ ] 원문이나 언어가 바뀌면 이전 요청을 취소하고, 취소가 늦거나 불가능해도 요청 ID와 입력 버전으로 오래된 응답을 무시한다.
- [ ] 결과를 요청 당시 원문/언어와 묶는다. 수정, 지우기, 새 선택 영역 수신 즉시 이전 결과의 복사/삽입을 비활성화한다.
- [ ] 빈 문자열/공백은 요청하지 않는다. 엔진 입력 제한을 넘으면 요청 전에 설명한다.
- [ ] 로딩, 오류, 명시적 재시도, 복사 성공/실패를 연결한다. 늦게 끝난 복사 작업의 안내가 새 원문 상태에 남지 않도록 버전도 확인한다.
- [ ] 예시 미리보기는 실제 번역 요청을 만들지 않는다. 실제 입력이나 언어 변경으로 예시를 벗어난다.
- [ ] 언어 선택을 저장하고 복구한다. 같은 언어 선택과 자동 감지 결과가 대상 언어와 같은 경우의 표시 규칙을 명확히 한다.

완료 기준: A 입력 후 B로 수정했을 때 A 응답이 늦게 도착해도 B 화면을 덮지 않는다. 한글 조합 중 요청이 발생하지 않고 오래된 결과는 어떤 복사/삽입 경로에서도 사용할 수 없다.

## 3. 메뉴 막대 상주와 전역 호출

대상: `src/main/index.ts`, 신규 창/트레이/단축키 관리 모듈, `desktop-ipc.ts`, `useDesktopShortcuts.ts`.

- [ ] 창 인스턴스를 관리하고 닫기/ESC는 숨기기로 처리한다. 트레이 메뉴의 열기/종료와 앱 종료는 별도 경로로 둔다.
- [ ] Tray 참조를 유지하고 macOS 메뉴 막대에 맞는 아이콘을 사용한다. 단일 인스턴스를 보장하고 재실행하면 기존 앱을 연다.
- [ ] 전역 단축키를 등록하고 종료 시 해제한다. 최소화/숨김 상태에서 호출하면 같은 창을 복원한다.
- [ ] 등록 실패를 확인하고 앱 안에서 단축키를 변경할 수 있게 한다. 저장한 단축키를 재시작 후 복구한다.
- [ ] 설정 dialog와 IME 조합 중 ESC 처리가 창 숨기기와 충돌하지 않게 한다.
- [ ] 트레이에서 열기와 외부 앱에서 선택 영역 번역 호출을 구분한다. 외부 호출 정보를 트레이 호출에 재사용하지 않는다.

완료 기준: 닫기 → 재호출을 반복해도 창/리스너가 늘지 않고 상태가 유지된다. 종료하면 프로세스와 단축키가 정리된다. 단축키 충돌 상태에서도 트레이로 앱을 열 수 있다.

## 4. 선택 영역 가져오기와 포커스 복원

대상: `src/main/desktop/` 신규 macOS 통합 모듈, 호출 세션 계약, preload 이벤트, `useFloatWorkspace.ts`.

- [ ] 창을 앞으로 가져오기 전에 원래 앱/창/포커스 정보를 호출 세션으로 기록한다.
- [ ] macOS 접근성 API로 선택 텍스트를 읽는 방식을 먼저 작은 프로토타입으로 검증한다. Electron에서 필요한 부분만 네이티브 helper로 분리할 수 있다.
- [ ] 접근성 권한 상태와 요청/설정 안내를 구현한다. 권한이 없으면 직접 붙여넣기로 계속 사용할 수 있게 한다.
- [ ] 접근성으로 읽을 수 없는 앱에서 복사 단축키 보조 방식을 사용할지는 실제 결과로 판단한다. 사용할 경우 기존 클립보드를 새 선택으로 오인하지 않고, 처리 중 사용자 클립보드 변경을 덮어쓰지 않게 한다.
- [ ] 새 호출 세션으로 가져온 원문을 전달하고 이전 결과를 즉시 무효화한다. 빠른 연속 호출의 오래된 선택 읽기 결과도 무시한다.
- [ ] 선택 없음/읽기 실패를 빈 성공으로 취급하지 않는다. 과거 원문을 이번에 가져온 것처럼 표시하지 않고 입력 대기와 안내를 제공한다.
- [ ] 닫기/ESC는 유효한 호출 세션의 원래 앱으로 복귀한다. 대상 앱이 종료됐거나 세션이 없으면 잘못된 앱을 활성화하지 않는다.

완료 기준: 브라우저의 서로 다른 문단을 연속 호출하면 해당 원문과 결과가 갱신된다. ESC 후 원래 문서로 돌아간다. 권한 거부, 선택 없음, 대상 앱 종료에서도 수동 입력이 동작한다.

## 5. 원래 위치에 삽입

대상: macOS 통합 모듈, `QuickActions`, 호출 세션 및 결과 유효성 검사.

- [ ] 원래 앱의 편집 가능한 대상과 선택 영역/커서 정보를 확보할 수 있는지 확인한다. 브라우저 일반 문단이나 읽기 전용 영역은 삽입 대상으로 취급하지 않는다.
- [ ] 현재 결과와 호출 세션이 유효하고 대상이 편집 가능할 때만 버튼을 활성화한다. main에서도 다시 검증한다.
- [ ] 삽입 클릭 → 대상 재검증 → 원래 앱 활성화 → 대상에 결과 전달 순서로 구현한다. 다른 입력 위치로 이동했거나 대상을 확인할 수 없으면 자동 삽입을 중단하고 복사를 제공한다.
- [ ] 직접 접근성 삽입 또는 붙여넣기 중 실제 지원 범위에 맞는 방식을 선택한다. 붙여넣기 방식은 클립보드 보존과 사용자 변경 감지를 포함한다.
- [ ] 중복 클릭을 막고 실패 시 재시도/복사 경로를 제공한다. OS가 입력 이벤트를 수락한 것과 실제 내용이 바뀐 것을 구분해 확인 가능한 수준으로 상태를 표시한다.

완료 기준: 지원하는 편집기와 브라우저 입력창에서 선택 문장이 한 번만 치환된다. 대상 변경, 권한 거부, 오래된 결과에서는 다른 위치에 입력하지 않는다. 지원하지 않는 앱에서는 복사로 진행할 수 있다.

## 6. 통합 검증과 로컬 앱 마무리

- [ ] 요청 순서 역전, 취소 후 응답, IME, 입력/언어 변경, 결과 무효화에 대한 동작 테스트를 추가한다.
- [ ] IPC 입력/발신자 검증, 단축키 등록 실패, 호출 세션 만료/교체, 삽입 중복 방지 등 실패 경로를 테스트한다. native 동작은 mock 테스트만으로 완료 판정하지 않는다.
- [ ] 브라우저 문서 읽기, 브라우저 textarea 작성, 일반 텍스트 편집기에서 실제 앱 사이의 흐름을 검증하고 앱/버전과 지원 여부를 기록한다.
- [ ] 긴 원문/결과의 독립 스크롤, 최소 크기, 확대/복원, 키보드 접근과 설정 닫기 후 포커스를 점검한다.
- [ ] `pnpm typecheck`, `pnpm exec eslint .`, `pnpm build`와 추가한 테스트를 통과시킨다.
- [ ] 앱 이름/식별자/아이콘과 실제 사용하는 권한 설명을 정리한다. 기본 템플릿의 불필요한 권한 설명과 예시 업데이트 주소를 정리한다.
- [ ] native helper가 있다면 패키지 포함/실행 경로를 확인한다. macOS 로컬 패키지에서도 상주/호출/번역/복귀/삽입을 확인한다.
- [ ] README에 설정, 개발/빌드, 권한, 단축키, 지원 앱과 제한을 기록한다. `use-case.md`를 실제 구현 상태에 맞춘다.

완료 기준: 실제 번역 연결과 앱 사이의 핵심 흐름을 개발 모드 및 로컬 패키지에서 확인한다. 권한/인증 등 환경 제약으로 실행하지 못한 검증은 사유와 남은 절차를 남기며 통과로 표시하지 않는다.

## 실행 순서와 완료 관리

1 → 2 → 3 → 4 → 5 → 6 순서로 진행한다. 엔진 결정/인증을 기다리는 동안 1의 계약 및 2의 테스트용 구현과 3–5를 진행한다. 이후 실제 어댑터를 연결하고 6을 수행한다.

각 단계가 끝날 때 이 문서의 체크박스를 갱신하고 아래 실행 기록에 변경 요약, 검증 명령/결과, 미검증 항목을 추가한다. 체크박스는 구현과 해당 검증을 마친 경우에만 완료한다. 사용자 입력이나 macOS 권한이 필요한 경우 독립 작업을 먼저 계속하고 필요한 항목을 구체적으로 요청한다.

전체 완료는 실제 엔진 연결, 읽기 흐름, 지원 앱에서의 삽입, 로컬 패키지 검증까지 충족했을 때만 판정한다. 예시/모의 응답과 타입 검사만으로 완료하지 않는다.
