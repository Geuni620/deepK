# 번역 결과 구조 유지: 목록·코드 블록·인라인 코드·링크

상태: 2026-10-12 1단계(PR #49, 회귀 수정 #50)와 2단계(PR #53)를 main에 머지했다. 2026-10-13–14 3단계 복사한 코드 블록(#56)과 코드 표시 S6′의 스타일 값·렌더러(#57), 문법 색·긴 코드 접기(#58), 설정의 ‘표시’ 탭과 고르기 화면(#59), 명시 경계 뒤 추가 번역(#65)을 main에 머지했다. 실제 앱에서 확인하지 않은 항목은 5절에 남긴다.

2026-10-17 추가 요구: 웹에서 복사한 목록의 글머리표·번호·항목 구분·들여쓰기를 원문과 번역 결과에 유지한다. 아래 5단계의 구현과 오프라인 검증을 완료했다. 실제 브라우저 복사·전체 앱 연동은 별도 확인이 남는다.

## 1. 문제와 목표

번역 결과가 모두 16pt 일반 텍스트로 보여 원문의 구조가 사라졌다.

- 원문에 코드가 섞여도 산문과 구분되지 않았다. 모델이 가끔 남기는 짝 없는 ```` ``` ````가 화면·복사·삽입에 그대로 섞였다.
- Chrome에서 복사한 원문의 인라인 코드(`read`, `write` …)와 링크가 결과에서 평범한 글자가 되고, 링크를 눌러도 열리지 않았다.
- 웹의 목록을 복사했는데 원문 창부터 글머리표가 빠지고, 번역 결과에서도 항목들이 일반 문단처럼 이어진다(2026-10-17 사용자 첨부 화면). 각 항목의 제목과 설명을 묶고 목록이라는 구분을 유지해야 한다.

목표는 Notion처럼 결과 창이 원문 구조를 유지하는 것이다. 코드 블록은 회색 박스·고정폭 글꼴·언어 라벨, 인라인 코드는 회색 칩, 링크는 번역된 글자를 누르면 원래 주소가 열린다.

## 2. 결정

- 두 단계 PR로 나눈다. 1단계는 코드 블록과 복사 형식, 2단계는 클립보드 HTML의 링크와 인라인 코드다.
- 원문 창은 일반 텍스트로 둔다. 중복 판정·입력 한도·언어 감지도 일반 텍스트를 쓴다.
- 코드 위치는 모델이 언어 태그를 붙인 펜스로 표시하게 해서 판별한다. 코드 안 주석은 번역하고 로그·오류 메시지는 문장으로 번역한다.
- 결과 창에는 펜스·백틱·링크 태그를 뺀 화면 텍스트만 넣고, 박스·칩·밑줄은 범위로 그린다. 받는 중에는 기호가 될 수 있는 꼬리를 잠깐 보류해 화면이 뒤에만 붙게 한다. 그래서 선택과 스크롤이 유지된다.
- 링크 글자는 번역하고 링크는 유지한다. 모델에는 번호 태그 `<aN>…</aN>`만 보내고 URL은 앱이 보관한다. 인라인 코드는 백틱으로 보낸다. 구조가 없는 요청의 프롬프트는 바이트 단위로 이전과 같다(골든 테스트).
- 링크는 클릭하면 바로 연다. 열기 전에 다시 검증하며 `http`·`https`·`mailto`만 연다. 이전 결과(흐린 글자)의 링크는 열지 않는다.
- 복사 형식은 설정의 번역 탭 '복사 형식'(`resultCopyFormat`)에서 고른다.
  - 서식 포함(기본): 코드·링크가 있으면 HTML·RTF와 URL 없는 일반 텍스트를 함께 쓴다.
  - 마크다운만: ```` ``` ```` 펜스와 `[글자](url)`을 쓴다.
  - 삽입은 URL 없이 글자만 넣는다. 원문에 펜스가 없었다면 일반 텍스트와 삽입에서 펜스 줄을 뺀다.

| 버린 대안 | 이유 |
| --- | --- |
| `NSTextBlock`으로 코드 박스 그리기 | `lineSpacing`과 함께 쓰면 무시된다. padding은 들여쓰기·문단 간격으로 만들고 박스는 뷰에서 그린다(#49) |
| `~~~`도 펜스로 인정 | 구분선으로 쓰는 경우가 있다(#49) |
| 등록된 언어 태그만 태그로 인정 | 목록 밖 실제 태그(`console`, `nginx` 등, 확인한 102개 중 94개)가 코드 첫 줄로 보였다(#50) |

## 3. 단계

### 1단계: 코드 블록과 복사 형식 (PR #49 2026-10-08, PR #50 2026-10-09)

- `TranslationMarkup`이 펜스를 판정하고 `TranslationResultTextView`가 둥근 회색 박스·고정폭 13pt·언어 라벨로 그린다.
- 펜스 이름: 등록된 언어 태그는 태그, 자주 쓰는 단독 명령 22개(`pwd`, `ls`, `cd` …)는 코드 첫 줄이다. 그 밖의 단독 이름은 다음 줄로 정한다. 코드 줄이 이어지면 태그, 바로 닫히거나 첫 코드 줄에서 채팅식으로 닫히면 코드다.
- 완료 시 정규화(`TranslationStore.complete`): 남은 펜스와 빈 블록을 지우고 닫히지 않은 태그 펜스를 닫는다. 원문 선택이 펜스 안에서 끝났거나 원문에 남은 펜스가 있으면 그대로 둔다.
- 코드 표본: `benchmarks/codeblock-samples.json`(`BENCHMARK_SAMPLES_PATH`로 Claude 벤치마크에 지정).

### 2단계: 링크와 인라인 코드 (PR #53, 2026-10-12)

- `RichSourceImporter`가 [웹 수식 복사 정리](web-math-copy.md)와 같은 `public.html`(Chromium 복사, 512KB 이하)에서 `<a href>`와 `<code>`를 찾아 일반 텍스트 위에 투영한다. 맞지 않는 범위는 버리고 일반 텍스트로 처리한다. 수식 정리로 글자가 바뀐 복사에는 구조를 붙이지 않는다.
- 버리는 주소: `javascript:`·`data:`·`file:`, 제어문자를 끼운 우회, userinfo(`https://bank.com@evil.com`), 2,048자 초과, 상대 경로(기준 URL이 없다).
- 원문을 한 글자라도 고치면 일반 번역이 되고, 정확히 되돌리면 링크가 돌아온다. 같은 문장을 다른 곳에서 다시 복사하면 예전 링크가 남지 않는다.
- 캐시 키에 구조(링크 번호만, URL 없음)를 넣는다(`document-inline-v1`). 캐시를 복원할 때는 지금 복사한 URL 표를 쓴다.
- 구조가 있는 원문은 문서 전체로 번역한다. 그 뒤에 직접 입력한 문단은 꼬리로 나눌 수 있을 때(원문과 덧붙인 글이 모두 일반 문장이고 빈 줄로 구분될 때, [증분 번역](incremental-translation.md) 규칙)만 꼬리로 번역한다. 꼬리 요청에는 구조를 싣지 않고 화면은 위쪽 링크·칩을 유지한다.
- 2026-10-13(U1): 펜스 밖 `---` 줄 뒤 블록은 원문 종류와 관계없이 꼬리다([명시 경계 번역](explicit-boundary-translation.md)). 코드 기호가 있거나 구조 복사인 A 뒤에 `---`를 두고 B를 붙여도 B만 구조 없이 요청하고 T(A)의 링크·칩은 그대로다. 구조가 없는 요청은 첫 경계에서 잘리므로, 잘린 첫 블록이 복사본과 정확히 같으면 그 블록 요청에 구조를 싣는다.

### 3단계: 복사한 코드 블록 (2026-10-13)

- 1단계의 "코드 위치는 모델이 펜스로 표시한다"를 복사한 웹 페이지에 한해 바꾼다. Chromium 복사의 `<pre>` 코드 블록은 앱이 펜스로 감싸 보내고(`CodeBlockGuard`가 모델 출력에서 블록을 원문 바이트로 되돌린다), 탭·복사 버튼 같은 위젯 글자를 지운 정리본이 원문 창·캐시의 기준이다. 선택된 탭 이름은 펜스 `title="…"`로 남는다. 상세는 [복사 원문 구조화](structured-copied-source.md).
- 모델이 직접 펜스를 다는 1단계 규칙은 일반 텍스트 복사에 그대로다.

### 4단계: 코드 표시 S6′ (#57·#58·#59 머지)

- #57(C1): 1단계의 고정 회색 박스를 코드 스타일 값(macOS Native 기본, GitHub)과 렌더러 하나로 바꿨다. 머리줄에 언어·제목과 블록 복사 버튼을 둔다.
- #58(C2): 직접 만든 줄 단위 토크나이저로 문법 색을 입히고, 긴 코드 블록을 접어 보인다. 처음 후보였던 HighlightKit·HighlighterSwift는 쓰지 않았다.
- #59(C3): 설정의 ‘표시’ 탭과 코드 스타일 고르기 화면을 반영했다. 스타일과 동작을 설정 화면에서 바꿀 수 있다.
- 상세 결정·한계·확인 항목은 [결과 창 코드 표시](code-display.md)에 있다.

#### S6′ 확정 설계 (2026-10-08)

시안은 저장소 밖의 pen.dev 시안에 있다.

- 설정에 '표시' 탭을 더한다. 첫 행은 '코드 스타일'(견본 + 스타일 이름 ›)이고, 그 아래에 동작 토글(긴 코드 접기, 링크 출처 표시, 문법 색)을 둔다.
- '코드 스타일' 행을 누르면 창이 넓어지며 고르기 화면이 열린다. 왼쪽은 스타일 목록, 오른쪽은 지금 고른 스타일과 동작 설정을 반영한 실제 결과 미리보기다.
- 원칙: 렌더러는 하나로 두고 스타일 값만 바꾼다. 접기·출처 표시·문법 색 같은 동작은 스타일과 분리한다.
- 사용자 취향은 GitHub 또는 macOS Native 스타일이다. PR #49에는 기본 macOS Native와 처음 스타일 GitHub·Native 두 개를, PR #53에는 기본 macOS Native만 적었다.
- 구현하면 [설정·창 크기 계획](window-size-and-layout.md)의 '별도 화면 탭은 만들지 않는다'(2026-09-23)를 갱신한다.

### 5단계: 목록 구조 보존 (2026-10-17 구현·오프라인 검증)

사용자가 제공한 impeccable 문서와 deepK 화면에서는 네 항목의 글머리표가 원문 창과 번역 결과에서 사라졌다. 항목 첫머리의 짧은 제목과 뒤 설명이 각각 하나의 항목으로 읽히고, 항목 사이가 구분되는 것이 목표다. 아래는 고정 응답의 구조 예시다. 실제 모델의 새 응답을 수집한 결과는 아니다. [36개 엄격 검사·실제 컴포넌트 전후 화면·CPU 비용](../docs/evidence/format-stability/README.md)에 근거와 한계를 남긴다.

```text
• 결과 설명: 원하는 결과를 일상적인 말로 설명하세요.
• 검토 요청: 디자인의 문제와 시작할 지점을 확인하세요.
• 대안 비교: 여러 안을 비교하고 유지할 버전을 고르세요.
• 페이지 가리키기: 바꿀 요소와 적용할 방향을 지정하세요.
```

**확인된 범위와 조사할 지점**

- 첨부 화면에서는 원문 창에 기호가 없다는 것까지 확인했다. 해당 복사의 `text/plain`·`public.html` 원본은 아직 확보하지 않았으므로, 브라우저 복사·가져오기·모델 응답 중 정확한 소실 지점은 캡처로 확인한다.
- 기존 검사는 평문에 이미 `•` 또는 `-`가 있는 경우였다. HTML에만 목록이 있는 세 합성 사례를 추가해 기호·번호·중첩을 복원하고 요청·결과·추가·재번역·내보내기를 검사했다. 실제 브라우저 복사 표본은 아직 확보하지 않았다.

**완료 기준**

- [x] 원문의 불릿 목록과 번호 목록을 구별해 원문 창·번역 결과에 표시한다. 항목 수·순서·경계를 지키고, 항목의 제목과 설명을 서로 다른 항목으로 나누지 않는다.
- [x] 긴 항목이 여러 줄로 감기면 다음 줄을 본문 시작 위치에 맞춘다. 항목 사이 간격과 중첩 목록의 깊이를 유지한다.
- [x] 번호 목록의 시작 번호와 항목별 번호(`ol[start]`, `li[value]`)를 보존한다. 평문에 기호·번호가 이미 있으면 중복해서 붙이지 않는다.
- [ ] 목록 안 링크·인라인 코드와 코드 카드·탭 제목은 보존한다. 다만 `<li>` 안 `<pre>`의 완전한 목록 포함 관계는 후속이며, 실제 복사와 외부 앱에서 확인한다.
- [x] 일반 텍스트·Markdown 복사와 삽입에서도 항목 기호와 구분이 남고, 서식 포함 복사의 HTML·RTF에도 목록 구조가 남는다.
- [x] 추가 입력·전체 다시 번역·방향/제공자 변경·캐시 복원에서도 목록이 일반 문단으로 바뀌지 않는다. 변경되지 않은 복사 접두부를 재사용한다. 복사 영역 내부 수정·여러 복사본은 #64 후속이다.

**구현 흐름과 후속 확인**

1. 브라우저의 복사 원본에서 일반 텍스트와 HTML 목록 경계를 대조한다. 목록 기호가 CSS로만 보이는 경우와 항목 중간에서 선택한 경우를 포함한다.
2. 가져오기 단계에서 목록 종류·항목·깊이·번호를 복사 범위의 텍스트와 대응시켜 보관하고, 모델 입력에 명시적인 목록 구조를 싣는다. HTML의 페이지 전체 목록을 복사 범위 밖까지 끌어오거나, HTML 근거가 없는 일반 문단을 임의로 목록으로 만들지 않는다.
3. 결과 표시와 복사·삽입이 같은 목록 정보를 쓰도록 한다. HTML이 없는 일반 텍스트와 Markdown의 기존 기호도 지원한다. 기호는 일반 텍스트에 남기고, 공유 `TranslationLists`가 표시·HTML·RTF의 UTF-16 범위를 해석한다. 복사 접두부 재사용과 캐시의 구조 동등성은 Store에서 검사한다.

| 첨부 화면의 네 항목을 재현한 픽스처: HTML에는 `ul/li`, 평문에는 기호 없음(실제 복사 원본은 별도 확보) | 원문과 결과에 네 항목이 구분되고 앞에 글머리표가 보임 |

| HTML 번호 목록의 시작 번호·중간 번호 변경, 불릿/번호 중첩 | 번호와 중첩 깊이 유지 |
| 긴 항목, 항목 안 여러 문단·링크·인라인 코드·코드 블록 | 줄 감김의 들여쓰기와 항목 경계 유지, 링크·코드도 유지 |
| 목록 일부 선택, 첫/마지막 항목 중간 선택 | 선택한 내용만 번역하고 선택 밖 항목을 추가하지 않음 |
| 목록과 코드 위젯을 함께 복사 | 목록과 코드·탭 제목의 경계가 섞이지 않음 |
| 추가 입력·`---` 경계·전체 재번역·방향/제공자 변경·캐시 복원 | 기존 항목과 목록 정보가 사라지거나 중복되지 않음 |
| 결과의 두 복사 형식·삽입, 좁은/넓은 실제 창 | 기호·항목 구분을 유지하고 긴 줄의 들여쓰기가 올바름 |

문자열에 `-`가 남는 것만으로 완료 처리하지 않는다. 실제 Chrome 복사 → 원문 창 → 모델 요청 → 결과 창 → 복사·삽입을 확인하고, 각 단계의 검증 여부를 따로 기록한다.

## 6. 결정 기록

- PR #49 착수 전 사용자 결정: 두 PR로 나눈다. 원문 창은 일반 텍스트로 둔다. 링크 글자는 번역하고 링크는 유지하며 클릭하면 바로 연다. 복사 형식은 설정에서 고른다(기본 서식 포함). 코드 주석은 번역한다.
- 2026-10-08: 고정 회색 박스 대신 설정에서 고르는 '코드 스타일'로 제공하고, 설정 화면은 S6′(표시 탭 + 드릴다운 고르기)로 확정했다.
- 2026-10-12: 꼬리 입력 후 전체 재번역의 링크 소실은 증분 규칙과 함께 바꿔야 해 별도 작업으로 보류했다.
- 2026-10-12(PR #53): 출처 URL(`org.chromium.source-url`) 값은 읽지 않는다. 이 타입은 Chromium 복사인지 판별하는 데만 쓴다. Chrome은 클립보드 HTML에 절대 주소를 쓰므로 상대 경로 링크는 버린다. 그래서 `RichSourceImporter.capture`의 `sourceURL` 인자는 앱 경로에서 쓰이지 않는다.
- 2026-10-17: 사용자 첨부 화면을 기준으로 각 항목의 글머리표·번호와 목록 형식을 유지하는 개선을 추가했다. 텍스트에 이미 기호가 있는 목록과 HTML에만 구조가 있는 목록을 나눠 검사하고, 결과 표시뿐 아니라 원문 가져오기부터 복사·삽입까지 완료 기준에 포함한다.

- 2026-10-17 구현: 원래 목록 3개·자동 감지 2개·복사 접두부 뒤 재번역 2개는 모두 엄격 검사에서 통과한다. HTML 목록을 실제 기호로 복원하고 두 편집기의 내어쓰기, HTML·RTF 목록을 지원했다. 원문 내부 편집과 실제 앱 연동은 완료 처리하지 않았다.
