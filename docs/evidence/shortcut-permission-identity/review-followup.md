# 병합 전 독립 리뷰 반영

## 권한 안내 창 종료

PR #6의 `cb381b8`에서 시스템 설정 프로세스가 살아 있지만 창만 닫히면, 안내가 숨은 채 0.25초 타이머가 계속 남는 경로를 확인했다. 처음 창을 본 뒤에는 시작 시간 제한도 적용되지 않아, 나중에 다른 설정 창을 열면 오래된 안내가 다시 표시됐다. 작업 세션에서도 리뷰어의 격리 재현을 실행해 같은 결과를 확인했다. 실제 사용자 권한이나 화면을 조작하지 않은 실험이다.

시스템 설정의 모든 일반 창 존재와 지금 화면에 보이는 앞쪽 창을 분리했다. 창을 닫으면 안내와 타이머를 종료하고, 다른 앱·Space로 이동하거나 최소화하면 안내만 숨긴다. 돌아오면 같은 안내를 다시 표시한다. 창이 처음부터 나타나지 않을 때의 15초 대기도 유지한다.

`PermissionGuideLifecycleTests`는 처음 창을 기다리기, 표시, 앱 전환·최소화 중 숨김, 복귀, 창 닫기, 시작 시간 초과, 배경 창 닫기를 확인한다. 실제 타이머 컨트롤러가 이 수명 상태의 결정을 사용한다. 단독 Swift 6 검사와 `bash -n scripts/test.sh`, `git diff --check`가 통과했다.

두 변형을 별도 임시 사본에서 컴파일해 실행했고 모두 새 테스트가 실패했다.

| 변형 | 결과 |
|---|---|
| 설정 창을 관찰했다는 상태를 기억하지 않음 | 창 닫기 검사 실패 |
| 다른 앱으로 이동할 때 숨김 대신 종료 | 앱 전환 검사 실패 |

선행 PR 브랜치는 별도 checkout에서 사용 중이므로 그 브랜치를 변경하지 않았다. 수정은 PR #7에 포함하고 기준을 `main`으로 바꿔 PR #6의 변경과 수정이 함께 들어가는 최종 결과를 검증한다. PR #6은 대체 PR이 병합된 뒤 중복으로 닫는다.

처음 시작한 PR #6 단독 머지 후보의 전체 검사는 최종 병합 경로를 바꾸면서 중단했다(exit 130). 완료·통과로 세지 않는다. 최종 PR #7의 머지 후보 전체 검사·빌드 결과와 고정 SHA는 PR 리뷰 반영 코멘트에 따로 기록한다. 수명 테스트 추가 후 Swift 검사 구성은 30개 소스 파일·26개 실행 프로그램이며 개별 케이스 수와 구분한다.

## 로컬 정리

사용자의 불필요한 항목 제거 요청에 따라 개발 앱의 입력 모니터링·손쉬운 사용 기록 2개만 초기화했다. 남은 관련 기록 27개는 허용값·서명 조건 해시·수정 시각까지 유지됐고, 설치 앱의 ‘권한 준비됨’도 확인했다. 임시 빌드·스테이징 폴더 9개는 복구 가능한 휴지통으로 옮겼다. 설치 앱·공증 ZIP·이전 버전 복구 ZIP·검증 자료는 보존했다.

## 측정 범위

사용자가 설정 창을 닫은 뒤 남던 반복 타이머를 종료하도록 한 동작 수정이다. 실제 배터리·CPU 사용량과 번역 속도는 미측정이며 성능 개선 수치를 주장하지 않는다. 이 코드 변경으로 기존 빌드 19와 달라지므로 최종 배포본을 다시 빌드·서명·공증해야 한다.
