# 선택형 업데이트 안내 검증

2026-11-15, 언어 지원 PR19 head `d273fd9` 위의 업데이트 안내 변경. 별도 작업 트리에서 기존 준비 코드 중 업데이트 관련 파일만 옮겼다. 기존 미커밋 권한 복구 작업은 수정하지 않았다.

- `scripts/test-app-updates.sh`: 모의 HTTP·버전 비교·정식 arm64 ZIP·일일 주기·캐시·중복 안내·자동 확인 끄기·수동 확인·취소 검사 통과. 첫 sandbox 실행은 Swift 매크로 실행 제한으로 컴파일 실패했고, 정상 권한 환경에서 재실행해 통과했다.
- 현지화 정적 검사: 291 참조 키, 295 항목, 4개 언어, 플레이스홀더 보존 통과. 실제 번들 조회 전체를 보증하는 검사는 아니다.
- 실제 Debug 앱 0.3.0 (65)을 실행해 새 버전 알림 설정과 수동 확인을 확인했다. 당시 공개 최신 v0.2.0 조회 후 ‘현재 버전보다 새로운 업데이트가 없습니다’가 표시됐고 확인으로 정상 복귀했다.
- [설정 실제 화면](settings.png): Dev 자동 확인 기본값 off. 배포 앱은 on. 구독·계정 정보는 캡처하지 않았다.
- 실제 새 stable 릴리스를 발견했을 때 안내 창 표시, 다른 Mac의 업데이트/권한, 자동 업데이트 지연·메모리 비용은 미검증이다. 안내 닫기/중복 방지는 모의 응답 테스트 범위다. 번역 지연 전후 비교는 하지 않았다. 번역 경로에는 추가 네트워크 대기를 넣지 않았다.

전체 테스트·최종 빌드 및 배포 검증은 PR 기록에서 해당 head와 함께 추가한다. 이 문서만으로 릴리스 공개나 Homebrew 설치 완료를 뜻하지 않는다.

동일 버전 비교를 `>`에서 `>=`로 바꾼 사본은 처음 기존 검사를 통과했다. 실제 동일 버전 조회 검사를 추가한 뒤 정상 구현은 통과했고, 변형은 `a fresh check must not offer the already installed version` 단언에서 exit 133으로 실패했다. 제품 코드 변경 없이 검사 실효성을 보강했다.

## 내용 기준 높이 디자인 보완

Claude 시안의 창 크기 수정과 디자인을 `cd9e783`에 반영했다. `maxHeight: .infinity`와 NSHostingView 기본 최소 크기 전달 때문에 넓이가 좁아진 채 글이 줄바꿈되어 높이가 과도하게 늘어나는 경로를 제거했다. 고정 폭과 내용 높이·intrinsicContentSize로 창 크기를 정한다. 자세한 시안·Claude 측정값은 [디자인 기록](../../design/update-notice/design.md)에 있다.

메인 세션에서 실제 Dev 앱에 업데이트 관련 설정 다섯 항목만 백업하고 모의 0.3.1을 임시 적용해 새 패널을 띄웠다. 실제 창 목록에서 **340×161pt**를 확인했고 앱 아이콘·문구·버튼이 잘리지 않는 것을 직접 확인했다. [실제 앱 패널 PNG](compact-panel-mock-version.png)는 **모의 버전 화면**이며 실제 0.3.1 릴리스가 아니다. ‘계속 사용’ 후 정상 번역 창으로 돌아옴을 확인하고 앱을 정상 종료했다. `defaults import`가 생략 키를 삭제하지 않아 첫 원복 검사에서 모의 값 세 개가 남았으나, 해당 키를 명시적으로 제거한 뒤 다섯 항목의 원본 일치를 확인했다. 배포 앱 설정은 변경하지 않았다.

새 디자인의 Debug 빌드와 업데이트 로직 회귀 검사 통과. 최종 전체 회귀 검사는 별도 실행 중이며 완료 후 PR에 결과를 기록한다. 사용자 실제 번역 작업의 원문·결과는 재시작 전에 로컬로 보존했고 공개 증거에는 포함하지 않았다. 실제 릴리스 감지·다중 화면 배치·다크 모드는 추가 검증하지 않았다.
