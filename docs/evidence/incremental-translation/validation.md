# 증분 번역 1차 검증 — 2026-09-27

대상: `0d6c8d5`에서 시작한 현재 작업 트리. 사용자 요청에 따라 문단 append를 구현했다. 커밋·원격 게시·앱 자동 재시작은 하지 않았다.

## 지원 동작

- A 번역 완료 후 빈 줄로 B 추가: T(A)를 유지하고 B만 요청.
- B 진행 중 빈 줄로 C 추가: B 요청 유지, 완료 뒤 C만 요청.
- 미완료 B 수정: A 유지, 이전 B 응답 폐기, 수정된 B 요청.
- B 오류/연결 끊김: A 유지, 재시도/연결 복구 후 미완료 부분만 처리.
- 현재 원문 전체가 완료되기 전 전체 복사·삽입 차단. 전체 다시 번역은 캐시를 우회.
- 처음 여러 문단을 함께 입력한 결과는 하나의 완료 단위. 완료 단위 내부 수정/겹치는 재선택까지 문단별 재사용하지 않는다.

## 자동 검사

`bash scripts/test.sh`:

- `IncrementalTranslationTests`: 실제 전달 payload와 요청 횟수, 순서/완료 경계, 변경된 tail/제공자/언어의 늦은 응답 차단, IME·길이 제한, 캐시 메타데이터 복원, 캐시 비활성화 시 현재 문서 보존, byte 한도, 연결 복구, 명시적 전체 재번역, 새 prefix를 과거 전체 캐시가 덮어쓰지 않는지 검사.
- 기존 `TranslationStoreTests`: 공백 정규화·진행 요청 재사용·캐시 만료/축출·중복 이벤트·제공자 변경·타임아웃 회귀 유지.
- `TranslationResultTextViewTests`: 실제 AppKit 객체에서 텍스트 추가, 선택/스크롤 보존, 문단 간 선택, 자동 따라가기 없음·원점 고정, 꼬리만 고치는 완료/재시도, 초안 제거 시 높이 유지, 앞 단위 삭제 시 읽던 줄 유지, 새 번역 알림, 다른 결과로 교체. NSApplication은 초기화하며, first responder 검사용 창은 만들지만 표시하지 않는다.
- 덧붙이기 전후 렌더링(2026-10-07): [이전](append-before.png) · [이후](append-after.png). 영상 원문 두 문단 번역 뒤 두 문단을 붙이는 시나리오를 c16912f와 새 코드에 같은 조건으로 넣고, 실제 결과 뷰(`TranslationResultTextView`)를 단계마다 이미지로 그린 것이다. 번역문은 미리 정한 값이며 제공자를 호출하지 않았다. 앱 전체 창 스크린샷이 아니라 상태 행은 포함하지 않는다.
- `StableAppendIntegrationTests`(2026-10-07): 실제 Store가 내보내는 표시 값을 실제 결과 뷰에 적용한다. 추가·스트리밍·완료·실패·재시도 동안 읽기 위치·선택·이미 보인 번역이 바뀌지 않는지, 읽던 앞 단위가 삭제되면 남은 글이 맨 위에 오는지, 전체 재번역 동안 흐린 이전 번역이 제자리에 있다가 같은 화면에서 교체되는지 검사한다.
- Codex/Claude 모의 통신, 두 번 복사/권한 표시, 창 정책, 로그인 항목 회귀 검사 포함.

`bash scripts/build.sh`: Xcode Debug 앱 빌드와 기존 개발 인증서 서명 검증. 빌드 위치는 `.build/DerivedData/Build/Products/Debug/DeepK.app`이다. AppIntents 프레임워크를 사용하지 않는 프로젝트의 메타데이터 추출 생략 경고는 기존 도구 출력이며 빌드 실패가 아니다.

## 실제 구독 제공자 확인

실행: `DEEPK_RUN_LIVE_TRANSLATION_TESTS=1 bash scripts/test-incremental-live.sh`. 특정 제공자만 다시 확인할 때 `DEEPK_LIVE_PROVIDER=codex` 또는 `claude`를 지정한다. 기본 실행은 최대 6번의 예시 번역을 요청한다. 환경 변수와 `--synthetic-fixture`가 없으면 fixture는 실행을 거부한다.

fixture는 회의 시간·보고서 부수·문서 공유 금지에 관한 공개 예시 문장만 사용한다. 사용자 영상/원문을 전송하거나 자격 증명을 직접 읽지 않는다. Claude 실행 파일 경로 하나만 앱 설정에서 읽어 실제 앱과 같은 CLI를 사용한다. 설정과 로그인 상태를 바꾸지 않는다.

| 제공자 | 모델 | 요청 | 요청별 문자 수 | 기존 번역 보존 | 최초 완료 / A+B+C 전체 |
| --- | --- | --- | --- | --- | --- |
| Codex | gpt-5.6-luna | 3회 | 41 / 45 / 43 | 통과 | 약 5.55초 / 14.03초 |
| Claude Code | claude-haiku-4-5-20251001 | 3회 | 41 / 45 / 43 | 통과 | 약 4.05초 / 9.95초 |

A 완료 뒤 B를 시작하고 곧바로 C를 추가했다. fixture는 실제 클라이언트에 전달된 원문 목록이 정확히 `[A, B, C]`인지 검사한다. B/C를 기다리는 동안 T(A)가 남아 있고 전체 복사·삽입이 비활성이며, 최종 결과는 세 단위와 동일 T(A)를 유지하는지 확인한다. 수치는 제공자별 단일 시나리오의 관측이며 평균/p95나 속도 향상 보장이 아니다. 문맥 독립 번역의 일반적인 품질을 입증하지도 않는다.

처음 Claude 확인은 기본 PATH의 구버전 CLI로 인해 번역 전 실패했다. fixture가 앱의 `claudeExecutablePath`를 사용하도록 수정 후 Claude만 다시 실행해 위 결과를 확인했다. 설치나 인증을 변경하지 않았다.

## 남은 수동 사용 확인

- 새 빌드로 재실행한 전체 앱의 작게/크게 배치, 창 닫기/재호출, 실제 IME 사용.
- 실제 Chrome/TextEdit에서 두 번 복사 → 문단 추가 → 전체 복사/원래 위치 삽입.
- 사용자 문서의 용어·대명사 일관성. 필요하면 ‘전체 다시 번역’으로 문맥을 포함해 번역한다.

자동 검사는 부분 결과 사용 차단과 기존 삽입 세션 계약을 확인하지만 실제 사용자 대상 앱의 삽입 성공을 대신하지 않는다. 영상의 겹치는 재선택 전체를 해결했다고 주장하지 않는다.

## 앞부분 삭제 보완

사용자 확인으로 재현 조건이 끝의 구두점/개행 편집이 아니라 위쪽 원문 삭제임을 확인했다. 별도로 번역 완료된 A/B에서 A를 제거한 경우 B를 재사용하도록 보완했다. B만 남기기, 남은 개행 보존, B 뒤에 C 추가, C 처리 중 A 삭제와 D 추가, LRU 비활성화, 반복 문단 오판 방지를 모의 제공자의 실제 요청 payload·횟수·취소 여부로 검사한다.

구두점/개행 정규화 정책은 변경하지 않았다. 최초 전체 번역의 내부를 잘라 원문-번역 대응을 알 수 없는 경우에는 여전히 전체 번역이 필요하다. 이번 보완의 제공자 통신/외부 앱 삽입을 별도로 실측한 것은 아니다.

보완 후 `bash scripts/test.sh` 전체 검사와 `bash scripts/build.sh` 빌드·서명 검증이 통과했다. 수정본을 다시 테스트할 수 있도록 기존 실행 스크립트로 앱을 재시작한다.

## 링크·인라인 코드가 있는 원문 — 2026-10-12

[#53](https://github.com/Geuni620/deepK/pull/53) 이후 Chrome 계열에서 복사한 원문에 링크·인라인 코드가 있으면 증분 규칙이 다음처럼 달라진다. `TranslationStoreTests`가 모의 제공자의 요청 payload로 검사한다.

- 구조가 있는 복사는 앞에 번역된 일반 문서가 있어도 꼬리가 아니라 문서 전체로 요청한다.
- 그 뒤에 직접 입력한 문단은 꼬리로 나눌 수 있으면(원문과 덧붙인 글이 모두 일반 문장이고 빈 줄로 구분됨) 구조 없이 꼬리로 요청하고 위쪽 번역의 링크·칩은 유지한다. 꼬리로 나눌 수 없으면 전체 요청이 되어 링크와 칩이 사라진다.
- 이 상태에서 ‘전체 다시 번역’(또는 방향·제공자를 바꾼 뒤 다시 번역)을 하면, 원문이 복사본과 달라 구조 없이 요청하므로 링크와 칩이 사라진다. 꼬리 증분 규칙과 함께 바꿔야 해서 보류했다.
- 실제 앱에서 복사 → 문단 추가 → 전체 복사·삽입 흐름은 확인하지 않았다([Mac 연동 기록](../../../plans/mac-integration-checks.md#실제-앱-확인-대기--2026-10-12)에서 추적).
