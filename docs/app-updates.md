# 새 버전 확인과 업데이트 안내

0.3.0에서 새 버전 확인과 앱 내 업데이트 알림을 추가한다. 현재 공개된 0.1.0·0.1.1·0.2.0에는 이 코드가 없으므로 기존 설치본에 원격으로 알림을 보낼 수 없다. 처음 한 번은 Homebrew 업그레이드 또는 새 ZIP의 앱 교체가 필요하다. 후보 코드가 있다는 사실은 0.3.0의 공개 배포 완료를 뜻하지 않는다.

## 앱에서의 동작

- 배포 앱은 처음 시작할 때 확인하고, 마지막 성공한 확인으로부터 24시간 후 다시 확인한다. 앱이 활성화되어도 최근 확인은 중복 요청하지 않는다. 실패하면 1시간 후 재시도하며 자동 실패 안내를 띄우지는 않는다.
- 설치 가능한 새 버전이 있으면 키보드 포커스를 가져오지 않는 업데이트 안내 창을 버전당 한 번 표시한다. 번역·한글 조합·모달 안내 중이면 표시를 미루며, 다음 주기 확인 때 다시 시도한다.
- 업데이트는 선택 사항이다. ‘계속 사용’을 누르거나 안내 창을 닫으면 현재 버전으로 이어서 사용한다. 업데이트를 미뤘다는 이유로 번역·복사·삽입 등 기존 기능을 제한하지 않는다.
- 메뉴 막대 메뉴에 업데이트 항목을 남기고, 설정 하단과 앱 메뉴에도 수동 확인을 제공한다. 수동 확인은 주기 제한과 관계없이 동작한다.
- 같은 버전의 자동 안내를 다시 띄우지 않도록 표시한 버전을 Mac에 저장한다. 발견한 새 버전도 저장해 재실행 후 일일 확인 주기에 걸려 업데이트 표시가 사라지는 것을 막는다.
- 설정의 ‘새 버전 알림’을 끄면 이후 자동 확인을 멈춘다. 수동 확인은 계속 쓸 수 있다. 개발 앱 `com.deepk.app.dev`는 기본적으로 자동 확인을 끈다.
- ‘업데이트 안내 열기’는 해당 버전의 공식 GitHub 릴리스 페이지를 연다. 이 구현은 앱을 자동으로 다운로드·교체하거나 권한을 다시 허용하지 않는다.

## 배포와 요청 정보

확인 주소는 `https://api.github.com/repos/Geuni620/deepK/releases/latest`다. stable 버전 숫자와 실제 Apple Silicon 앱 ZIP이 함께 있는 릴리스만 안내한다. Draft, 사전 릴리스, 소스만 공개한 릴리스와 현재보다 오래된 버전은 안내하지 않는다. 릴리스 페이지 주소는 응답의 임의 URL을 사용하지 않고 이 저장소 주소와 검증한 태그로 만든다.

배포할 때는 `VERSION`과 태그의 버전 숫자를 올려야 한다. 같은 버전의 ZIP만 교체한 경우에는 새 업데이트로 판단하지 않는다.

요청에 원문·이미지·번역문·계정 토큰·사용자 식별자를 넣지 않는다. 쿠키와 인증정보를 공유하지 않는 별도의 일시적 네트워크 세션을 사용한다. GitHub는 IP 주소 등 일반적인 접속 정보를 처리할 수 있다. 로컬에는 확인 시각·성공 여부·알릴 버전·이미 표시한 버전·자동 확인 선택만 저장한다.

## 검증

`bash scripts/test-app-updates.sh`는 가짜 HTTP 응답과 독립된 설정 저장소로 버전 비교, 배포 ZIP 검사, 일일 확인, 재실행 캐시, 중복 안내 방지, 오류 재시도, 자동 확인 끄기와 늦은 응답 취소를 검사한다. `--live-check`를 붙이면 공개 릴리스 정보만 실제로 조회한다. 이 조회는 앱 설치·재실행이나 알림 창 표시의 증거가 아니다.

실제 사용자 Mac의 검증은 새 기능이 포함된 배포 앱 설치 후 더 높은 stable 릴리스를 공개했을 때의 안내 표시·‘계속 사용’ 이후 기능 유지와 반복 방지·메뉴에서 재확인·설치 후 버전 변경을 확인해야 한다.
