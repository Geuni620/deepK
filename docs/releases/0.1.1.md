# deepK 0.1.1

이번 업데이트는 두 번 복사 단축키의 권한 충돌을 줄이고, 앱 이름과 개발·배포 환경을 구분하는 수정이다.

## 사용자에게 보이는 변화

- 배포 앱의 파일·실행 파일·번들·표시 이름을 모두 `deepK`로 통일했다. `DeepK`와 `deepK`가 섞여 보이던 이름을 정리한다.
- 권한 화면에 **감시 다시 연결**을 추가했다. 설정 스위치 표시만으로 연결됐다고 판단하지 않고 실제 입력 감시의 재연결 결과를 보여 준다.
- 권한을 허용한 뒤 재실행이 필요한 경우 **앱 다시 열기…**를 제공한다. 현재 번역 내용이 유지되지 않는다는 안내를 먼저 표시한다.
- 권한 요약을 ‘연결 확인 필요’로 바꿨다. 시스템 설정에서 허용돼 있어도 실행 중인 앱의 감시 연결이 끊긴 상황을 구분한다.

## 개발·촬영 작업이 설치 앱에 미치는 영향 축소

- 개발 앱을 `deepK Dev.app` / `com.deepk.app.dev`로 분리했다. 배포 앱은 기존 `com.deepk.app`을 유지한다.
- 개발 실행 스크립트가 종료하는 대상도 개발 앱으로 제한했다.
- 공증하지 않는 로컬 테스트 패키지는 개발 앱의 이름·식별자와 별도 빌드 캐시를 사용한다.
- 개발·배포 앱의 Claude CLI 설정 도메인과 설치 디렉터리를 함께 분리했다. 개발용 준비가 배포용 CLI 파일을 덮어쓰지 않도록 했다.

## 검증 범위

개발 앱에서 사용자의 실제 키보드로 ⌘C 두 번 호출, 합성 원문 캡처와 한국어 번역을 확인했다. 설치 앱의 입력 모니터링 재등록과 준비 상태도 별도로 확인했다. 같은 조건의 실제 SwiftUI 권한 화면과 실제 키보드 결과를 [검증 기록](../evidence/shortcut-permission-identity/verification.md)에 보관했다.

이전 로컬 검증본은 **0.1.1 (빌드 19)**이며 Apple 공증 Accepted, 티켓·서명·Gatekeeper 검증을 통과했다. 이 Mac에서 0.1.0→0.1.1 업데이트 시 입력 모니터링 권한을 재등록하지 않고 ‘준비됨’이 유지됐고, 관련 OS 허용값·서명 조건도 같았다. 이는 이 Mac의 1회 확인이며 다른 Mac이나 과거에 서명 기록이 어긋난 환경 전체의 검증은 아니다.

이후 손쉬운 사용 스위치가 켜져 있는데도 미연결인 원인을 추가로 확인했다. 과거 개발용 서명 조건이 남은 기록이었으며, 사용자 승인 후 설치 앱의 손쉬운 사용만 초기화해 현재 앱으로 등록했다. 앱에서 두 권한 모두 ‘준비됨’으로 바뀌었고, 나머지 입력 모니터링·손쉬운 사용 기록 28개는 그대로였다. 기존 잘못된 기록의 복구 과정이며 모든 사용자가 업데이트할 때마다 재등록해야 한다는 뜻은 아니다.

전체 회귀 스크립트의 최초 실행은 Claude 가짜 CLI의 인증 확인 시간 초과로 중단됐다. 해당 실행 파일의 단독 재검사와 나머지 검사 구간이 통과했다. CLI 설치 격리는 별도의 가짜 npm/defaults 테스트로 검증했다. 최초 전체 실행을 한 번에 통과한 것으로 표현하지 않는다.

번역 모델·언어 지원·번역 속도를 개선한 업데이트는 아니며, 속도 비교는 수행하지 않았다. 기존 서명과 어긋난 OS 권한 기록이 자동으로 고쳐지는 것은 아니다. 다른 Mac 설치와 원래 위치 삽입 등 미검증 범위 및 공증 결과는 검증 기록에서 구분한다.

이 문서는 수정 내용 설명이며 GitHub Release·Homebrew 공개 게시를 뜻하지 않는다.

## 최종 배포 후보

병합 전 독립 리뷰에서 설정 창을 닫아도 권한 안내 타이머가 남는 문제를 수정해 **0.1.1 (빌드 24)**로 다시 빌드·서명·공증했다. 새 ZIP의 추출본에서도 번들 내용·strict 서명·공증 티켓·Gatekeeper 검증을 통과했다. 개발 설정 명령과 세션 검증 도구의 대상도 개발 앱으로 통일했다. 이전 빌드 19의 검증은 당시 기록으로 보존하며, 최종 후보의 근거는 [현재 공증 결과](../evidence/shortcut-permission-identity/notarization-verification.json)와 [리뷰 반영 기록](../evidence/shortcut-permission-identity/review-followup.md)에서 확인한다. 공식 게시 여부는 GitHub Release를 기준으로 확인한다.
