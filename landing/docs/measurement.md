# 웹사이트 측정과 개선

이 문서는 `deepk.geuni.me` 소개 페이지에만 적용한다. Mac 앱의 번역 사용량·원문·이미지·OCR 글자·번역문을 측정하거나 운영자에게 보내지 않는다. 웹사이트의 자동 예시는 준비된 애니메이션이며 실제 번역이나 사용자 체험 완료가 아니다.

## 측정 범위

기존 Google Analytics 계정 안에 deepK 전용 GA4 속성과 HTTPS 웹 스트림을 사용한다. 개인 블로그의 속성·설정·보고서와 분리한다. 별도 서버, 광고 계정, 결제·유료 요금제, 세션 녹화는 추가하지 않는다.

| 이벤트 | 실제 의미 | 해석하면 안 되는 것 |
| --- | --- | --- |
| `page_view` | 통계를 허용한 방문자의 공식 페이지 열람 | 전체 실제 방문자 수, 앱 사용 횟수 |
| `install_guide_open` | 설치 안내 대화상자 열기 또는 안내 링크 클릭 | 설치 완료 |
| `install_command_copy` | 제공한 Homebrew 설치 명령을 클립보드에 쓰는 데 성공 | 터미널 실행·설치 성공 |
| `download_click` | 공식 ZIP 링크 클릭 | 다운로드 완료·설치·재방문 |

GA4의 `first_visit`, `session_start`, `user_engagement` 같은 기본 방문 이벤트가 함께 생길 수 있다. 자동 폼·검색·스크롤·파일 다운로드·외부 링크 측정은 웹 스트림의 향상된 측정에서 끈다. 직접 보내는 이벤트 이름은 위 네 개로 제한한다. 언어와 설치 방법은 정해진 값만 쓰며 DOM 텍스트·입력값·클립보드 읽기·원본 링크를 이벤트 인자로 넘기지 않는다.

## 동의와 데이터 경계

- 처음 방문하거나 선택이 만료되면 허용/거절을 같은 수준으로 제공한다. 거절해도 설치와 모든 페이지를 사용할 수 있다.
- **Basic consent mode**: 허용 전에는 Google Analytics 스크립트 자체를 불러오지 않는다. 거절 상태의 cookieless ping도 보내지 않는다.
- 허용 여부만 `deepk.website-analytics.v1`에 최대 180일간 저장한다. 브라우저 저장소가 막히면 메모리에서만 처리한다.
- 허용한 방문의 유입 분류 enum만 `deepk.website-source.v1`에 탭 세션 동안 유지한다. 내부 페이지 이동·새로고침을 새 유입으로 잘못 분류하지 않기 위한 값이며, 새 외부 유입 때 갱신하고 철회 때 비운다. URL이나 사용자 콘텐츠를 저장하지 않는다.
- 페이지 아래 통계 설정에서 철회하면 자체 이벤트 전송과 해당 측정 ID를 비활성화하고 deepK 전용 GA 쿠키를 지운다. 이미 Google에 전송된 과거 데이터까지 삭제한다는 뜻은 아니다.
- DNT 또는 GPC가 켜져 있으면 측정하지 않는다. 다른 탭의 선택 변경도 반영한다.
- HTTPS 공식 도메인의 `/`, `/en/`, `/guide/`, `/en/guide/`, `/privacy/`, `/en/privacy/`만 허용한다. `embed` 쿼리가 있으면 제외한다.
- `page_location`은 공개 경로로 재구성하고 쿼리·해시를 제거한다. `page_referrer`는 출처 origin으로 줄인다. UTM의 임의 문자열은 넘기지 않으며 유입 분류는 정해진 소스 값만 쓴다. 알려지지 않은 소스는 `other`다.
- `deepk` 쿠키 접두사와 `deepk.geuni.me` 도메인을 사용해 개인 블로그 쿠키와 분리한다. 방문 쿠키의 설정 수명은 90일이다.
- Google Signals, 광고 개인화, User ID, 광고 제품 연결은 사용하지 않는다. 광고 관련 동의는 계속 거절 상태다.
- Google은 허용된 방문 통계에 대해 브라우저·기기·대략적인 지역 등 기본 정보를 처리할 수 있다. 외부 제공자의 처리와 보관은 그 서비스 정책을 따르며 전체 경로의 무저장을 약속하지 않는다. 호스팅 접속 기록과 Google Fonts는 별개다.

## 설정과 검증

1. 전용 GA4 속성의 시간대는 대한민국, 통화는 KRW로 두고 공식 도메인의 웹 스트림을 선택한다. 향상된 측정을 끄고 광고·Signals가 활성화되지 않았는지 확인한다.
2. 공개 측정 ID만 Vercel의 운영 환경변수 `PUBLIC_GA_MEASUREMENT_ID`로 지정한 뒤 정확한 소스 커밋을 빌드·배포한다. ID는 인증 토큰이 아니며 비밀키를 만들지 않는다.
3. 새 브라우저 상태에서 허용 전과 거절 후 `googletagmanager`·`google-analytics` 요청이 없는지 확인한다. 허용 후에는 알려진 이벤트만 보내는지 확인하고, 철회 뒤 추가 전송과 전용 쿠키를 확인한다.
4. 직접 만든 합성 마커를 쿼리·해시·유입 경로에 넣어 실제 측정 요청에 남지 않는지 확인한다. 사용자 번역 내용으로 테스트하지 않는다.
5. 미리보기·시안·직접 입력 체험과 DNT/GPC에서는 측정하지 않는지 확인한다. GA4 Realtime 또는 DebugView에서 도착한 합성 이벤트와 정상 보고서의 집계 지연을 구분한다. 로컬 가짜 태그 테스트만으로 실제 GA4 수신 완료라고 하지 않는다.

## 개선에 사용하는 방법

처음에는 방문 수, 유입 출처, 언어별 설치 안내 열람, Homebrew 복사·ZIP 클릭을 같은 기간끼리 본다. 보고서에서 이벤트 수와 해당 행동을 한 사용자 수를 구분한다. 반복 클릭과 동의·차단 비율 때문에 정확한 사람 수 또는 완전한 퍼널이라고 단정하지 않는다.

| 관찰 | 확인할 개선점 |
| --- | --- |
| 검색 유입 자체가 적음 | Search Console 색인·검색어·제목·설명과 공개 링크 확인 |
| 메인 방문에 비해 설치 안내 관심이 적음 | 지원 Mac·기존 CLI 구독 조건·이미지 번역 가치가 첫 화면에서 명확한지 확인 |
| 설치 안내는 보지만 복사·ZIP 클릭이 적음 | 설치 단계, 권한 이유, CLI 로그인 설명의 막힘 확인 |
| 특정 언어·기기에서 차이가 큼 | 해당 언어 문구와 모바일 레이아웃을 직접 확인 |

수집 전 과거 데이터는 소급해서 만들지 않는다. 실제 표본이 쌓인 뒤 한 번에 한 가지 문구나 배치를 바꾸고 같은 지표를 비교한다. 작은 수치 차이를 성과나 인과관계로 포장하지 않으며, 지금은 A/B 배분이나 자동 변경을 구현하지 않는다. 앱 사용·설치 성공을 알려면 별도 설계와 사용자 원칙 검토가 필요하다.

검색 관련해서는 공식 6개 경로의 canonical·언어 대체 링크·사이트맵·구조화 데이터를 유지하고, Search Console에서 소유권이 확인된 속성에 사이트맵을 제출한다. 검색엔진이 실제로 색인하고 순위를 반영하는 시점은 별도로 확인해야 한다.
