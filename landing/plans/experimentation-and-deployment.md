# 랜딩페이지 A/B 테스트와 배포 — 검토안

작성일: 2026-10-25

사용자는 기존 pen.dev 시안을 디자인 기준으로 수용했고, 제작 후 A/B 테스트와 배포도 고려하도록 요청했다. 이 문서는 구현 시 준비할 운영 경계를 정리한다. 실제 페이지, 계측, 계정 연결과 배포는 아직 구현·실행하지 않았다. 도구와 비용은 추천안이며 확정 사항과 구분한다.

## 1. 구현과 실험의 순서

1. 기존 시안에 맞춘 기준 페이지 A를 만든다. 이전 기술 초안의 Astro + TypeScript와 필요한 부분의 React 구성을 기본 검토안으로 유지한다.
2. 미리보기에서 반응형·주요 동작·계측을 확인한다. 첫 공개는 A만 제공해 방문량과 기본 전환율을 관측한다.
3. 계측이 안정되고 측정 목표가 정해지면 A/B 실험을 시작한다. 첫 실험은 첫 화면의 제목 문구처럼 한 요소만 바꾸는 안을 권한다.
4. 실험 결과를 바탕으로 유지할 안을 정하고 다음 실험으로 넘어간다. 방문자가 적거나 불확실성이 크면 승자를 정하지 않는다.

웹 번역 제공자·비용과 앱 설치 파일의 공개 여부는 별도 결정이다. 설명용 번역 예시, 실제 API 번역, 앱 다운로드를 같은 완료 상태로 표현하지 않는다.

## 2. A/B 테스트와 측정

### 도구와 배정

- **추천 후보:** PostHog의 feature flags와 experiments. 변형 배정·노출·성과를 함께 관리하는 기능을 사용하고 통계 엔진을 직접 구현하지 않는 안이다. 실제 채택과 데이터 수집 방식은 구현 전에 정한다. [실험 생성 안내](https://posthog.com/docs/experiments/creating-an-experiment)
- 기준 A와 변경 B를 비교하고, 실험에 참여하는 익명 브라우저에는 재방문해도 같은 안을 제공한다. 브라우저 식별자를 사람 수로 해석하지 않는다.
- 실험 키와 변형을 노출·후속 이벤트에 일관되게 연결한다. 새로고침마다 배정하지 않으며, 실행 도중 비율·대상·지표를 바꾸면 별도 실험으로 다룬다.
- 첫 화면이 실제 표시됐을 때 노출을 기록한다. 운영자·테스트·미리보기 방문과 서로 다른 안을 본 방문은 분석에서 구분한다.
- 동의·저장소 제한 등으로 안정적인 계측이 불가능한 방문에는 A를 제공하고 실험 표본에서 제외하는 안을 기본으로 검토한다. 장애 시에도 A와 기본 사용 흐름은 동작한다.
- 초기 렌더링과 수화 과정에서 A/B가 바뀌거나, 공유 캐시 때문에 다른 방문자의 안이 전달되지 않도록 검증한다. 배포 버전의 트래픽 분할과 제품 실험의 배정은 각각 운영한다.

### 지표

사용자는 **사용 흐름 체험 완료**와 **앱 설치·다운로드 행동**을 중점 목표로 선택했다. 첫 실험은 체험 완료율을 주지표, 설치·다운로드 행동을 핵심 보조지표로 두는 안을 권한다. 구체적인 실험을 시작할 때 최종 주지표와 판단 기준을 고정한다.

- 설치 파일 공개 전에는 설치 안내·준비 상태 확인 등 실제 제공하는 버튼의 클릭으로 설치 관심을 관측한다. 준비되지 않은 다운로드 버튼을 만들거나 이 클릭을 다운로드·설치 완료로 집계하지 않는다.
- 설치 파일 공개 후에는 다운로드 클릭률을 별도 지표로 측정한다. 실제 파일 전달 완료, 앱 설치와 최초 실행은 확인 가능한 별도 계측이 준비된 경우에만 기록한다.
- 체험 완료 후 설치 행동으로 이어지는 경로와, 체험 없이 바로 설치 안내·다운로드로 간 경로를 함께 관측한다. 설치 지표는 지원 OS·기기에 따라 분석 대상을 구분한다.

- `landing_exposed`: 실험 대상 영역이 실제 표시됨.
- `demo_started`: 방문자가 예시 또는 직접 입력 체험을 시작함.
- `demo_completed`: 방문자 동작 뒤 결과 표시가 완료됨. 준비된 예시와 실제 API 호출을 구분한다.
- `primary_cta_clicked`: 주요 버튼을 누름. 설치 안내와 실제 다운로드를 구분하며, 다운로드 클릭을 설치 완료로 해석하지 않는다.

체험 완료율은 실험에 노출된 익명 브라우저 중 체험을 완료한 비율로 계산하는 안이다. 설치·다운로드 전환도 같은 실험 노출에 연결해 분석한다. 체험 완료가 늘어도 설치·다운로드 전환에 의미 있는 감소가 관측되면 채택을 보류하고 원인을 확인한다. 표본이 부족하면 두 지표 모두 미확정으로 남긴다. 체험 오류율과 대기 시간도 함께 살핀다.

실험 시작 전에 가설·주지표·관찰 기간·의미 있는 최소 차이·필요 표본을 정하고, 작은 차이나 짧은 관측만으로 승자를 발표하지 않는다. 한국어·영어와 기기별 결과도 구분한다. 설치 파일 공개로 지표나 버튼 동작이 바뀌면 기존 실험과 결과를 섞지 않고 새 실험으로 평가한다.

Cloudflare Web Analytics는 현재 custom event를 지원하지 않아 이 전환 이벤트 분석을 단독으로 맡기지 않는다. [공식 FAQ](https://developers.cloudflare.com/web-analytics/faq/)

### 개인정보와 데이터 범위

- 번역 원문·결과, 직접 입력, 이메일·인증정보를 분석 이벤트에 넣지 않는다.
- 자동 DOM 수집과 세션 녹화는 기본으로 끄고 필요한 이벤트만 명시적으로 기록한다. SDK가 자동으로 붙이는 URL·쿼리·referrer도 전송 전에 제거·정규화한다.
- 이벤트 속성은 실험·변형·언어·예시/실제 모드·수치형 성능 등 필요한 값으로 제한한다. 개인 식별, 보존 기간과 동의 방식은 실제 설정과 함께 확정한다.
- 첫 측정 범위는 체험과 설치·다운로드 행동으로 두며, 출시 알림 신청과 이메일 수집 기능은 추가하지 않는다.

## 3. 배포와 운영

- **배포 대상:** 사용자 선택에 따라 Cloudflare Workers를 사용한다. Astro의 정적 소개와 향후 서버 경로를 같은 배포 기반에서 다룬다. 실제 계정 상태·도메인·비용은 배포 전에 확인한다. [Astro 배포 안내](https://developers.cloudflare.com/workers/framework-guides/web-apps/astro/)
- 패키지·lockfile·빌드·배포 설정은 `landing/` 안에 둔다. GitHub CI도 랜딩 관련 변경을 대상으로 실행하며 기존 Mac 앱 빌드와 분리한다.
- 흐름은 로컬 검증 → 브랜치 미리보기 → 검증된 커밋의 운영 배포로 구성한다. 운영 반영 시에는 한국어·영어 링크, HTTPS, 주요 버튼의 실제 목적지, 모바일·Safari, 검색 메타데이터와 오류 화면을 확인한 결과를 남긴다.
- 브랜치 미리보기는 Cloudflare Previews를 검토한다. 현재 공식 문서는 Wrangler 4.135.0 이상을 요구하므로 프로젝트에 지원 버전을 고정하고 실제 초기화 시 재확인한다. 운영 자원을 사용하는 Version URL과 브랜치 격리 미리보기를 혼동하지 않는다. [Previews](https://developers.cloudflare.com/workers/previews/), [작업 방식 비교](https://developers.cloudflare.com/workers/previews/compare-workflows/)
- 미리보기의 분석 프로젝트·설정·데이터를 운영과 분리한다. 운영 인증정보나 실제 번역 쿼터를 기본으로 사용하지 않고, 외부 PR 코드에 운영 배포 secret을 전달하지 않는다.
- Cloudflare 배포 토큰과 외부 번역 키는 서버·CI secret에 둔다. 앱의 Codex·Claude 구독 인증을 웹 브라우저나 공개 번역 서버에 복사하지 않는다.
- 초기 주소는 `workers.dev` 또는 사용자 지정 도메인 중 선택한다. 준비되지 않은 앱 설치 파일에 다운로드 링크를 만들지 않는다. 커밋 SHA와 배포 버전을 연결해 기록한다.
- 실험을 A로 되돌리는 중단 스위치와 웹 배포를 이전 정상 버전으로 되돌리는 절차를 준비한다. Workers 롤백이 저장소·DB 데이터를 되돌리지 않으므로, 향후 상태 저장을 추가하면 호환성과 복구를 별도로 검증한다. [롤백 안내](https://developers.cloudflare.com/workers/versions-and-deployments/rollbacks/)
- 번역 API를 열기 전에는 계정 과금 상태·요청 제한·예산 상한을 확인한다. 호출 오류나 계측 장애가 정적 소개까지 중단시키지 않게 한다.

## 4. 구현 전 선택과 확인 기준

선택할 내용: 실험별 최종 주지표·표본·기간, A/B 도구와 데이터 범위, 배포 계정·주소, 실제 번역 사용 여부·모델·비용, 운영 반영 방식. 이 문서 작성만으로 가입·결제·배포·실험 공개를 실행하지 않는다.

- 같은 방문의 배정 유지, 정확한 노출·완료 이벤트와 중복 제거, 미리보기·운영 데이터 분리를 확인한다.
- 이벤트·로그·번들에 원문·결과·인증정보가 없는지 확인하고 계측 차단 상황에서도 페이지가 동작하는지 확인한다.
- 대표 화면과 언어, 실제 버튼 목적지, HTTPS·검색 노출 설정, 배포 실패와 실험 중단·이전 버전 복구를 검증한다.
- 표본이 부족하면 결과를 미확정으로 남긴다. 배포 성공과 A/B 실험의 유효한 결과를 각각 기록한다.
