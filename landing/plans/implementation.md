## 1. 목표와 현재 확인한 상태

DeepK의 사용법과 기능을 소개하고, 방문자가 페이지 안에서 문단을 선택하거나 자신의 문장을 입력해 실제 번역을 체험하도록 만든다. 소개 영역은 Astro로 정적 생성하고 체험 영역만 React로 구현한다.

- 저장소에는 `README.md`, `assets/icon.svg`, 이 계획 문서가 있다. 아직 프레임워크나 제품 코드는 없다.
- pen.dev의 최종 Desktop 1440 / Tablet 768 / Mobile 390을 전체 랜딩의 기준으로 사용한다.
- 새로 만든 Web demo 01~04를 히어로 체험 영역의 기준으로 사용한다.
- 기존 pen.dev 시안은 유지한다. 체험 영역의 반응형 조정이 필요하면 별도 케이스로 추가한다.
- DeepK 앱의 로컬 소스에서 최소 macOS 15를 확인했다.
- 2026-10-12에도 GitHub Release 목록 조회 결과는 빈 배열이다. DeepK 앱 저장소는 PRIVATE다. 현재 저장소 링크를 일반 방문자용 설치·다운로드 경로로 취급하지 않는다.
- 현재 pen.dev의 번역 결과는 설명용 예시다. 실제 API 구현이나 라이브 번역 검증은 아직 하지 않았다.

## 2. 확정한 내용과 선택이 필요한 내용

### 확정한 내용

- Astro + TypeScript를 사용한다.
- Cloudflare를 배포 환경으로 사용한다. 서버 번역 경로가 있으므로 현재 공식 Astro 어댑터의 Cloudflare Workers 구성을 사용한다.
- 첫 출시부터 한국어·영어 사이트를 함께 제공한다.
- 번역 제공자와 비용 제한은 추천안을 계획에 포함한다. 처음 접하는 기술을 써보려는 사용자 의도에 맞춰 Astro, Workers, Workers AI, 필요한 최소한의 Durable Objects를 학습 범위로 삼는다.
- 상태가 필요한 번역 체험을 React 컴포넌트 하나의 경계 안에 둔다.
- 준비된 예시 문서와 직접 입력을 모두 지원한다.
- 문서를 읽던 위치에서 작은 결과 창을 열고, 복사하거나 닫고 원문을 이어 읽게 한다.
- 초기 예시 종류는 채용 공고 / 기술 문서 / 메일이다.
- 웹 체험은 이 페이지 안의 텍스트만 다룬다. 다른 앱의 선택 영역과 시스템 전체 단축키는 Mac 앱의 기능이다.
- 이번 작업은 구현 계획 작성이다. 제품 코드 작성, API 호출, 원격 게시와 배포는 아직 실행하지 않는다.

### 추천한 내용과 남은 선택

1. **번역 제공자 추천:** Cloudflare Workers AI의 Gemma 4 26B를 첫 평가 대상으로 둔다. 같은 호스트의 Qwen3 30B를 비교하고, 외부 API 후보는 Gemini 3.1 Flash-Lite로 둔다. 한국어↔영어 품질과 응답 속도는 아직 라이브로 비교하지 않았다. 최종 운영 모델은 작은 비교 검증 후 정한다.
2. **비용 제한 추천:** Workers Free의 무료 할당 안에서 먼저 운영하는 안을 제안한다. 유료 확장이 필요하면 AI 사용료 월 US$5 상한을 제안하되, Workers Paid 기본요금과 기타 비용을 따로 계산한다. 이 금액은 추천값이며 유료 플랜 변경이나 결제 동의가 아니다.
3. **공개 앱 배포 경로:** 미정이다. 다운로드 버튼은 앱 설치 파일을 받을 주소를 뜻한다. 현재 앱 저장소가 비공개이고 릴리스가 없으므로, 공개 설치 파일이 준비되기 전에는 `Mac 앱 출시 준비 중 / Mac app coming soon`을 표시하는 안을 추천한다. 사이트 공개 과정에서 앱 저장소를 공개로 바꾸거나 앱 릴리스를 만들지 않는다.

제공자 단가, 비용 계산 조건, 제한 구현과 평가 기준은 [번역 제공자·비용 계획](translation-provider.md)에 정리한다. 운영 모델·유료 확장·다운로드 주소는 추천안과 실제 결정 상태를 구분하며, 정적 페이지와 체험 UI는 공개 설치 파일과 독립적으로 구현할 수 있다.

### 구현 기본안 — 아직 확정하지 않은 작은 선택

- 스타일은 CSS 변수 + Astro scoped CSS + 체험 영역의 일반 CSS로 구성한다.
- 직접 입력 제한은 시안과 같은 **500자**를 출발점으로 삼는다. 클라이언트와 서버의 계산 기준을 같게 한다.
- 예시는 영어→한국어로 시작한다. 직접 입력에는 한국어→영어 / 영어→한국어 방향 선택을 제공한다. 자동 언어 감지는 후속 범위로 둔다.
- 입력할 때마다 유료 요청을 보내지 않고 명시적인 번역 버튼으로 실행한다.
- 첫 연결은 한 번의 요청에 JSON 결과를 반환하는 방식으로 만든다. 실제 대기 시간을 확인한 뒤 필요하면 스트리밍을 추가한다.
- 분석 도구, 계정, 결제, CMS, 번역 기록 저장은 초기 범위에 넣지 않는다.

## 4. 구현 구조

### 정적 페이지와 체험 영역

- 소개와 개인정보 안내는 빌드 시 HTML로 생성한다.
- 한국어는 `/`, 영어는 `/en/`을 기본안으로 삼고 개인정보 안내도 각 언어 경로를 제공한다. Astro i18n과 공통 레이아웃·타입이 있는 문구 사전을 사용한다.
- `TranslationDemo`만 React로 활성화한다. 히어로에 바로 보이는 체험이므로 초기 활성화를 기본안으로 삼는다.
- `/api/translate`는 서버에서 실행한다. `@astrojs/cloudflare` 어댑터를 사용하고 이 경로만 사전 생성에서 제외한다. 개발·미리보기 검증도 Workers 런타임인 workerd를 기준으로 한다.
- 첫 모델이 Workers AI라면 Worker의 AI binding으로 호출한다. 방문자에게 Cloudflare API 토큰을 전달하지 않으며, 별도 외부 제공자 키를 브라우저에 넣지 않는다.
- React 없이 처리할 수 있는 FAQ는 `<details>` / `<summary>`를 사용한다.
- 공용 상태 관리 라이브러리나 클라이언트 라우터는 초기 구조에 추가하지 않는다.

예상 파일 구조는 다음과 같다. 언어별 페이지는 같은 랜딩 컴포넌트를 재사용한다.

```text
src/
  layouts/SiteLayout.astro
  pages/index.astro
  pages/privacy.astro
  pages/en/index.astro
  pages/en/privacy.astro
  pages/api/translate.ts
  components/landing/                 # 소개 섹션별 Astro 컴포넌트
  components/demo/TranslationDemo.tsx
  components/demo/ExampleDocument.tsx
  components/demo/CustomInput.tsx
  components/demo/TranslationPopover.tsx
  components/demo/demo.css
  content/site.ts                      # 언어와 관계없는 링크·제품 정보
  i18n/ko.ts
  i18n/en.ts
  i18n/index.ts                        # 문구 키와 Locale 타입
  content/demo-examples.ts             # 예시 원문과 문서 정보
  lib/demo-state.ts                    # 요청 버전, 결과 무효화 등
  lib/translation-contract.ts          # 입력/응답 계약
  lib/server/translation.ts            # 선택된 제공자 호출
  lib/server/usage-limits.ts           # 비용·요청 제한
  worker/index.ts                     # Astro handler와 필요한 DO export
  worker/DemoBudget.ts                # SQLite 기반 전체 요청·예약 예산 카운터
  styles/tokens.css
public/
  images/
  fonts/
tests/
wrangler.jsonc
plans/implementation.md
plans/translation-provider.md
```

Wrangler에 AI binding과 필요한 Durable Object binding을 선언한다. `.dev.vars.example` 등 예제 파일에는 변수 이름과 자리 표시자만 적는다. 실제 secret과 외부 API 키가 필요하면 서버 환경에만 두며 Git, 브라우저 번들, 로그에 포함하지 않는다. DO export는 선택한 Astro 어댑터 버전의 custom entrypoint 방법으로 연결한다.

### 한국어·영어 사이트

- 소개, CTA, FAQ, 개인정보 안내, 체험의 버튼·오류·상태 문구를 모두 한국어와 영어로 제공한다.
- 언어 전환은 두 정적 페이지 사이의 링크로 구성하며 페이지의 대응하는 섹션을 유지한다.
- `<html lang>`, 각 언어의 canonical, `hreflang`과 OG 문구, 두 언어의 sitemap을 준비한다.
- 사이트 언어와 번역 방향은 독립적으로 둔다. 영어 사이트라고 자동으로 한국어→영어 요청을 보내지 않는다.
- 영어 문구는 한국어 시안의 의미와 사실 범위를 유지해 작성한다. 영문에서 과장된 성능·지원 범위를 추가하지 않는다.
- 기존 pen.dev 프레임은 유지한다. 영어 문구의 줄바꿈과 모바일 결과 배치를 별도 케이스나 구현 화면으로 검토한다.

### 체험의 상태와 행동

- **처음 방문:** 채용 공고 예시가 보인다. 문단 선택 전에는 번역 대상 안내를 보여준다.
- **선택:** 체험 문서 내부의 선택 텍스트를 저장하고 번역 버튼을 활성화한다. 페이지 밖이나 결과 창의 선택은 원문으로 취급하지 않는다.
- **요청 중:** 같은 요청을 중복 실행하지 않고 실제 진행 상태를 표시한다.
- **완료:** 선택한 원문과 방향에 대응하는 결과만 표시한다. 복사 성공/실패와 닫기 동작을 제공한다.
- **직접 입력:** 글자 수, 방향 선택, 입력 지우기, 번역 버튼을 제공한다. 빈 입력과 제한 초과를 UI와 서버 양쪽에서 처리한다.
- **실패:** 네트워크 오류, 시간 초과, 이용 한도 초과를 구분하고 재시도 가능한 경우만 안내한다.

입력·예시·언어 방향이 바뀌거나 창을 닫으면 진행 중 요청을 취소하고 요청 버전을 바꾼다. 취소가 늦게 반영돼도 오래된 응답이 새 화면에 표시되지 않아야 한다. 다른 문장의 이전 결과를 현재 번역으로 보여주지 않는다.

### 두 번 복사와 모바일

- Mac에서는 체험 문서의 동일한 선택에 대해 발생한 연속 `copy` 이벤트만 번역 트리거로 사용한다.
- 첫 복사와 기본 클립보드 동작을 유지한다. 시스템 클립보드를 읽거나 페이지 전체의 복사를 가로채지 않는다.
- 버튼을 눌러 브라우저 선택이 해제돼도 저장한 번역 대상이 유지되도록 처리한다.
- 모바일에서는 문단별 번역 버튼을 주 동작으로 제공한다. 드래그 선택과 단축키가 있어야만 체험 가능한 구조로 만들지 않는다.
- 데스크톱은 문서 옆의 작은 창, 좁은 화면은 문서를 가리지 않는 결과 영역으로 조정한다.
- 결과 창은 키보드로 열기·닫기·복사가 가능하고 상태 안내는 보조 기술에서도 전달돼야 한다.

### 서버 계약과 운영 제한

- 요청: 원문 문자열과 지원하는 번역 방향. 모델명과 시스템 지침은 클라이언트가 정하지 않는다.
- 응답: 번역 문자열과 요청에 대응하는 방향. 원문과 결과를 실행 가능한 HTML로 렌더링하지 않는다.
- 서버에서 빈 입력, 문자 수, 요청 크기, 지원 방향을 검증한다.
- 선택한 모델은 번역만 수행한다. 도구 호출이나 에이전트 실행을 붙이지 않는다.
- 요청 시간 제한과 출력 길이 상한을 둔다. 제공자 오류를 임의의 예시 결과로 바꾸지 않는다.
- 제한 추천값은 500자, 익명 브라우저당 1분 3회·하루 10회, 무료 단계 전체 하루 100회다. 로그인 없는 환경에서 브라우저 식별자를 사람 수 제한으로 보장하지 않는다.
- 전체 호출 수와 예약 예산은 SQLite 기반 Durable Object에서 원자적으로 관리한다. 프로세스 메모리, KV의 지연 전파, 위치별 Rate Limiting binding을 전체 비용의 정확한 카운터로 취급하지 않는다.
- 한 요청의 최대 청구 가능량을 확인해 호출 전에 예산을 예약한다. 실패·시간 초과로 실제 사용량이 불명확하면 이미 예약한 금액을 임의로 되돌리지 않는다. 가격·모델·출력 상한이 바뀌면 예약 단가도 다시 검증한다.
- 비용 제한을 확인할 수 없는 상태에서는 공개 번역 요청을 허용하지 않는 방향으로 설계한다. 실패하거나 한도를 초과하면 다른 유료 제공자로 자동 전환하지 않는다.
- 원문과 번역문은 애플리케이션의 영구 저장소와 요청 로그에 기록하지 않는다. 제공자 전송·보관 정책은 선택한 API의 실제 정책을 확인해 개인정보 안내에 반영한다.

## 5. 구현 단계와 완료 기준

### 1단계 — 프로젝트와 디자인 재료 준비

1. Cloudflare Workers·한국어/영어 확정을 적용하고, 모델·비용 추천안과 미정인 공개 다운로드 경로를 별도로 기록한다.
2. Astro + TypeScript + React 통합을 구성하고 패키지 매니저·lockfile을 하나로 통일한다. 기본안은 pnpm이다.
3. 작업 시점의 안정 버전과 호환되는 런타임을 확인해 고정한다.
4. pen.dev MCP로 아이콘 등 필요한 자산만 내보내고 저장소에 포함한다. 기존 `assets/icon.svg`를 DeepK 제품 로고로 가정하지 않는다.
5. CSS 변수, 폰트, 공통 레이아웃, 두 언어의 문구 사전과 메타 태그 골격을 만든다.

완료 기준: 개발 서버가 열리고 타입 검사와 빌드가 성공한다. 주요 자산이 외부 디자인 파일에 의존하지 않고 저장소에서 재현된다.

### 2단계 — 전체 랜딩과 반응형 구현

1. 최종 Desktop 기준으로 소개 섹션과 체험 영역의 외형을 만든다.
2. Tablet / Mobile의 간격·줄바꿈·배치로 조정한다.
3. 두 언어의 FAQ, 섹션 이동, CTA, 개인정보 안내와 언어 전환을 구현한다. 비공개 앱 저장소를 일반 방문자용 링크로 연결하지 않는다.
4. 앱 소스와 배포 상태에 맞게 문구를 검토한다. 지원 CPU, 수식 처리 범위, 설치 조건, 기록 저장에 대해 시안보다 넓은 보장을 추가하지 않는다.
5. 웹 API 체험 안내와 Mac 앱의 구독 이용 안내를 구분한다. 웹 체험이 앱과 같은 구독 연결로 작동한다고 표시하지 않는다.

완료 기준: 1440 / 768 / 390과 그 사이 너비에서 가로 넘침·본문 잘림 없이 읽을 수 있다. JavaScript 없이도 소개·FAQ·주요 링크가 이용 가능하다.

### 3단계 — 체험 UI와 요청 상태 구현

1. 01~04 상태를 실제 React 컴포넌트로 연결한다.
2. 예시 탭, 문단 선택, 번역 버튼, 직접 입력, 결과 복사·닫기를 구현한다.
3. 두 번 복사와 모바일 문단 버튼을 연결한다.
4. 요청 취소와 오래된 결과 무시, 실패·한도 상태를 구현한다.
5. 로컬 개발에서는 명시적으로 구분한 테스트 응답으로 상태를 검증한다. 이를 실제 번역 연결 완료로 표시하지 않는다.

완료 기준: 모든 경로를 클릭·키보드로 사용할 수 있고 원문 변경 후 이전 응답이 표시되지 않는다. UI 검증은 실제 제공자 호출 없이 재현 가능하다.

### 4단계 — 실제 번역 API 연결

1. Cloudflare 어댑터, AI binding, DO binding과 `/api/translate`를 구현한다.
2. 추천 모델을 작은 한국어↔영어 평가로 비교한 뒤 운영 모델 하나를 고정한다. Workers AI는 운영자 Cloudflare 계정의 binding을 사용하고 외부 API를 선택할 경우에만 별도 서버 secret을 준비한다.
3. 입력 검증, 시간·출력 상한, 호출 전 예약 예산과 요청 제한을 적용한다. 현재 계정이 Free인지 Paid인지 확인하기 전에는 무료 비용을 보장하지 않는다.
4. 실제 개인정보 처리 방식에 맞게 `/privacy`와 체험 안내를 마무리한다.
5. 합의한 비용 범위 안에서 소량의 실제 한국어↔영어 요청을 실행해 품질과 대기 시간을 기록한다.

완료 기준: 예시 원문과 임의로 입력한 새 문장을 실제 제공자가 번역한다. 키가 클라이언트에 없고 한도 초과·제공자 장애가 올바르게 처리된다. 실제 연결 검증과 테스트 응답 검증을 구분해 기록한다.

### 5단계 — 브라우저 검증과 출시 준비

1. 타입 검사, 핵심 로직 테스트, 프로덕션 빌드를 실행한다.
2. T3 협업 브라우저에서 실제 선택·클릭·복사·모바일 경로와 화면을 확인한다.
3. Mac Safari의 선택·두 번 복사·결과 복사는 별도로 확인한다. Chromium 검증으로 Safari 검증을 대신하지 않는다.
4. Cloudflare workerd 로컬 런타임과 요청된 미리보기 배포에서 AI·DO binding 및 서버 API를 확인한다. 정적 빌드 성공만으로 서버 경로 동작을 검증했다고 하지 않는다.
5. 폰트·이미지·체험 번들의 초기 로딩을 확인하고 불필요한 JavaScript를 줄인다. 개선 수치가 필요하면 같은 조건에서 측정한다.
6. 다운로드 목적지, 개인정보 문구, OG 이미지, canonical, sitemap, robots와 필요한 언어 메타데이터를 점검한다.

완료 기준: 실제 사용자 흐름과 서버 경로 검증 기록이 있고 미검증 사항이 명시된다. 실제 배포는 배포 요청에 맞춰 수행하며, 준비되지 않은 앱 릴리스를 다운로드 완료 상태로 표시하지 않는다.

## 6. 필요한 검증

핵심 동작을 검증하는 테스트만 만든다. 정적 섹션의 구조를 그대로 복제하는 테스트는 만들지 않는다.

- 선택 없음 / 빈 입력 / 문자 수 경계 / 지원하지 않는 방향을 거부하는 서버 계약.
- 예시 또는 입력을 바꾸는 동안 도착한 이전 응답이 무시되는 경우.
- 진행 중 창 닫기, 재시도, 중복 번역 트리거가 올바르게 처리되는 경우.
- 동일한 선택의 두 번 복사만 실행되고 한 번 복사와 페이지 밖 복사는 기본 동작을 유지하는 경우.
- 시간 초과, 제공자 오류, 요청·비용 한도와 제한 확인 실패 시 실제 호출이 실행되지 않는 경우.
- 여러 동시 요청이 잔여 호출 수나 예약 예산을 초과하지 않는 경우와 날짜·월 경계의 카운터 처리.
- 한/영 문구 키가 대응하고, 언어 전환·메타 태그·500자 경계 입력과 오류 안내가 두 언어에서 동작하는 경우.
- 모바일 문단 버튼, 직접 입력, 결과 표시, 복사 실패 시 대안 안내.
- 브라우저 화면 비교는 pen.dev 기준과 구현을 같은 너비에서 확인한다.

명령 기본안: `pnpm check`, `pnpm test`, `pnpm build`. 각 스크립트의 실제 검사 범위는 프로젝트 구성 때 정리한다.

## 7. 완료 판단과 후속 범위

첫 구현의 완료는 랜딩의 외형만 완성된 상태가 아니다. 예시 선택·직접 입력으로 실제 번역하고, 결과를 읽고 복사하며, 좁은 화면에서도 사용할 수 있어야 한다. 배포는 별도의 준비·검증 상태로 기록한다.

초기 범위 밖: 계정·결제·대시보드, 브라우저의 다른 탭이나 앱 읽기, 웹에서 시스템 전체 단축키 감시, 번역 기록·공유 링크, 다양한 제공자의 자동 전환. 스트리밍과 자동 언어 감지는 초기 동작과 대기 시간을 확인한 뒤 판단한다.
